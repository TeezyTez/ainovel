# 自适应体验重构：实现与验收记录

日期：2026-10-10。核心依据为本轮桌面附件《方糖｜自适应富交互与叙事体验：项目重构任务书》。这是实际实现记录，不是下一轮产品规划。

## 实际架构

保留原生 JavaScript 页面、Node 本机服务、既有回合/事件/世界/分支结构和本机 Codex 授权。没有迁换框架，也没有添加支付、社区或独立微服务。

本次新增共享交互语义层，将“我现在怎么样”“查看人物资料”“比较这两个”解析为公开记录查询。文字列表、表格、选择、排序和来源回看使用同一份当前分支投影，不调用叙事模型，不写世界事件。选择最多四个稳定对象 ID，绑定世界、分支和版本；发送时后端重新解析对象，不信任客户端传来的对象值。刷新不重造对象；临时选择不跨刷新延续，草稿仍保存。

生成链路为：自由输入/当前动作 → 服务端权威分支 → 两个候选场景的构思与有依据的选择 → 正文与结构提案 → 原文证据、状态回放、数量/路线/约定、叙事线程校验 → 原子持久化 → 浏览器安装公开回合。普通文本若与当前唯一动作标签或输入完全匹配，复用按钮交易校验；其他表达仍是自由尝试，不强制只能选菜单。

`BranchLedger` 新增持久登记、创建、生成、编辑和恢复。已完成请求重试返回同一个回合；过期版本、错误分支、冲突正文拒绝写入。旧作者存档的首次登记是兼容导入边界。新的一句话开局在服务端保存幕后世界，仅公开玩家已知投影；scoped read/generate 不透露兄弟分支才发现的人物。完整多分支作者档案中的人物并集，与当前玩家投影有明确区别。

一句话创建直接生成并进入正文。阅读页将相关交互插在剧情之后，低价值/无动作资料可折叠；支持纯阅读密度。自由输入、有限时间推进、人物资料、历史、分支、命名存档、润色和纠错沿用并接入新的持久状态链。未知呈现类型退回文字；无效业务状态不会为了展示而放行。

## 本轮发现并修复的真实问题

- 浏览器 `fetch` 被作为 BranchClient 方法调用，导致 Illegal invocation：绑定正确全局 receiver，并有 red→green 回归。
- 已登记原分支的编辑响应覆盖未提交本地 fork：改为合并权威分支并保留本地新分支/草稿/个人存档。
- 恢复完成后 busy 控件未解除、过期对象选择导致助手锁住、恢复期间切换分支、生成后清除用户新选择：分别修复生命周期与条件清理。
- 私有故事未来角色发现污染开篇及其他分支投影：固定开场依据、逐回合回放，read/generate 按请求分支投影。
- 模型把交互对象名称/引文写成正文中不存在的组合：保留严格校验，增加一次有界的 game 引文修复。正文、事件、数量、状态、动作及数组数量冻结，不能删实体来绕过规则；修复后继续全部校验，仍共用原截止时间。失败诊断仅开发验证使用，不随 API 返回。

### 本机 Codex 真实模型

完整脚本：`scripts/verify-adaptive.mjs`。结果及公开存档在 `test-results/adaptive-live`，与用户真实存档隔离。

- 修仙：世界创建 76.7 秒，自由行动 80.7 秒，提交一回合；许师傅拒绝“整理铺子换指导”，继续处理自己的修符生意。相同 requestId 重试和读取恢复均为同一 turnId；公开档案通过回放验证。
- 日常情感：创建 51.2 秒，自由行动 69.0 秒；人物未接受不合适的周五安排，提出其他方式，未替玩家接受。有限时间推进 63.1 秒，实际经过半个多小时，遇到来访需回应时停下，未越过上限或作新承诺。两回合公开档案有效。
- 都市悬疑：首次与诊断复测的行动均被证据校验拒绝；原因是 game 引文未包含完整实体名称或不是本轮原文。失败没有形成回合。修复后的独立结果记录于 `test-results/adaptive-live-mystery`，最终复测通过：开局70.234秒，行动97.033秒（规划31.964秒、写作51.218秒、一次证据修复13.829秒）。1个真实回合、幂等回执、同回合恢复、公开档案回放全部通过。两次诊断失败保存在该目录的 first-failure/second-failure.json。

不是三次一遍全过，不把失败隐去。即使幂等回执避免重复世界结算，未提交的模型调用仍可能消耗账号额度。

## 当前限制

1. 本机模型生成仍需约一分钟，复杂输出或证据修复会更久；当前没有 token 流式正文。失败明确保留旧世界和输入。
2. 开场正文里的物件、时间未必立即全部结构化：人物/地点可从公开开篇投影，其余资料随有证据的回合登记；空记录不代表不存在。尚未引入通用自然语言事实抽取器。
3. 历法、年龄、跨年约定及自由正文的全部语义不能仅靠原文引用证明；目前有上下文约束与结构校验，没有声称绝对防止模型矛盾/剧透。
4. 新故事完整恢复依赖项目 `.data` 账本和原浏览器 owner 标识；JSON 导出仅是浏览器档案，不能独立迁移私有幕后世界。界面已说明。没有云同步、多设备身份或跨进程共享锁。
5. 老作者档案保留原本幕后内容；新受保护路径的隔离不能追溯声称旧档同样保密。已有世界高级编辑的任意结构修改不等同于安全迁移全部私有历史。
6. 这次交付的判断是核心技术闭环及短局体验，不是“所有长篇剧情已经经读者验证”。
