## 首次发现与最终复核

### P1：撤销润色会丢失新版笔记的唯一来源见证

位置：`src/experience-controls.js` 的 `undo-polish` 分支（审查时第 96 行）。

触发：润色最后一轮，在润色后的句子上保存笔记/书签/草稿引用，再撤销润色。代码取出最后一个 revision 后将它从数组移除，直接恢复旧正文，但不保存被撤销的新正文。新引用既不匹配当前 prose，也不再出现在 revisions 中。`LocalRepository.save` 会保存该数据；下次 `validateArchive` 会拒绝加载整个档。

已用只读 Node 脚本按该分支的同样操作重现：`UNDO_ARCHIVE_FAILURE: 个人资料无效：来源原文已修订或不存在，请重新选择引用。`

建议保留所有正文见证，并用独立的版本选择/撤销逻辑切换；至少在替换前保存离开的正文，并验证完整档仍能往返加载。不能删除用户为新版保存的私人资料来掩盖问题。

复核：已修复。控制器调用 `undoPolish`；该函数保留离开正文的见证并移动 `polishUndoIndex`，不删历史。`tests/experience.test.mjs` 的来源笔记与 JSON 往返回归通过，该文件 15 项测试通过。

### P2：JSON 创作资料导入静默截断

位置：`src/world-import.js` 第 10–19 行。

JSON 世界和角色卡路径对 opening、rules、characters 及各文本字段直接 `slice`，却只给“请核对”的通用提示；文本导入路径才有明确截断说明。采用后，被截掉的资料不进入草案。原文件仍在用户设备，但 UI 没有告诉用户哪些内容未导入。

已重现：输入 12001 字 opening 和 41 条 rules，得到 12000 字与 40 条，warnings 仅含通用核对说明。建议拒绝超限，或逐字段报告原长度、实际采用范围与被忽略字段，不能静默弱化用户设定。

复核：原字段和条数现已前置拒绝超限；仍发现角色卡 first_mes 占位符展开后的长度未重新校验。例如 name 为 100 字、first_mes 为 121 次 `{{char}}`，原输入合规，展开后 12100 字再被截为 12000 字。已告知主任务补查展开后的 opening；截至本段写入仍待复核。
