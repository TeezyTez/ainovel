2026-10-13。用户指出初版简陋、体验不舒服，并要求搜索优秀设计后全面优化。保留此前确认的原则：辅助内容由系统按需出现，玩家不需要开启功能或选择展示格式。

## 初版的问题

1. 阅读页由多轮样式覆盖组成，标题、行文、工具和输入区缺少连贯层级。
2. 表格只有两行也显示搜索；图形下方完整复制节点卡片，辅助说明比有效内容更抢眼。
3. SVG 强制最小宽度，手机必须横向滑动；直接缩小又让文字难以辨认。
4. 排序箭头不随状态变化；写入草稿的反馈不够明确；图示不能放大检查。
5. 自动生成持有故事锁，发送行动时要求用户等待，破坏了自动辅助的初衷。

## 实现方向

- 阅读：统一色彩和排版，增加简洁场景定位与阅读设置入口，重做章节、回合分隔和输入区域。
- 组件：表格、卡片、图表、关系图、时间线、插画分别获得适合内容的布局，减少重复说明。
- 手机：独立的可读图表和小型关系图布局，宽表格只在内部滚动；保留完整文本与原尺寸图示检查。
- 操作：排序状态、草稿反馈、缩放、适应窗口、Escape 关闭和焦点返回都应可验证。
- 响应：自动整理使用状态快照，在后台调用模型；写入前重新验证。继续行动会取消可选整理，旧响应不能覆盖新剧情、草稿或当前分支。
- 视觉验收：使用隔离的固定数据覆盖组件；它不代表模型每次会同时生成全部组件。实际策略仍只在必要时选择少量有用内容。

## 验证记录

- 完整 `npm test`：440 项通过，0 失败，0 跳过。日志：`test-results/ui-redesign-tests.log`。最后统一地图弹层色彩后，20 项阅读测试及预览脚本自检再次通过。
- 桌面与390px窄屏：检查浅色/深色、横向溢出、短表格、排序箭头、图示缩放与适应窗口、Escape关闭和焦点返回。排序后追加草稿保留原有文字、展开状态与排序，且不产生故事回合。
- 地图：用独立验收故事检查9个长地名、测距和不同通行状态；手机地图在内部滚动，文字保持14px。无方位关系的3地点场景使用紧凑记录，无空白大地图或无效缩放按钮。
- 稳定性：同一交互定义的排序、搜索和展开状态按故事、分支、定义摘要隔离；节点显隐及重复项数量变化不会串用另一张表的状态。历史页头的位置和时间对应实际所读片段。
- 真实模型：`node scripts/verify-rich-interactions.mjs --live --case=auto,quiet` 两项通过，执行期间实现源码未变。比较路线场景自动生成table，安静阅读场景明确不生成界面，均未推进剧情或修改物资。证据：`test-results/rich-live-2026-10-13T02-41-58.652Z/manifest.json`。
- 浏览器截图：`test-results/redesign-reading-desktop.png`、`redesign-artifacts-desktop.png`、`redesign-mobile-dark.png`、`redesign-map-mobile.png` 为隔离固定数据验收；`redesign-current-story.png` 为用户当前故事的实际页面。当前故事重新载入后仍为2回合、空草稿，未执行额外行动。

固定数据页面用于组件与边界验收，不能据此推断模型会在每次回复中生成全部组件；真实模型验收独立记录。对地图弹层的最后配色统一在截图保存后完成，截图主要作为布局证据。
