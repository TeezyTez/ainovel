# 智能交互优化与前沿产品差距评估

评估日期：2026-10-15。对象为当前人生复本工作区；对照各公司的官方公开能力，不把发布演示当作相同任务的实测成绩。

**结论：项目已具备按剧情选择呈现形式、生成可运行界面、审核与恢复的基础，但仍处于需要持续验收的本地原型阶段。最值得缩小的差距是连续修改的稳定性、生成等待、可管理的长期记忆，以及针对真实任务的质量评估。** 不宜用“达到某公司多少百分比”概括这些不同能力，也没有证据要求先整体迁移 React 或更换模型。

## 同日后续：优先减少等待

按用户要求，展示与创造性输出不再经过额外一轮模型内容审查。当前策略为：

- 只读组件、沙箱交互图与 `attempt` 草稿：生成后直接进行本地结构、表达式、证据引用和脚本语法检查，成功即返回；没有 `judge` 调用。只有格式或代码实际无效才进行一次修复。
- 新的正式 `rule`：仍验证成本、公式和授权。仅修改界面时，字段、步骤和正式动作完全一致，而且同场景的事实来源指纹未变，可复用服务端已有验证。审查输入移除整套视图、旧界面和失败候选，避免重复传入脚本。
- 已结算行动的描写：`narrate` 生成一次即可保存正文，不再调用 `narrationReview`。它只能修改正文、摘要和叙事状态，不能重新扣除资源或改变正式回执。
- `prepare` 不再强制 medium 推理；沿用显式配置，缺省 low，仍保留足够的代码输出预算。模型型号没有更换。

来源指纹同时用于规则缓存、沿用、正式执行与自由输入目录。同版本正文修订后，旧规则不能继续按原事实执行。旧存档中没有来源指纹的正式规则会在下一次准备时重新验证一次；纯展示不受影响。

用同一 `gpt-6-sol`、相同隔离场景复跑：

| 场景 | 修改前 | 修改后 | 模型调用数：前 → 后 |
| --- | ---: | ---: | ---: |
| 三路线比较 | 27.6秒 | 14.2秒 | 2 → 1 |
| 分配试算 | 44.5秒 | 17.4秒 | 2 → 1 |
| 保留局部数量后修改试算 | 81.9秒 | 25.4秒 | 4 → 1 |
| 安静阅读，决定不展示界面 | 10.7秒 | 8.4秒 | 1 → 1 |

四次任务均首次生成通过，审查调用为0，故事状态未变，源码指纹在测试期间一致。这是修改前后各一次的观测，生成内容与网络耗时有波动，不能当作稳定百分位或将全部差额归因于删除审查。旧计时还包含少量验收文件读写；新计时在 prepare 返回时停止。可以确定消除的是串行审查及其导致的重新生成。

最终全量测试 **674/674通过**。已对这次真实生成的修改成品进行1000px和390px浏览器检查：初值4，改为6并加入阿青的假设份数后剩余6，刷新保留输入；无脚本错误或横向溢出，已查看手机宽度截图。该检查验证当前成品，模型修改请求中的 `quantity=4` 仍为受控注入，不是初版界面实际操作后回传。

证据：[本轮测试日志](../test-results/speed-full-tests.log)、[真实耗时与调用清单](../test-results/interactive-live-2026-10-15T04-19-59.301Z/manifest.json)、[成品浏览器结果](../test-results/speed-generated-browser/result.json)、[浏览器验收脚本](../test-results/verify-speed-generated.mjs)、[手机截图](../test-results/speed-generated-browser/generated-390.png)。测速脚本新增 `--dry-run`，可离线验证阶段计数；`--live` 使用现有模型额度。上述证据位于本机忽略目录。

默认剧情主链路仍是“生成正文 → 提取结构化记忆和状态”，第二次调用承担存档工作，并非额外的独立审查。本次没有将这两项合并。展示文字、局部公式和后续描写的质量交给生成模型，产品不再声称它们经过独立事实复核。运行中的本地服务需要重启加载修改。

## 第一轮完成的改进

| 原来的问题 | 现在的行为 | 验证 |
| --- | --- | --- |
| 有现成界面时，“只显示北路和南路”“按时间排序”“给这个表格加一列来源”等仍走剧情入口 | 支持这些明确的展示修改；对白、后续剧情动作、假设问题及人物的否定表达继续走原入口 | 新增正反例，路线名称不再硬编码 |
| 新界面使用新 digest 后默认从空状态启动 | 模型可将仍适用的局部参数显式映射到 `initialState`；同一界面已有的本地保存优先 | 初值、零值、null、存储不可用及恢复用例；实际生成界面浏览器复验 |
| 客户端可保存的较长局部状态被服务端静默丢弃 | 初值、运行时保存、服务端回传共用受限 JSON 校验 | 超长、非有限数字、缺失数组项、原型字段及合法状态往返测试 |
| 修改备注等无关字段时，整个图被销毁重载 | 视图内容未改变时保留原 iframe 和运行状态；显示内容改变时正常刷新 | 浏览器确认 iframe token 不变，数量保留 |
| 一个 interactive 节点放入 repeat 后被展开成多个共享状态的 iframe | 新生成定义拒绝此结构，提示在单个交互图内部管理多项 | 直接及嵌套 repeat 的失败后通过回归 |

初值仍只是未提交的展示数据，不能成为剧情事实、交易授权或资源结算依据。参数在新界面中的含义映射由生成模型提出，不能保证任意复杂界面都能无损转换；当前不再为纯展示映射单独调用模型审核。新增 repeat 限制保护新生成和修改结果；旧版已审核界面的沿用路径没有做批量迁移。

## 与前沿产品的具体差距

| 能力 | 官方公开参照 | 项目现状与判断 |
| --- | --- | --- |
| 按任务生成交互 | OpenAI Visualizations 支持图表、计算器、仿真与交互解释，允许调整控件、数据和标签后继续修改；结果可能是替换版本。[官方文档](https://learn.chatgpt.com/docs/visualizations) | 已有受控组件与隔离 HTML/CSS/JS，能力类型开始重合。本轮补齐一些续改入口和参数恢复；自然语言入口仍依赖保守规则，尚无广泛真实措辞的成功率。 |
| 连续的对话内呈现 | Claude 于 2026-03-12 发布自动按需生成的对话内 visuals，可随追问修改；它和长期使用的 Artifacts 有不同定位。[发布说明](https://claude.com/resources/articles/claude-builds-visuals) | 本项目已有自动判断、保留、替换、关闭和失败恢复。尚缺修改历史、用户所指对象的稳定定位、局部编辑，以及更充分的跨任务验收。不能将此次几个正例当作日常触发准确率。 |
| 应用式界面生成 | Claude Artifacts 可经对话创建并分享应用，官方文章记载后续加入 MCP 和持久存储；Gemini Canvas 支持 HTML/React 预览与反复修改，Dynamic view 为实验性的按提示生成交互界面。[Artifacts](https://claude.com/resources/articles/build-artifacts)、[Canvas](https://blog.google/products-and-platforms/products/gemini/gemini-collaboration-features/)、[Dynamic view](https://blog.google/products-and-platforms/products/gemini/gemini-3-gemini-app/) | 本项目只有一个隔离交互图，没有外部依赖、服务调用或共享应用平台，表达与集成范围较窄。互动小说近期更需要正确的试算和剧情连续性，不必照搬这些平台的全部范围。 |
| 可管理的角色记忆 | Character.AI 于 2026-05-21 公开 Story Memory、消息固定、可编辑和禁用的自动 Facts、人物分组与记忆占用显示。[官方说明](https://blog.character.ai/memory/) | 项目已有带来源事件、分支记忆与资料查询，但召回仍以有限近期原文和相关摘录为主。需要让玩家清楚检查人物记住了什么，并验证几十轮后的承诺、关系变化和秘密边界。官方也未给出足以横向比较的长期记忆错误率。 |
| 实时角色与记忆基础设施 | Inworld 当前文档明确 Character Studio 已退役，能力迁移到 Runtime；Realtime 的跨会话记忆持久化由开发者数据库完成。[迁移说明](https://docs.inworld.ai/character-studio-deprecation)、[记忆文档](https://docs.inworld.ai/realtime/usage/long-term-memory) | 不能把旧 Studio 的宣传当成现成万能角色系统。项目可以沿用自己的分支账本增加来源可查的事实召回；实时语音不是本次文字小说优化的第一优先级。 |
| 可靠性评估 | Anthropic 的评估实践强调最终状态、完整轨迹、混合评分和重复运行，区分偶尔成功与稳定成功。[官方工程文章](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) | 已有大量确定性测试和隔离真实模型场景，但缺少固定语料的多次运行、视觉任务评分、长篇人物一致性与用户体验盲评。这是判断是否真正接近前沿体验的主要证据缺口。 |

正式回执、幂等结算、公开视角投影和分支隔离是本项目适合互动小说的基础；竞品发布页不能证明它们在这些维度更好或更差。相反，代码测试通过也不能证明小说感染力或交互设计已经达到竞品水平。

## 第一轮验证结果（提速修改前）

- **自动测试：662/662 通过**，无跳过、取消或失败；相关源码及验收脚本语法检查通过，diff 无空白错误。新增缺陷用例先复现失败再修复。
- **受控浏览器：1000px 与 390px 通过**。调整数量到4份，修改备注不重挂交互图；请求修改后恢复4份、剩余8份；按钮追加草稿，故事回合与状态版本保持0；无脚本异常或页面横向溢出。
- **真实模型：Codex 本机授权 / gpt-6-sol / 协议7**。隔离账本完成三类场景、四次准备任务；每次准备前后均核对故事快照不变。下表记录单次观测，不是性能分布或与竞品的延迟测试。

| 真实任务 | 最终结果 | 本次端到端耗时 | 首次候选 |
| --- | --- | --- | --- |
| 无明确界面指令的三路线比较 | 表格及说明 | 27.6秒 | 通过 |
| 可修改的干粮分配试算 | 可运行交互图 | 44.5秒 | 通过 |
| 传入局部 quantity=4 后修改分配方式 | 新交互图，initialState 保留4 | 81.9秒 | 首次被审核拒绝，修复一次后通过 |
| 普通安静阅读 | none，保持纯文字 | 10.7秒 | 通过 |

连续修改首个候选将客户端数值描述为此前试算总量，审核要求改成可修改的草稿初值，修复后通过。这暴露了等待与审核尺度的问题；后续已按用户要求移除纯展示的这层模型审查，正式规则的结算校验继续保留。

该真实脚本注入了受控 `quantity=4` 状态，验证状态进入模型并生成初值，不等于玩家从第一个成品连续操作的完整端到端实测。随后用**当前最终运行时**打开这份真实生成的修改结果：在1000px与390px下实际显示4，改为6后计算同步，刷新仍恢复6；无运行错误，并已查看截图。完整玩家提交流程的草稿和不推进剧情约束由上述受控浏览器及服务端测试覆盖。

首次受限账户运行因模型进程权限失败；正常用户权限下复验成功。没有改动模型配置、玩家存档或线上服务。

## 下一轮优先级

1. **固定交互任务集并重复评估。** 建议20种场景各重复5次，同时包含该出现与不该出现界面的案例；分开记录首次通过、修复成功、取消、可完成任务、错误动作以及端到端 p50/p95。这个规模是下一轮计划，不是本轮已取得的数据。
2. **减少有效结果前的等待。** 依据轨迹统计慢在生成、审核还是修复；先处理审核误拒与不必要的重生成，评估分阶段呈现。当前模型调用与结果提交仍非流式，不应展示虚假的逐字生成。
3. **验证角色的长期一致性。** 增加30至50轮测试：承诺延后兑现、人物不知道未告知的信息、纠错后的引用、换分支不串记忆。资料页已有基础，可在此增加可检查和修订的记忆条目。
4. **以完成任务衡量视觉质量。** 检查窄屏遮挡、标签理解、键盘操作、算式与状态对应关系，积累渲染反馈；“有图、有按钮”本身不算任务成功。

这些工作完成后，才能用相同故事、相同输入与明确评分标准进一步比较竞品体验，而不是凭页面是否更华丽判断智能程度。
