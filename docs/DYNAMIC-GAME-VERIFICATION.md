## 真实模型与浏览器

使用现有 Codex 本机授权、gpt-6-astra、规划与正文两阶段。上下文预算 48000，输出预算 4000。不是 mock 生成。

1. 修船铺：初始真实生成自然出现制作操作；浏览器点击制作后麻绳 3→1、帆布 2→1、补帆包 0→1。第一次暴露“小动作使整局结束”问题，修复后在另一分支重新真实调用验证，`ended=false`，继续阅读与新动作均可用。
2. 停电研究站：初始真实生成已知路线地图，封锁路线不可直接移动，手电未知电量保持未知。移动的规划有一次因附加引用不准确而失败，原状态保留。修复引用筛选后复用该次真实规划并重新调用正文模型，成功抵达配电间，转为设备调查操作。该次是恢复规划后成功，不是声称所有生成一次成功。
3. 输入“查看背包”：出现只读已有物品；消息回合数仍为 2，不调用模型推进时间。可关闭。
4. 刷新恢复相同分支、数量与操作；旧回合组件折叠为只读记录。实际导出存档再次回放校验通过。
5. 桌面与 390×844 移动视口检查，无横向溢出。修复外层组件与内部列表 CSS 类名冲突；最终桌面实际内边距为 22px。

实际首轮生成耗时约 58–66 秒。本次没有把模型延迟优化列为已完成成果。

## 实现边界

组件种类是受约束的可信目录；世界的数值名称、地点、物品、配方和行动按剧情产生，不预设通用血量或等级。确定效果由代码运算，未知后果作为尝试进入叙事。模型定义规则，正文引用和结构校验不能证明所有生成规则的语义正确。

实体暂保留最多 200 个，尚无长期退役策略。支持声明式资源变化、状态变化和已知路线移动，不运行模型任意代码，也没有额外假定通用战斗掷骰。场景按钮不会直接结束整局。不同模型供应商的输出稳定性未在本轮全部验证。
