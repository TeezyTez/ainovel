# 核心游戏交互重构：实现与验收

依据：2026-10-12 核心游戏交互附件及用户“直接重构、界面尽可能简单”的补充。保留原项目、原生 JS/CSS、现有本机 Codex 授权、服务端分支账本和用户故事。

## 实际实现

- 阅读正文与一个自由输入框仍是主界面。顶部为时间、地图、身上、手记；输入框旁提供继续故事与周围。参与方式放在故事选项，复杂操作按需展开。
- 身上区分随身物品、在别处的物品、位置未明的记录。对象分别呈现所有者、保管者、位置。现场动作必须有当前公开依据；人物指向加入可移除引用，保留草稿，不自动发送。
- 时间首页只查询，展开后才安排短等、等时刻/事件或略过一段。条件等待必须明确上限，旧版本或生成中的操作不执行。接手会先取消等待中的请求；已提交结果仍可恢复。
- 手记区分接受的约定、主动关注、自己的打算、私人笔记及经历原文。私人打算不等于世界承诺。
- 地图有场所、地区、世界层级；无室内分区时禁用场所层。地点详情与路线比较在地图内完成，选中路线后另点出发。地图、选择、缩放、历史查询不改变世界时间；视角按故事/分支保存。
- 地理优先使用已证实的包含关系、方向和真实通路；只有连接时明确标注连接示意。缺失的方向、距离和费用不编造。传闻地区作为尚未定位消息，不放成可导航坐标。
- 路线持久记录途经地点、耗时范围、等待是否计入、费用及原文依据。出发引用当前版本，费用只在有效行进结果提交时扣除。中断记录实际停点和实际消耗，不能展示为抵达终点。
- 时刻、身体/通行条件变化使旧估计待核对；不足余额、未随身携带的支付物、额外费用、错误停点和跨日错误会阻止提交。NPC 可以撤回请求，抵达本身不接受或履行约定。
- 修复公开投影将传闻升级为确认、初始人物资料被开场姓名观察覆盖、人物状态更新让旧位置看似实时等问题。新旅程引用使用独立标识，保留旧名为 journeys 的场景动作与存档。

使用独立 localhost 导入副本，不对用户原故事执行行动。桌面与 390×844 手机尺寸检查：四入口、路线比较、物品/时间查看、人物指向、草稿保留、查询不推进均已实际点击核对。曾发现本次开发中新路线条件签名变化导致验收档重放失败，已改为兼容原记录的条件版本检查；刷新恢复及草稿持久化重新通过。

末轮实际交互发现并修复两项问题：抵达后保留的路线面板仍让用户打听前往当前地点的路线；人物明确“在场”但位置为“码头登船处附近”时未出现在周围。前者抵达后回到地点详情；后者要求当前版本的确认记录、明确在场状态及当前地点关联，不能仅凭模糊名称或过期记录认定在场。两项回归先失败、修复后通过；浏览器刷新后实际显示“你在这里”和在场人物唐棠。人物证据为 `test-results/core-play-browser-presence.txt`。

## 保留的限制

- 桌面资料目前是按需面板，未做常驻固定栏，以保持主界面简单。
- 路线属于正文有据的数据；旧故事没有地理/报价时只能展示已知连接或先起草打听路线，不会自动补造完整地图。新时刻可能需要重新核对报价。
- 真实模型仍有约一分钟以上的生成等待，且可能因证据/状态不一致被拒绝提交。通过单次出行不能证明长期文学质量或全部经营、委托情景稳定。
- 浏览器真实出行中，正文仍替玩家补写了一句“你告诉她，表已经修好，留在铺里”；结构化状态没有自动接约、交表或收费，但自由行动下的叙述代言边界尚未得到可靠保证。本次不将这点或长期剧情质量声称为已解决。
- 数值旅途消耗须在已授权报价内；未报价的身体变化可以定性呈现，不能静默改写资源余额。
- 全部 A01–A20 未逐项进行真实模型与实机验证。触摸缩放采用浏览器指针实现，当前核验包含手机尺寸与按钮操作，未在实体手机上测试。
- 本次未提交或推送 Git；工作区保留既有未提交修改。
