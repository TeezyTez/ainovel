# 生成架构重构：从续写到可兑现的剧情

2026-10-10。用户要求直接分析方案并改造当前原型；本文记录实施取舍，不把设计当成人类阅读效果的证据。

## 阅读动力与工程假设

1. 在意具体的人与目标：角色需要独立动机和行动，不靠作者宣告人物重要。
2. 可理解的期待：读者知道正在等什么、为何有意义；未知应有边界，不是不断增加名词。
3. 可见进展和阶段兑现：本轮交付一个发现、结果、关系变化或成果，之后自然产生新的期待。
4. 行动留下后果：有效方法被承认，过去选择改变后续条件，胜利不会为了续写立即被取消。
5. 可信意外：来自既有规则、不同人物目标或旧证据的新解释，避免临时换谜底。
6. 张弛与收束：安静场景让所得进入生活。可继续阅读也能获得完整结束，不无限吊胃口。

具体阅读回路是：**我在意这个人想得到什么 → 我能预期接下来可能发生什么 → 行动或信息改变局面 → 得到一次实在回报 → 新处境让我想看人物怎样回应**。回报可以是谜底、能力发挥、被理解、关系重新解释或过去细节在此刻发挥作用，并不只等于打败敌人。未知提供方向，兑现建立对叙述者的信任；只欠不还会消耗这种信任。

因此本次优先做“承诺—进展—兑现”的可追踪循环。没有引入靠倒计时、损失恐惧或惩罚离开维持阅读的产品机制。需要阅读兴趣，而不是将停下来设计成损失。

这些是可检验的产品假设，不是保证让所有人持续阅读的公式。DOC（ACL 2023）支持在特定长篇任务中分离规划和生成的方向；悬念研究强调情感意义、预期和求解，不能据此宣称开放互动留存已被验证。来源：https://aclanthology.org/2023.acl-long.190/ ，https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2015.00079/full 。文档中的 StoryBox 缺少核验来源，本次不依赖该论据。

## 实施架构

现有本机 Node + Codex 传输、localStorage、事件提交保留。没有证据支持为了内容质量改写成 Go/Rust 或引入向量数据库。

输入与权威世界/状态 → 情境与方法选择 → 规划模型（两个结构不同的小构想，其中允许自由构思；选定场景工作稿） → 写作模型（正文、事件、叙事增量） → 结构与证据核验 → 正文/事件/叙事记录原子提交。

方法库保存少量原创方法卡：适用条件、具体操作、禁用情形，而非复制小说片段。方法只是选择工具，不允许覆盖世界事实。同一方法近期使用会降权；优先处理拖延的期待，允许安静余韵与结束。

方法检索最多3张。规划返回两个有不同人物决定、因果路径或兑现方式的候选；本地先验证世界/状态版本、方法ID、已有线程和原句来源，再按明确休息、过期期待与兑现优先级选择。此优先级不是文学评分。写作只看到选中场景及核实原句；未选候选不进入写作或存档。没有额外评委模型和自动重试链。

正文中已建立、尚未解答的重要问题应记为线程；未来才可能发生的方向记为机会。旧存档没有快照时，模型从现有内容恢复最相关的少量期待，并要求本轮正文自然提及以提供证据，不回写旧回合。一个局部成果不等于整个故事结束，剩余核心目标与人物冲突仍可发展；也不为续写制造人为障碍。

规划结果只在服务端本次请求中存在，候选不作为事实提交。写作输出用正文中的原句支持期待记录的变更；当前保留记录中已解决的问题不能重新打开。完整语义一致性不能仅靠字符串验证证明，连续多轮样本另行评审。

## 公共接口与数据契约

`src/narrative-state.js`：无服务端依赖。导出 `validateNarrative(value, expectedTurn?, expectedWorldKey?)`、`advanceNarrative(previous, delta, prose, nextTurn, worldKey)`、`narrativeForBranch(branch)`。

Narrative snapshot：`{schemaVersion:1,worldKey,turn,focus,threads,recentBeats,opportunities}`。

- thread：`{id,question,stakes,status,openedAt,updatedAt,evidence}`；status = open / progressed / resolved / retired。最多8项；已有问题的question、stakes保持稳定。evidence为建立或更新时的正文原句。
- recentBeat：`{turn,kind,summary,methodId}`；kind = setup / progress / payoff / aftermath / rest；最多6项。
- opportunity：`{id,condition,idea}`；最多3项，明确为未发生的未来候选。
- delta：`{focus,beat:{kind,summary,methodId},threads:[{id,question,stakes,status,evidence}],opportunities}`，单轮最多3条线程更新；所有更新必须有正文精确证据，且保留记录中的resolved/retired不能重新开启。新线程必须open或progressed。保留未更新线程；只淘汰此前回合已结束的最旧线程，不默默丢弃开放期待，也不丢掉本轮兑现证据。

这是有界叙事记忆，不是永久问题数据库：已淘汰记录的ID不再保留墓碑；相同问题换一个ID也无法靠结构校验识别。旧正文与事实仍随分支保存，但不能承诺无限篇幅后绝不重提旧问题。

生成请求增加可选 `narrative`（当前最后已提交快照）；输出增加 `narrative`（advanceNarrative生成的下轮快照）。旧存档缺失字段合法。commitTurn同时提交；分支从复制的历史末轮读取，切换世界版本不复用旧机会。润色保留状态与叙事记录，纠错从前一轮重新出发，没生成快照时下一轮从实际事实重新规划。

## 边界和运行

辅助问答/措辞/润色仍走原有独立通道；原生假设输入不可借新架构暗中推进世界。默认新引擎，两次模型调用共享一次请求超时与取消，不无限重试。可显式配置direct作为开发对照，绝不在失败时悄悄降级并伪称已规划。全局并发、去重、来源检查沿用原服务。只展示通过核验的完整正文，不先播放尚未提交的决定性结果。

## 验收

自动化验证旧存档、分支隔离、期待兑现/退役、候选不变成事实、证据缺失拒绝、失败取消不提交。真实模型对照同一起点与动作，至少两种题材连续多轮；测试直接阅读、有效行动、拒绝机会和休息。保留完整请求与结果于本机test-results，报告调用耗时与限制。读者是否愿意继续需要用户实际体验；不能以模型自评分或测试通过替代。
