# 场景推进与路径体验改动（2026-10-10）

目标：减少走一步、看一眼、再确认的细碎回合，让选择路线产生完整事件和有用的后果，同时保留玩家的重要决定、世界事实和时间约束。

## 实现

- `src/scene-direction.mjs` 从已提交的近期场景和期待记录派生本轮节奏，不保存新的事实。旧问题三轮未更新或五轮未解决时，进入优先兑现名单；连续两个发展节拍后也提示交付成果。默认最多新增一个期待，旧问题积压或已有三个活跃期待时提示先兑现。
- 构思和写作收到同一份 direction。候选排序降低与最近正文/节拍摘要逐字重复的 payoff 优先级，明确的休息请求优先。重复检测是保守的文字检测，不声称理解所有语义重复或判断文学质量。
- 场景写作要求普通移动连贯到达并呈现第一件有意义的事；危险、玩家明确的逐步探索、接手条件、重大代价仍须停在选择之前。用行动和对话作为原文证据，避免为了记录再写一遍总结。
- 路径生成要求可见的吸引点和不同的收获或取舍。新地图优先场景地点，不不断创建门边、路口内侧等微节点。既有地点不会被追溯删除，未选择路线也不会被当作历史。
- `game-state.js` 支持将公开 fact 记录呈现为 clue；保留原记录的 kind、certainty、id 和 name。仍拒绝物品、人物、地点混用身份。此问题由真实模型测试发现并经失败用例复现。
- 没有增加模型评审调用、循环重写或固定剧情脚本。单输入框和现有状态、证据、分支校验继续使用。

其中场景尺度、路径吸引点、新期待名额和文风是模型生成约束，不是程序能证明的文学质量保证。程序确定执行的是上下文派生、候选排序和原有提交校验。

## 局限

- 两条路线是小样本验收，不是盲评、长篇稳定性或阅读留存证明。尚不能声称所有题材、每条路径都持续吸引人。
- 生成仍需要构思和写作两阶段，实测等待时间长。本次主要改变故事推进尺度，没有解决响应速度。
- 新规则作用于后续生成，不改写旧存档的碎片化正文或地图。既有未结构化人物资料缺失的问题也未在本次回填。
- 本次未改版前端视觉，也未加入地图的语义自动聚类；已有地点记录不会凭名称相似被合并。
