# 生成式 UI 的官方证据与本项目重构边界

核验日期：2026-10-15。结论：值得借鉴的是**按任务选择界面、可持续编辑的作品对象、明确的状态归属、真实进度与失败恢复**。React / TypeScript / Vite 可以作为本项目的工程选择，但公开资料不支持“换成 React 就拥有 ChatGPT / Claude 的智能交互”，也不能据此判断两家的完整内部技术栈。

本次按 research 技能的一手来源流程，实际打开下列 8 个官方页面并阅读正文；搜索摘要仅用于定位。未登录两个产品做同题生成，未调用模型、消耗生成配额或测试账号可用性。这里是**功能参照与工程建议，不是竞品性能实测**。已阅读 [上一轮交互研究](2026-10-14-chatgpt-interaction-reference.md) 和 [本地差距报告](../AI-INTERACTION-GAP-2026-10-15.md)；前者提供线索，后者提供既有本地验收记录，本次没有重跑它们的测试。

## 3. 对本项目可提出的差距与验收目标

以下本地现状均来自上述既有验收报告，不是本次新做的代码审计；重构前应由当前源码与回归结果确认。右列为本项目设计建议，不是供应商实现内幕。

| 既有报告中的本地证据 | 值得补齐的能力 | 可检验的完成条件 |
| --- | --- | --- |
| 已有自动选择与展示续改，但自然语言入口仍有保守规则，缺广泛措辞成功率 | 以任务语义路由，并定位所指作品；明确区分解释、编辑作品与推进剧情 | 对“看看另一种分法”“只保留这两条路”“继续赶路”等正反例记录路由结果；最后一句不能因正在显示图表就被误吞为界面修改。 |
| 新 digest 通过 `initialState` 映射局部参数；无关备注修改已避免重挂 iframe | 建立稳定 `artifactId`，让版本、代码、数据与运行时输入有各自身份 | 先调数量再改标签，数量保留；恢复旧版能说明恢复的是代码、数据还是输入。分支切换不混入另一分支的状态。 |
| 已有生成、审核和修复，但缺修改历史与稳定选区编辑 | 持久版本及局部 patch：每次修改基于明确 `baseVersion` | 只改标题时，其他交互保持；过期 patch 被识别而非覆盖新作；失败候选不会替换最后可用版本。 |
| 模型调用与提交尚非流式；已有生成/审核/修复等待记录 | 真正的分阶段事件流，而非给最终文本添加打字动画 | 首个进度、首个可见结果、首个可操作版本、最终完成分别计时；取消、失败、重试在界面有对应状态。上游无 token 流时，只展示真实阶段进度。 |
| 已有隔离 HTML/CSS/JS，但无外部依赖和服务调用平台 | 若扩大表达范围，补受控依赖与编译执行边界 | 依赖按允许清单和固定版本解析；运行错误能定位作品版本；宿主消息校验来源和结构。生成界面操作仍不得直接修改剧情事实或越过正式结算。 |
| 已有确定性测试和少量真实生成验收，尚缺固定题集重复运行 | 浏览器任务验证加持续质量评测 | 覆盖桌面/窄屏、键盘、计算正确性、连续修改、状态恢复和剧情不变；保存失败轨迹与截图。运行相同题集后再比较重构前后。 |

## 4. 推荐的重构边界

建议把 React + TypeScript + Vite 用于逐步替换智能工作区：React 组织可持续更新的界面对象，TypeScript 约束消息与动作协议，构建工具管理受控依赖。这是面向本项目维护成本的选择，并非竞品对等性的证明。保留已验证的剧情账本、分支隔离、审核和正式提交边界，避免把前端迁移与业务规则重写绑在同一次变更中。

建议使用以下五个可独立验收的接口：

1. `ModelGateway`：适配现有 Codex 路径与 API 路径，声明是否支持文本流、结构化输出、取消和用量信息；不支持的能力不伪装为已支持。
2. 类型化事件流：区分阶段通知、文本增量、作品候选、验证结果、最终提交、错误与取消；使用请求及作品标识关联事件。暂存候选可以展示预览，但只有通过验证的版本成为当前版本。
3. `ArtifactStore`：保存稳定作品身份、父版本、来源消息、代码/组件描述、数据快照和验证结果；局部输入单独保存，并为跨版本迁移提供显式规则。
4. 双运行路径：已知业务操作用受控组件；确有必要的自由交互代码进入独立沙箱。允许依赖、网络能力与宿主动作分别声明，不能因用了 iframe 就认定隔离完整。
5. 浏览器验证器：对生成结果检查加载、错误、布局和关键操作，再决定发布或修复；记录实际观察，不以生成的自评替代运行证据。

建议先固定一套同故事、同输入的多轮任务，冻结基线后再迁移。最低记录应包含路由正确性、首次验证通过率、最终任务完成率、连续修改后状态保持率、误推进剧情次数、取消有效性和端到端 p50/p95。首次可见与首次可操作应分别记录；这是拟议验收方法，本次没有产生这些数据。

## 5. 仍未验证的边界

- 两家产品在本用户账号上的可用性、真实生成质量、同任务延迟、连续多轮稳定性及成本，没有本次实测数据。
- 支持 React/HTML 预览不证明宿主使用 React，也不证明拥有公开可复用的产品生成引擎。两家内部路由、提示词、模型组合、编译服务和沙箱实现均未由这些来源确认。
- 对话续改、分支、保存代码、跨会话数据存储是不同能力；没有证据保证任意作品改写后能无损迁移运行状态。
- 上述公开技术可以成为本项目基础设施参考，但不能从 AI SDK 或 A2UI 的存在推断 ChatGPT、Claude 正在使用它们。
- 本报告只新增研究文件；没有修改应用、安装依赖、上线、调用登录态产品或运行真实模型评测。
