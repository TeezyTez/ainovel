# ElseLife 首页：前沿 AI 官网研究与设计转译

日期：2026-10-15。范围：官方首页的信息层级、产品入口、文案与组件语义，以及官方品牌指南；结论用于本项目设计，不是排行榜。

## 证据边界

本次成功读取 13 家公司的官方首页正文：Anthropic、OpenAI、Google DeepMind、xAI、Mistral、Runway、ElevenLabs、Midjourney、Cursor、Cognition、MiniMax、Moonshot、DeepSeek。Perplexity 首页仅返回图片，Luma 首页返回工具不支持的 Markdown 内容类型；因此对这两家的首页不作完整审美判断。Z.ai 未能访问。

正文抓取能确认内容、入口、按钮标签、媒体声明和分组，不能证明实际字体、色值、空间关系、动画节奏或响应式表现。IAB 载入 Anthropic 后读取界面仍超时，本次没有成功取得可供视觉审阅的网页截图。以下外站观察严格限于可核实内容；ElseLife 的字体、配色、空间与动效数值均为独立设计建议。

## 官方证据与可迁移原则

| 官方参考 | 此次确认的首页结构 | 对 ElseLife 有价值的原则 |
| --- | --- | --- |
| [Anthropic](https://www.anthropic.com/) | 首段用一句明确的研究使命定调，随后是产品发布与分类清楚的内容条目。 | 首页需要一个能够长期成立的核心命题；不要在首屏同时讲世界引擎、模型、记忆、人物关系和生成技术。 |
| [OpenAI](https://openai.com/) | 首页在机构导航之外直接提供 ChatGPT 输入入口；随后是新闻、故事、研究等独立栏目。 | 主入口可以就是产品体验；品牌说明与使用动作无需隔一层“了解更多”。 |
| [Google DeepMind](https://deepmind.google/) | Models、Research、Science、About 分工明确；首屏主标题后包含带媒体、介绍和 Learn more/Try 的产品条目。 | 大视觉必须有具体对象与行动；世界展示应该能进入世界，不能只是不可操作的氛围背景。 |
| [xAI](https://x.ai/) | 主标题和主 API 入口之后，用 Chat、Build、Imagine、Voice 等真实用途构成产品分区，页面还包含代码和使用演示内容。 | 将抽象能力转成可识别的行动。ElseLife 应让人马上理解“进入现成世界”与“写下自己的世界”。 |
| [Mistral](https://mistral.ai/) | 首页核心命题围绕控制权；导航、产品解释与客户案例持续服务同一个观点。 | 独特气质来自反复兑现一个命题。ElseLife 可围绕“另一种人生由你的选择继续”组织整页。 |
| [Runway](https://runway.com/) | 统一品牌命题后，Creative、Dev、Robotics 三条平台路线各有具体用途与入口。 | 先统一体验，再分支。不要把不同世界做成互相冲突的 UI 产品；用统一的封面比例与进入方式容纳不同题材。 |
| [ElevenLabs](https://elevenlabs.io/) | 品牌标题后区分创作、Agent、API；可读取到叙事文本、语言/声音选择器和 Play 按钮，也有真实产品界面示例。 | 用一小段真实结果建立可信度。ElseLife 可展示 60–100 字剧情开场与一个选择，而非堆砌“无限可能”。 |
| [Midjourney](https://www.midjourney.com/) | 导航入口有限，内容围绕想象力、美、人的未来以及项目展开；登录与探索都直接可达。 | 文学性与产品清晰度可以并存；诗性主标题旁仍应有明确的进入入口。 |
| [Cursor](https://cursor.com/) | 简短任务导向标题后给出主 CTA；首页多处将产品界面作为可交互演示，并有对辅助技术可读的演示说明。 | 体验展示要对应真实功能；同时提供静态文字解释和键盘可达的操作。 |
| [Cognition](https://cognition.com/) | 直接说明 Devin 是什么、如何工作，并给出 Try / Download；随后是研究、团队、文章。 | 对第一次访问者，应有一句无需懂 AI 的产品定义。 |
| [MiniMax](https://www.minimax.cn/) | 模型、产品、API、研究职责分明，每个产品段落配具体能力和实际入口。 | 设计导航时按用户目标组织，不按实现模块组织。 |
| [Moonshot](https://www.moonshot.cn/) | 简短品牌命题与产品/API 入口并列；后续包含研究、能力及有主题的 Doodle 内容。 | 一个持续使用的视觉母题可以容纳许多不同世界，而不必每张卡片各自建立一套装饰语言。 |
| [DeepSeek](https://www.deepseek.com/) | 短品牌命题加少量产品入口，页面内容很克制。 | 首屏可以很少，但每个元素都需要承担明确职责。 |

品牌层面另有两条可确认的证据：[OpenAI 品牌指南](https://openai.com/brand/)强调字体同时支持精确性、可读性和亲近感，标志保留清晰的周围空间；[Mistral 品牌指南](https://mistral.ai/brand/)明确将模型的像素插画视为标志系统的延伸。这支持“建立可复用的视觉规则”，不支持直接复制某一家的字形、颜色或标志。

## 适合 ElseLife 的方向

以下为本项目设计判断，不是对外站画面的描述。

**建议主题：一座收藏未发生人生的文学档案馆。** 外层界面冷静、精确、可读；世界内部有情绪、天气、时间和人物。延续黑白基础与局部虹彩，让虹彩只承担穿越边界、激活世界或选择反馈的含义。避免把所有组件都变成发光玻璃卡片。

### 导航与首屏

- 导航控制在品牌、探索世界、我的故事、设置/账户四个职责内。若当前只实现探索与存档，就只显示已实现的内容。
- 首屏只保留一个核心标题，例如“在未曾发生的人生里，成为你。”，配一句产品说明：“进入一个世界，让每次选择改变接下来的故事。”
- 主按钮使用动作与目的地明确的文案，例如“进入一个世界”；次入口“写下我的世界”使用文字按钮或更弱的描边。不要让二者同等抢夺注意力。
- 一个不对称构图就足够：标题和行动组成稳定的一侧，虫洞/世界窗口占另一侧；视觉主体要与探索列表共享同一空间语言。
- 若已有存档，提供小型“继续上次的人生”入口；不要让回访者每次重复观看大段营销内容。

### 排版与色彩

- 使用两种角色明确的字体：文学标题用衬线/宋体方向，导航和交互用中性无衬线。不要为“高级感”混用三四种字体。
- 中文主标题采用约 56–80 px 桌面尺寸、38–48 px 移动尺寸作为起点；正文 16–18 px、舒展行高。具体数值需在实际断行和字体回退下验收。
- 主界面采用近黑、暖白和少量中间灰；虹彩的面积和亮度都应受限。大面积纹理应低对比，不穿过主要文字。
- 采用内容驱动的留白：首屏主张、产品动作、世界入口之间形成明显停顿；不为增加页面长度而加入无意义空白。
- 小号等宽字仅用于章节、世界编号、时间或坐标；所有“系统状态”都要真实，不能制造虚假在线人数、信号数或 AI 正在运作的假象。

### 世界卡片与叙事入口

- 从“功能 bento 卡片”转为“有情境的世界封面”：世界名、一个题材标记、一句具体悬念、明确进入动作。
- 卡片最好以不同的叙事细节区分：车站广播、雨夜来信、失踪旅客、会记住名字的书店，比“奇幻/科幻/治愈”更能建立记忆。
- 每张卡片只保留一个点击目的地。收藏等次动作独立可见且语义明确，避免整卡嵌套按钮造成键盘或触摸困扰。
- 重点世界可以用一个大封面加两三个小条目的编辑式构图；不要为了整齐把所有世界做成完全同重的方块。
- 最有说服力的演示是可读且可操作的故事开场。选项应能进入实际对应世界或接入已有创作流程；无法实现时应保持为明确标识的预览。

### 动效与交互

- 虹彩门洞负责慢速环境运动；内容负责稳定阅读。指针偏移只增加深度，不承担任何必需功能。
- hover/focus 展示“即将进入哪个世界”，而非仅把卡片放大。可通过小范围的封面位移、边缘显影、章节号变化表达。
- 交互反馈建议约 140–220 ms；内容入场约 400–650 ms；环境循环可更慢。这些是待验收的设计起点，不是外站测量结果。
- 进入世界的转场沿同一视觉对象展开：封面/门洞放大，背景淡出，故事文字接续。避免每一步都换一套随机动效。
- 尊重减少动态效果偏好；触摸端不依赖 hover；点击后应立即有可见反馈，画面重的演示不应阻碍主 CTA。

## 应避免的同质化

1. 大标题、渐变球、三个优势卡片、数字墙的通用模板。它能表达“某个 AI 产品”，很难表达 ElseLife。
2. 直接照搬 Moonshot 的同一虫洞形式、Mistral 的像素语言或任何公司标志。可借鉴系统性，不复制识别符号。
3. 把“高端”理解为小字、低对比度、过大留白和无标签图标。
4. 用不可操作的按钮、虚构统计或假的实时状态模拟成熟产品。
5. 为了展示技术而让每个图层都持续漂移。对文学产品，静止与阅读节奏也是体验的一部分。

## 实施优先级

1. 收敛首屏标题、产品定义和一个主行动，建立黑白与局部虹彩的规则。
2. 调整世界封面的信息顺序、比例、留白和真实入口；让每个世界有具体悬念。
3. 统一导航、按钮、标签、focus 状态与移动端布局。
4. 再加入持续环境运动、指针反馈和进入世界的连贯转场，并在实际页面检查阅读与性能。

这些建议不要求新增模型、后端或虚构能力；应优先使用项目现有世界、存档和创作功能。
