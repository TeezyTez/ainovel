# 自适应体验整合 Implementation Plan

> 执行：使用 superpowers:subagent-driven-development，当前目录直接修改。任务书与用户明确授予技术自主权，因此不增加方案审批门槛。保留现有本机存档、自由输入和两阶段叙事。

**Goal:** 将一句话开局、自然查询、对象选择、行动、世界时间和恢复整合为实际可玩的闭环。

**Architecture:** 沿用原生 JS / Node、现有经验对象和回合事件。增加小型的共享交互语义层；前端负责本地查询和临时选择，后端负责已登记分支的版本与持久回执。静态可信组件目录不生成任意代码。

**Spec:** 桌面附件《方糖｜自适应富交互与叙事体验：项目重构任务书》，本轮完整阅读。P0 优先；不引入支付、社区、新框架或独立服务。

## 实仓发现

- 已有动态六类组件、经验对象、历史比较、有限时间推进、逐回合回放、原文引用、旧按钮失效与本机 CAS。
- 查询命令分散在 game-query/local-commands/detectIntent，普通“我现在怎么样”可能被当作行动。
- 对象只能逐个查看/引用，缺少明确的多选指代与选择生命周期。
- 开局需要生成、采用、保存、进入多次跳转。
- /api/generate 无持久分支权威；幂等响应缓存仅五分钟，重启后消失。隐藏设定曾在完整浏览器作者存档中保存，不能声称它具有服务端授权隔离。

## 工作项

- [x] A：后端持久分支登记、版本冲突、幂等回执和恢复接口；保留旧档导入语义。测试并发、重试、取消、重启与篡改。
- [x] B：共享对象上下文与本地查询/比较/呈现组件：稳定 ID、分支版本、明确清除，不做行号指代，不修改世界。测试未知、同名、旧版本与隐藏字段。
- [x] C：主应用接线、一句话直接开始、临时选择接续自由输入、只读/草稿/行动隔离、阅读信息密度与固定资料入口；保持输入与焦点。
- [x] D：审查时间与人物连续性、跨题材三类实测、真实 API + 浏览器完整旅程，记录所有失败与未测项。

## 接口与责任

A 独立修改 server 分支存储及 server.mjs；公共模型校验需与主代理沟通。B 独立修改新增 interaction-context.js / interaction-ui.js / interaction.css 与测试；主代理独占 app.js、reading-ui、创建界面与接线。A/B 可先后派遣，避免共享文件冲突。审查代理不改代码。

## Review Focus

1. 旧请求在新版本返回，不能覆写且保留草稿。
2. “比较这两个”无有效选择时不得替用户猜对象。
3. 引用旧事实不意味着重新授权旧动作；看资料/拟草稿不能推进时间。
4. 中断发生在服务端提交后，恢复要带回原回执，不重复扣费。
5. 未公开角色与未知时间/年龄不可在界面补造；本机作者权限与真正多用户隔离必须明确区别。

## Rulings / ledger

- 用户指定当前仓库直接重构；无可用提交基线，不创建空 worktree、不自动提交或迁移旧存档。
- 后端在本机增加受限持久账本，用于实际应用生成；首次从旧浏览器分支登记是显式兼容导入边界，不称为多用户云权限系统。
- 实现与验证逐项写入本文件；不把样例测试当作真实模型结果。
