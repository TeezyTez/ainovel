# 按需富呈现修复与验收（2026-10-10）

## 真实问题

用户输入单独的“地图”未命中 gameQuery，被送入剧情生成；当前回合地图又可能受纯阅读密度影响而折叠。旧地图只用数字圆点配合另一份地点列表，难以直接阅读。通用查询先于类型化视图，还会让背包等请求走文字资料列表。

## 实际改动

- 支持裸名称和明确的自然表达，如“地图”“给我看看地图”“我想看一下地图”“能显示地图吗？”；优先读取当前分支公开状态，跳过生成与提交回合。
- HTML 可点击地点卡片覆盖在 SVG 路线图上；显示名称、当前所在、已有状态与有向连接。地点点选只打开详情，可展开大图；窄屏局部滚动并居中当前位置。
- 合并已有地图与补充地点；没有连接的记录留在详情，不凭空连线。描述性的旧 location 不再与明确的当前地点重复展示。
- 用户明确索取的当前回合地图即使在纯阅读模式也直接展开。
- 物品用卡片网格，已知数值用原有状态/进度组件，人物用资料卡，约定与事件用时间线，对比与明确“用表格显示物品”请求用表格。人物关系按已记录的玩家关系呈现，缺失关系明确标注。
- 保持单一常驻输入框。呈现调整放在折叠选项里；查阅成功后清空已提交的查询文本，切换查询时收起上一类视图。
- 所有内容由受控 HTML/SVG 组件渲染，数据文本转义，不执行模型返回的任意脚本。

## 未解决的范围

旧存档部分 NPC 仅存在于正文，没有独立对象记录；此次没有做全文模型回填，因此这些人物和关系尚不能完整显示。无数字或上限时不制造状态条；没有已记录的连接时不生成虚构路线。时间线按对象记录版本排序，不把模糊故事时间转换成精确日期。地图为拓扑示意，不是等比例地理图；关系呈现不推断 NPC 之间的关系。此次没有新增模型调用，验证针对真实存档的只读 UI，不宣称跑过新的模型生成。
