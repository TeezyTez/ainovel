## 目标和范围

在现有原生 JavaScript / Node 项目内贯通模型提议、动态呈现、局部输入、正式行动、持久结果和后续叙事。保留正文中心、自由输入、输入框旁的「+」及既有地图体验。场景中有价值的操作就近出现，详细资料与管理功能按需打开。

这是一项架构改动：不能只把现有卡片换成可配置标题。最低交付包括真实生成的多步规则组合、商人交易闭环、至少 10 个无专用业务分支的新情境和 3 个无需界面的情境。未通过的项目必须单独列出，不用模拟结果替代真实模型证据。

不新增框架、现实支付、社区、图片生成或其他项目服务。不覆盖当前工作区中与本轮无关的未提交修改，不删除用户存档，不自动发布。

## 技术路线

采用受限 JSON 交互定义和纯函数规则解释器。模型不输出可执行 JavaScript，不获得 DOM、网络、文件、时钟或任意数据库写入能力。

比较过的方案：继续扩展固定场景卡片，改动较小但不能满足新场景组合要求；执行模型生成代码，表达力强但引入本任务不需要的隔离平台；受限声明式组合能够复用现有验证与渲染方式，是本轮选择。

规则的可信度来自正式登记、来源和执行权限检查。模型提出的条件不能自动成为权威事实；格式通过也不代表世界规则正确。

## 交互契约

契约有明确版本，包含以下五部分：

1. `scope`：worldKey、sessionId、branchId、sceneId、sourceTurnId、baseVersion；服务端分配 interactionId、revision 和定义摘要。客户端不能自行声明有效归属。
2. `presentation`：`none`、`hint` 或 `interactive`，以及玩家可见的解释和出现条件。`none` 是一等有效结果。
3. `view`：受限树，可组合段落、分组、对象引用、列表、比较表、输入、选择、简图、条件区和重复区。只通过声明的公开数据绑定取值。
4. `flow`：有界步骤、临时字段、输入校验、计算值和步骤转换。前端转换只修改交互草稿；需要人物判断或世界结果时必须提交正式行动。
5. `actions`：查看、起草、预演、确定规则行动或叙事尝试；列出目标、参数 schema、公开条件、已登记规则引用、代价和生命周期结果。

规则表达式使用结构化节点，支持有限的算术、比较、布尔、条件、集合聚合与显式字段读取。无字符串脚本、动态属性访问、递归、无限循环或外部函数调用。数组展开、深度、节点数、字符串长度、求值步数和数值范围均有硬上限；成本使用整数最小单位。除零、溢出、错误类型和未知操作立即报错。

规则效果限定为已允许对象上的资源增减、对象转移、公开状态修改和带来源事件。必须声明写入集合；不得通过 UI 定义修改秘密、任意角色信念或用户未授权的承诺。随机结果如有需要由服务端采样并随首次提交持久化，重试读取原值；首批不以随机玩法作为必须新增的功能。

角色说法、推测和确认事实分别引用，界面不能把“商人说有效”转换为确认属性。公开禁用原因必须来自玩家已知条件；隐藏条件只能在正式裁定后提供可公开的反馈。

## 世界提交与叙事分离

服务端扩展分支的正式事件日志，区分既有完整故事回合、已提交行动和附加叙事。统一从日志生成当前状态；前端历史回合只是投影，不形成第二份权威账本。

确定规则行动的流程：

1. 收到 requestId、完整 scope、interactionId/revision、actionId、目标与参数。
2. 读取权威状态，核对幂等指纹、版本、所有权、定义摘要、参数和世界条件。条件改变时拒绝旧请求，保留草稿，不擅自采用新报价。
3. 在一次持久写入中登记动作、全部资源与归属变更、事件、状态版本和回执；将其叙事标记为待补充。
4. 返回正式结果。即使模型超时或连接中断，已提交操作也不会回滚为“未发生”。
5. 后续生成以该回执为输入，只附加叙事及经过校验的后续提议；不能再次执行相同动作，不能推翻已结算结果。

`requestId` 与输入指纹一致的重试返回同一回执；同 ID 不同内容拒绝。叙事重试引用 operationId，使用独立的 narrationRevision，不能增加动作次数或重复扣款。为保持顺序，待补充叙事期间允许查询、保存和编辑草稿，暂不接受依赖未完成叙事的新世界行动。

没有确定规则的行动走现有叙事裁定流程：生成结果验证通过后才提交，不先保证成功。涉及交易条件或规则的新提议先形成正式记录，不能直接凭模型声称的“成功”执行确定规则。

自由输入由解释阶段生成相同的结构化行动提议。明确匹配当前规则的输入进入同一执行器；议价、换物、人物立场等无法确定计算的请求进入叙事裁定。复合输入必须保留所有约束；无法唯一解释就请求澄清，不能只执行识别到的一个短语。

服务端继续使用本机单服务文件账本。原有进程内锁覆盖多浏览器页面并发；同一账本多服务进程运行应通过持有锁拒绝或使用文件级互斥，不能声称进程内 Map 足以支持多进程事务。

## 生命周期与恢复

交互状态区分 active、in-progress、completed、stale、archived。重要多步输入按 session/branch/interaction/revision 保存；显示折叠状态与输入分开存储。

模型新提议只更新相关区域。自动出现不抢焦点、不滚动、不清空自由输入。玩家主动打开时才移动到结果；触屏不依赖悬停，选择和拖动都提供键盘/列表替代。

世界版本或交互定义变化后保留原草稿并标为待核对。允许继续查看，但旧提交按钮失效。无关世界变化不重建整张表单；是否仍可执行仍以服务端版本与条件检查为准。

历史片段保存当时的公开契约和回执，只读查看原报价与输入，不将今天的数据覆盖到过去。切换分支时不得复用另一分支的输入、定义或回执。

未知显示节点降级为其文字摘要；未知执行规则不执行，保留上下文并提供自由输入。界面生成失败不丢失已经验证的正文；正文裁定失败也不能造成半笔世界操作。

## 兼容和公开边界

新增日志、契约与回执需带独立版本。旧档先经现有验证，再转换为等价的已完成日志记录；保留原 turnId、requestId、来源引用、分支关系、个人笔记及未发送草稿。

迁移在副本中完成并验证回放一致性，成功后原子安装；旧文件保留可恢复备份。无法验证时保留原文件并说明原因。新导出携带新格式版本；导入仍支持旧格式，禁止为了兼容而丢弃待完成交易或规则。

新运行接口仅返回当前分支的公开事实及交互，不下发私有世界再靠前端隐藏。旧档中已被作者保存的秘密无法“撤回”，但新接口不得继续扩大披露。作者导入、编辑与玩家运行入口分开处理，维持本机授权边界，不声称已有多用户云权限体系。

产品标识按任务书统一为「人生副本 / ElseLife」、包标识 `elselife`；已有存储键、owner token 和数据路径保留兼容，不通过改名清空历史。

## 验收与证据

自动验证覆盖解释器资源上限和非法输入、引用和权限、流程恢复、原子资源转移、重复请求、不同参数复用 ID、并发、过期、跨分支、取消、迟到结果、重启恢复、叙事失败后单独重试、历史只读、秘密投影及旧档回放。

商人过程必须覆盖真实报价与声明性质、比较与数量、余额和库存、购买回执、后续叙事、自由议价及拒售。不得新增商人专用渲染器或专用执行分支。

通用实现完成后固定代码版本，再编写至少 10 个新的情境输入。它们必须覆盖多对象比较、资源分配、多步输入、条件变化、人物判断和运行时生成的规则组合，不能仅换名字。每例保存世界内容、初始正式状态、模型原始输出、通过或拒绝理由、操作参数、回执和恢复后的状态。若验收暴露缺陷，通用修复后重新记录版本并重跑，不能伪称始终没有改业务代码。

另保留至少 3 个纯正文情境，实际验证模型选择 `none` 且界面没有额外卡片。对同一场景改变玩家意图、人物立场和关键条件，检查语义变化；只改变无关文字时不扰动用户正在编辑的内容。

真实模型证据与固定数据测试分目录记录，所有失败和重试保留。记录实际耗时、调用次数与可获得的用量；供应商未提供的 token/成本填“不可得”。通过本机现有模型运行，不读取或输出授权令牌。

浏览器验收覆盖桌面、窄屏、键盘、草稿保留、局部更新、刷新续接、行内错误和“仅重试叙事”。真实设备软键盘及屏幕阅读器没有实测时如实列为未验证。

## 后续实施边界

技术设计获确认后，编写按依赖顺序的实施计划：契约与解释器 → 正式日志/迁移/回执 → 模型提议与自由输入统一 → 前端及恢复 → 新场景真实验收。先完成完整的最小通路，再扩大表达能力；最终验收范围不因分步实现而缩减。

本设计不把结构校验当成全部叙事正确性的证明，也不宣称能覆盖所有未知玩法。实际未支持的规则、生成失败率和验收缺口将在交付时逐项列明。
