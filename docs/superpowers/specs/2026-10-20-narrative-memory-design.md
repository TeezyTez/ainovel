# 有限上下文中的人物与剧情记忆设计

设计提案，2026 年 10 月 20 日。覆盖长期存储、场景取材、角色视角、压缩、写回与验收。用户已批准执行，落地范围与验证结果见[实施记录](../../../notes/2026-10-20-narrative-memory-implementation.md)；本设计文件本身不代表文学质量验收。

用户要求人物有各自的内在生活，经历能持续影响人物与剧情；数据库保存长期材料，模型在需要时获取。提示词有限，所以系统必须精细判断存什么、什么时候取、取到什么粒度，以及哪些信息可以压缩。

推荐在现有 PostgreSQL 正式历史上建立可回源的文学记忆索引，由 Go 按场景和生成阶段编译材料。Rust 表达本阶段需要了解的问题，Go 决定能读取哪些记录并装入预算。模型上下文是本次工作材料；未入选的信息仍在数据库中，不能因此视为已经遗忘、失效或不存在。

## 1 设计目标与边界

人物连续性来自过去如何影响现在的理解和选择。人物可以有矛盾、误解、自我辩护、成长和反复；性格概括只能帮助理解这些变化，不能把角色锁成固定反应。日常关心、默契、体面、习惯和小小的不快，同样值得保存。

本设计区分三件事：一段经历值得取回；它会影响此刻的反应；人物有理由把它说出口。三者分别判断。检索到的经历可以影响称呼、说明量、动作和选择，也可以在当前场景没有可见表现。不设每场回忆、口头禅、冲突或拒绝玩家的配额。

Go 继续拥有正式页、事实、分支和事务提交权威。记忆摘要、检索标签、关系解释与未来设想均为派生材料，不能单独证明事件发生、授予角色知情或替玩家作决定。保留现有世界事实与人物说法、信念的区分。

采用“原始依据 + 可重建索引 + 按需工作材料”。只延长滚动摘要仍会混淆稳定特点与临时任务；只增加语义检索无法保证找到约定、关系转折和无关键词重合的相关经历。语义检索可作为候选发现手段，权限、来源与本场用途由统一流程处理。

## 2 当前系统可以复用什么

已有正式页和状态快照、分支版本、来源句柄、回取收据、容量检查、生成阶段和审稿绑定可以复用。当前缺口在材料选择和组织：

- [generation_view.go](../../../backend/internal/experience/generation_view.go) 的 `compileGeneration` 先尝试全量，容量不足后依规则、秘密、近期记录和名字关联筛选；人物笔记仍整体保留。
- [source_reader.go](../../../backend/internal/experience/source_reader.go) 与 [experience_retrieval.sql](../../../backend/internal/sqlc/queries/experience_retrieval.sql) 支持固定版本的记录和整页回取；名字、词项与类型筛选主要在 Go 扫描 JSON，没有面向关系经历、约定和人物表达的检索接口。
- [narrative_pipeline.go](../../../backend/internal/experience/narrative_pipeline.go) 的 actor 投影只接收已物化且角色知情的事实。它正确阻止全局笔记泄露，但稳定人物依据可能先被容量投影遗漏。
- [narrative_state.go](../../../backend/internal/experience/narrative_state.go) 已有经历、目标、关系、声音和剧情线索笔记；完整替换的自由文本不能精确表达“哪些特点继续成立、哪些只属于刚才那场戏”。

旧样例已经显示：正式快照仍有角色声音和目标，生成视图却省略它们；角色只收到近期订单事实。这要求从数据库按需要补齐材料，而不是继续在被裁剪的上下文里寻找丢失信息。

## 3 长期保存的层次

### 原始依据

正式页与原文、版本化世界事实、作者明确设定及其版本长期保存。对白、承诺、误解和关系转折保留可定位的原文入口。压缩只产生新的读取表示，不删除或改写原始依据。

发生时间、记录版本与人物获知时间分开。例如秘密发生在第三天、某人第五天才知道；第五天的知识不能回填到第三天的反应中。未知时间保留未知，不伪造精确时刻。

### 文学记忆索引

索引记录一段材料涉及谁、与什么关系或未解决问题相连、可从哪里回看，以及当前是否仍有影响。它让系统能发现“应该查这件事”，不要求每轮把全部索引发给模型。

| 类别 | 需要保留的内容 | 当前场景中的取用条件 |
| --- | --- | --- |
| 人物倾向 | 在什么情境、面对谁、习惯怎样回应；代表经历与反例 | 人物出场时取最小身份与倾向依据；遇到相关压力或对象时展开 |
| 目标与在乎之物 | 长期在乎、当前目标、临时打算的区别；可能互相冲突 | 当前选择会影响它，或离场后未完成的行动重新进入故事 |
| 关系经历 | 有方向性的信任、期待、顾虑、共同习惯与转折 | 两人互动、评价对方、替对方决定或处理共同物件时 |
| 经历与后果 | 事件经过、选择、结果、尚在作用的影响；人物各自的认识 | 当前处境有相似的社会含义，或直接承接其后果 |
| 承诺与未了之事 | 谁对谁、承诺什么、条件、时点、履行情况 | 对象重逢、期限临近、条件变化、发生可能违约的选择时 |
| 表达与习惯 | 对不同对象的说明量、称呼、回避方式、少量对白和动作例证 | 本场有相应关系和交流情境；不要求照搬例句 |
| 物件与地点的意义 | 赠送、共同使用、丢失、修复等经历及各人的理解 | 物件或地点实际出场、被提及，或影响当前选择时 |
| 剧情线索与读者信息 | 已呈现内容、未解问题、兑现条件、人物和读者各自知情范围 | 情节进入相关因果链、需要回收或改变理解时 |

这些是可选记忆类型，不是每个角色必须填满的问卷。未观察到的特点保持空缺；新人物可以在正常互动中逐步形成。

“人物认为对方在躲自己”“作者设定他不愿承认依赖”“读者尚未见到一次解释”属于不同层次。角色包只使用其可知依据；作者对潜意识、误解和戏剧反讽的解释放在写作材料中，不能转成角色明确知道的真相。

### 本场临时状态

疲惫、急躁、紧张、正在回避的话题和临时计划有自己的时效。场景结束后检查是否产生实际后果。一次沉默可以留下误会，但不能自动沉淀成“性格冷漠”；一次道歉也不能自动把长期隔阂改成“关系已修复”。

## 4 记忆记录和读取粒度

派生记录至少需要以下语义，具体数据库布局在实施计划中确定：

```text
identity       记忆ID、所属经历和分支、可用版本
kind           人物倾向 / 关系经历 / 承诺 / 表达例证 / 其他已定义类别
subjects       涉及人物、关系对象、地点和物件
meaning        短提示及可选详细摘要；解释归属和不确定性
sources        正式事实ID、页版本、内容hash、原文位置或作者设定版本
time           发生时段、获知依据与时间、有效或失效条件
status         活跃、已解决、已修订；更新依据和相反证据
retrieval_keys 有来源的关系、事件和社会情境连接
```

世界状态来自正式事实；索引中的 `status` 只描述记忆记录的用途。作者未来计划不能写成已发生的承诺。检索标签“涉及接受照顾”是发现材料的辅助解释，不能证明人物一定害怕依赖。

每条记录可提供三种粒度：

1. **定位提示**：知道存在这段经历及其与当前问题的连接。
2. **关键摘要**：保留参与者、因果、条件、结果、知情差异与未解决影响。
3. **原文证据**：需要准确承接对白、含混措辞、承诺或关系转折时读取相关片段；必要时展开同一场景的前后文。

摘要由原始依据及当前有效变化重建，避免无限“摘要的摘要”。代表性片段保存完整语义，不截断否定、主语、条件或应答关系。原文页可能含角色不知道的旁白；允许作者读取整页，不等于允许 actor 读取整页。

同一记忆的 actor 版本从该角色已获授权的材料生成。不能先总结全知材料，再仅凭几个可见 fact_id 宣称摘要安全。自由文本语义仍需审查，引用覆盖与原字匹配只证明来源位置。

片段的角色访问许可必须来自 Go 验证的正式知情事实，或经审查的观察、听闻依据，并绑定人物与获知版本。索引提取模型不能通过自行填写可见人物列表授予知识。无法确认授权的新旧片段都只供作者使用，不进入 actor 包。

## 5 什么时候取 取什么

### 进入一场戏

操作接受后固定分支、版本和输入。Go 先从当前场景、最近交流和相关实体索引形成小型入口材料。入口包含当前局面、可能参与的人、活跃的相关约定以及可查材料的线索。

“她”“那个人”“三人”通过当前场景和最近交互解析，不能依赖用户每次重新输入全名。解析存在实质歧义时保留候选和未知；不能为了生成完整故事擅定主体。

复用现有 memory 阶段形成场景需求：谁与谁互动；眼前要处理什么；哪些旧事、关系或条件可能改变反应；哪里缺少依据。安静相处、休息和观察也可以是场景作用，不强制寻找危机或戏剧转折。

### 形成角色意图之前

根据参与人物批量查询数据库，给每人形成独立材料：

- 最小身份和仍有效的人物倾向依据；
- 他此刻知道、误解或不确定的局面；
- 面对当前对象的关系，以及最近改变这种关系的事件；
- 当前选择触及的长期在乎、目标和未履行约定；
- 相关经历和少量适用的表达例证。

查询从完整的版本化存储出发，不被第一轮缩略上下文限制。角色目录也必须在权限过滤后形成，不能泄露隐藏记录的标题、命中数量或存在性。

### 规划和选择场景时

提供角色意图、相关因果和世界限制、尚未兑现的后果，以及读者已经看过什么。规划不重复装入所有人物传记。候选如果依赖缺失的旧约定或事实，应定点补查；可合法创作的新细节不要求先在历史中存在。

缺少人物倾向或关系解释记录，不妨碍人物在当前授权与叙述视角内产生新的动机、情绪和选择。来源要求约束对过去的断言，不冻结现在的创作；新表现采用后再记录，不能为了证明合理而补造过去。

### 写正文之前

按选中方案重新取材，给 writer 连续性原文、当前人物之间的关系材料、适用的声音例证和必要的作者资料。清楚标注哪些是作者可知、哪些角色知道、哪些只是提案。

actor 的 speech 是可改写草稿。writer 根据人物目的、对象、情境和已有表达习惯组织对白。内部证明材料无需逐条说出口；若当前听者确实缺信息，仍须通过场内交流或观察建立来源。

### 审稿时

从实际写出的正文、涉及的人物和关系、新事实及知情申请反查必要依据。审稿不能只复用 writer 的缩略材料；否则遗漏会在两个阶段相互掩盖。检查事实边界，同时检查本场是否错误复述经历、忽略关系变化或把临时任务当成人格。

### 场景正式提交后

只有已采用并通过审查的正文及变更进入正式状态。提取阶段提出“新增经历、改变关系、履行约定、出现反例”等局部记忆变化，按来源验证后随正式页生效。未采用候选、规划分支和失败生成不能污染长期记忆。

索引可在提交后幂等更新，但必须有 `indexed_through_revision`。未索引的最新正式页通过增量补读覆盖；需要的索引未就绪时不能假装不存在该经历。重试索引构建不重试故事结果。

水位按经历、分支及来源版本命名空间维护，只有该前缀全部处理成功后才原子推进。索引批次发布时复核来源 hash、版本和构建令牌，拒绝作者修改或恢复操作之后迟到的旧任务。读取固定版本 R 时，摘要、关系解释和“已解决”标签同样只能依据 R 及之前的材料，不能给最新摘要附上旧页出处冒充历史视图。

## 6 如何发现无关键词重合的重要往事

检索同时使用具体人物关系、因果连接、未解决事项、当前社会情境和文本线索。当前请求“帮忙搬一盆花”，重要的可能是对方过去维护过他的体面，文字不一定相似。

先检索当前双方的关系经历和变化，再根据“接受照顾、欠人情、暴露无知、当众纠正、承担责任”等可能相关的场景解释寻找候选，最后回到原文核实。社会情境解释是检索假设，不是对人物内心的确定结论。

保留与旧概括相反的经历及较新的关系变化，避免永远只取支持“他不信任人”的记录。角色得到不同资料是正常结果；相同经历可能对两个人具有不同意义。

重要性依本场而变，不固定为一生不变的分数。取材优先考虑：

- 遗漏后是否会改变行动的合法性、因果或必要条件；
- 是否会改变人物对当前对象的期待和选择；
- 是否能解释本场的误解、沉默、矛盾或变化；
- 是否与仍有作用的承诺、代价或读者尚未解开的疑问相连；
- 是否提供尚未被其他材料覆盖的信息。

近期、出现频率、情绪强度只是辅助信号。强烈创伤不能自动挤掉相关的普通信任；很旧的承诺也不能因为年代久远被逐出。

## 7 压缩底线与容量处理

| 材料 | 可以压缩的内容 | 必须保留或能原文展开的内容 |
| --- | --- | --- |
| 重复日常过程 | 多次相似执行步骤、无变化的清点和环境描写 | 这次不同之处、造成变化的选择和仍有作用的后果 |
| 人物特点 | 重复表现归纳成带条件的短描述 | 面对谁、适用情境、重要例外和变化证据 |
| 关系经历 | 常规往来合并为模式 | 方向性、误会、信任或伤害的关键来源、未说开的部分 |
| 承诺与代价 | 不影响意义的叙述铺陈 | 谁承诺、向谁、承诺什么、条件、期限、不确定性和履行状态 |
| 对白例证 | 无关上下文和重复例子 | 应答关系、称呼与语境；争议依赖原句时保留原句 |
| 线索与物件 | 无关重复描写 | 实际观察、归属、谁知道、意义的经历来源；细节后来相关时可回源 |

不相关材料只是不进入当前窗口，原始内容仍可检索。今天是装饰的细节，之后可能成为线索，所以不能在存储时永久宣布“无文学价值”并删除原文。

预算按每个阶段分别计算：配置的可用输入容量，扣除该阶段 system、schema、固定载体和安全余量，并遵守模型输出预留。延用当前经过验证的容量计量，不用粗略中文字数或虚增窗口代替实际请求检查。

先保障本次输入、角色身份、相关行动限制和关键未了事项；再为实际参与人物覆盖必要的自身及关系材料，最后加入按用途选择的经历与表达例证。每人获得适当材料份额，避免一个资料特别多的人吞掉其他人物的存在。

超限时去重，降低次要材料的读取粒度，移除本场无关项，并保留可补查提示。不能把每条材料机械截短。若关键证据仍无法装入，应分开完成有界子任务并检查全部调用预算；在仍无法满足约束时明确失败，不能悄悄删除关键承诺后继续写。

审计记录保留完整取材过程，模型每个阶段重新装包。旧回取结果不无限累加到后续所有提示词。

## 8 写回时保留变化 避免标签化

人物倾向、关系和声音按记录局部更新，不整本自由重写。更新包含仍有效的旧内容、新证据、需要修订的适用条件；没有相关新证据时保留旧记录。

一次压力下的反应先作为场景经历；有持续后果就形成关系或目标变化。稳定特点允许在有依据时演变，但不采用“表现三次就成为性格”等固定计数规则。

“今天疲惫，没有解释”与“因此产生误会，尚未说开”分别保存临时状态和后续影响。“这次终于直接说了”作为与旧习惯不同的选择留下，不立即抹去旧倾向，也不因旧倾向否决人物成长。

解决的承诺和线索离开活跃列表，仍留在经历与关系索引中。已完成的帮助可能不再是待办，却成为以后信任的依据。阅读偏好仍独立保存，不能从虚构人物行为推断用户现实人格。

## 9 一个日常场景如何取材

以下是设计示例，不是模型运行结果，也不是必须生成的剧情。

林舟经常晚归，陈禾习惯等他吃饭。示例的已有记录包括：两人曾因未告知晚归发生不快，后来陈禾说过“晚了发个字就行”，林舟答应了。陈禾常用林舟第一次学陶艺做的歪蓝碗，平日会拿它开玩笑。本例另明确今天林舟没有按约发消息；他九点半带着夜宵回来，桌上的面已经凉了。

本场取回告知约定及原句、两人上次因此不快的经过、平时表达关心和不满的短例。如果蓝碗出现在当前场景，再取共同经历。不需要两人的完整履历、所有晚饭和所有物件。

记忆可让陈禾先问一句短话，或只是把碗移开；也可能影响林舟如何解释。具体反应仍由人物、眼前情况和创作决定。两人可以继续吃饭、争执或暂时搁置，不指定和解或惩罚。若改成已经告知，就不能沿用违约前提；是否告知未知时也不能凭冷面推断失约或委屈。

第二天若写普通工作，只取与工作场景相关的人物特点和经历。昨夜的不快若有明确持续影响，可以用一个带来源的当前状态承接；不必重复昨夜对白，不把每件小事都解释成旧事的后果。

写回实际发生的对话、选择及约定变化，不自动生成“陈禾冷漠”“林舟不负责任”或“蓝碗象征深厚感情”。

## 10 实现接口与迁移范围

在 `backend/internal/experience` 内集中实现上下文编译模块。其构造绑定当前 operation 的经历、分支、base revision、fence 和来源句柄，主要接口为：

```text
Prepare(stage, actor_id?, needs, budget) -> ContextBundle
```

调用方表达需要了解什么，模块负责权限、查询、来源核实、去重、粒度选择、容量和审计。模型不选择 audience。`ContextBundle` 返回材料、来源、粒度和需求覆盖情况，区分“尚不知道”“本次未查”“预算省略”“查询范围内没有记录”。

查询完整性只能针对明确查询范围声明。挑选出的相关材料不能标成整个历史完整。索引不存在不能证明事件没发生。

扩展现有 memory 阶段产出 `ContextNeeds`，复用既有调用批量预取。必要时允许当前阶段提出受限补查需求；actor 的补查由 Go 固定人物身份和知情范围。所有额外模型轮次和 DB 回取均受原操作总预算约束，预留后续写作和审稿资源，避免无限回忆循环。

优先沿用现有 PostgreSQL 和 sqlc，增加按人物、关系对象、版本、约定状态和来源的查询。初期可从现有 JSONB 资料定位；规模需要时增加可重建的派生索引表。索引设计依真实查询测量决定，不预设向量库是必要条件。

共享合同需要新增场景需求、阶段材料和受限补查语义，并同步 Go/Rust 类型、验证、所有合同快照与测试。当前 `NarrativeState` 作为兼容读取来源和过渡期投影，不再承担完整长期记忆仓库。历史原始记录保持不变。

旧档案回填只建立有来源的索引，不补造当时的内心或知情。没有安全片段来源的旧笔记暂供作者使用；actor 使用已验证事实。分支恢复和作者修改使派生缓存按来源版本失效，不能混入未来版本或另一分支的人物成长。

## 11 如何验证设计确实有帮助

先分开检测“找错了”“压坏了”和“材料正确但写坏了”。冻结前史、当前输入和 writer，比较：现有取材、人工选取的相关来源、系统选取的同预算来源，以及同一批来源的压缩版本。人工选材仅提供已有依据，不给期望台词或指定结局。保留全部输出，不选最好的一次。

工程验证覆盖来源、角色知情、分支与时间、预算、取消和索引滞后；可以用固定模型测试，但必须标明它们不验证文学质量。

文学对照至少包括：

1. 重要往事与当前输入没有关键词重合，仍能影响得体的提醒或帮助方式。
2. 相同请求由不同关系的人提出，结果可以相同，但理解、说明量和表达有合理差异。
3. 强烈但无关的旧事不自动触发伤感和闪回；真正相关时也不完全失去连续性。
4. 后来的守约或伤害改变旧关系，人物既能成长，也不突然彻底换人格。
5. 压力退去后不继续讲昨天的工作规程；幽默和习惯不变成每轮表演配额。
6. 同一往事的不同知情范围产生不同理解；合法揭露后允许怀疑、尴尬或暂不回应。

评审分别指出材料取回是否必要、是否自然影响当前场景、是否被不必要地说出口。去掉名字后的角色辨认只是辅助，夸张口头禅也可能提高辨认率。最终需要隐藏方案版本的连续阅读判断，模型审稿不能替代真实读者结果。

对照预先区分“应当相关、可能相关、无关”的来源，再做保留、删除和交换历史的配对测试。加入不需要产生差异的负对照：不同过去可以得到同样合理的当前反应，重要记忆也未必在每次互动中起决定作用。评审不奖励为了证明记忆有效而强行增加差异、帮助、回忆或情绪。

同时测量实际输入/输出字节或可验证 token、DB 查询数量与耗时、模型调用数、关键材料遗漏、索引延迟和读者等待。不能靠更多调用和更长上下文取得改进后，宣称有限预算设计已成功。

## 12 实施次序

第一步建立取材审计和固定回放，准确看到人物、关系、约定在什么阶段缺失。第二步让场景需求从完整数据库定点取回安全事实，先解决稳定人物依据随容量增长消失。第三步增加有来源的经历、对白片段和局部更新的文学索引，替换整本笔记重写。第四步完成按阶段装包、受限补查和审稿独立取证，在相同预算下做真实连续故事对照。

这些步骤在同一份记忆架构下实施，不建立客户端第二套 Agent 或独立世界事实。是否进一步采用语义向量、额外反思阶段或更复杂人物模型，应由上述失败样例和测量决定。
