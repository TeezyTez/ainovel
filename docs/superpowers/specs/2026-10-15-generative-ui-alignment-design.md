# 智能交互综合对齐架构设计

日期：2026-10-15。状态：用户已批准，并授权制定计划后连续实施、测试和修复，无需逐阶段确认。

用户要求直接对比 ChatGPT、Claude 等前沿产品，并彻底优化技术栈；已明确选择“生成效果、持续修改、速度和稳定性都升级”。交付目标是让玩家用自然语言得到有用的交互工具，能够连续修改、保留参数、恢复版本，并看见真实生成进度。小说的公开视角、分支和正式结算继续作为产品约束。

## 1 对齐对象与事实基础

对齐可观察的产品能力及公开开发协议。没有公开证据能还原 ChatGPT 或 Claude 的完整内部技术栈。React、AI SDK、esbuild 是本项目的工程选择，不能称为两家公司的同款内部架构。

| 维度 | 官方公开能力 | 当前项目 | 要达到的行为 |
| --- | --- | --- | --- |
| 自动出现 | ChatGPT Visualizations 根据用途呈现可交互解释 | 已有每场景自动 prepare 和 none/keep 决策 | 理解比较、推演、筛选需求；安静阅读维持文字 |
| 自然修改 | ChatGPT 支持继续修改预览内容；Claude 支持对话中迭代 artifact | 有少量续改正则，但常见措辞仍漏掉 | “这个颜色太淡了”“保留数量改成按人分配”指向当前界面 |
| 表达能力 | ChatGPT 支持 HTML、React、SVG、Mermaid、Vega 等预览；Claude 支持交互工具、设计和仪表盘 | 标准 JSON 组件与无依赖 HTML/CSS/JS iframe | 保留快速标准组件，增加受控 React/TSX 渲染器和设计组件 |
| 连续性 | ChatGPT 保存可编辑块并在后续使用最新版本；Claude 提供可继续编辑的 artifact 和部分计划下的跨会话存储 | 定义 digest 与故事版本共同标识状态，已有 initialState 恢复，但没有独立作品版本历史 | 稳定作品身份、修改历史、状态迁移、撤销与失败回退 |
| 生成反馈 | OpenAI API 和 AI SDK 公开协议支持事件/内容流 | 剧情已有阶段 NDJSON；智能 UI prepare 仍整包返回，底层模型内容未流式接入 | 工作区收到真实阶段；适配器支持时显示内容增量；旧界面继续可读 |
| 质量闭环 | 官方产品提供预览、修改和错误修复入口 | 有语法检查、运行错误回传和独立浏览器脚本，生产链路不验证控件任务效果 | 候选运行检查与任务断言，错误反馈精确到版本，失败不覆盖可用成品 |

## 2 当前代码的真实差距

1. `src/rich-request.js` 用正则决定展示请求是否离开剧情流程。“只显示北路和南路”能识别，“这个配色太淡了，帮我调深一点”“这张图的文字再大一点”“图里只保留时间和来源两列”尚不能可靠识别。这是任务路由问题。
2. `src/server-dynamic.mjs` 的上下文主要来自开场、最近三轮、当前公开状态和同范围 pending。跨回合的既有界面只提供简短元信息，缺少可寻址的完整作品历史。
3. 生成协议只有 `{payload:string}` 外壳，内层格式依赖事后检查；模型通常返回完整定义，没有受版本约束的局部补丁。
4. `src/interactive-runtime.js` 按故事、分支、状态版本与定义 digest 保存局部状态。现有 initialState 和 iframe 保留修复已改善连续性；服务端还有同 scope 最近 16 份契约目录、回合界面快照，客户端还有字段草稿历史。缺少的是长期 artifact ID、显式状态 schema、父版本和用户可操作的修订历史，不能说“完全没有历史”。
5. 新代码运行检查主要是脚本语法、可见内容、控件数量、宽度和运行报错。存在按钮不代表按钮完成任务，算式有输出也不代表计算正确。
6. `src/dynamic-ui.js` 与 `src/app.js` 混合 HTML 字符串、DOM 重绑、请求生命周期和草稿同步。工作区重渲染与 iframe 生命周期耦合，复杂交互难以稳定扩展。
7. 目前模型调用指标的 `usage` 为 null，缺少首次反馈、编译、检查、首个可用界面及修订成功率的统一轨迹。

检查期间共享工作区已有其他改动：最新 `needsRuleReview` 只为新增或改变的正式 rule 契约进行模型审核，纯展示和相同规则的呈现变化不再普遍增加 judge 调用；prepare 推理配置默认 low。后续不能再以“每张界面都调用两次模型”设计优化。

历史日志中，同一合成场景首次交互用时 44.451 秒，修订用时 81.910 秒，后者包含一次审核拒绝和重生成；这些是旧源码快照的单次观测，不是当前速度基线或 p95。本轮最后重跑 120 项相关自动测试，全部通过，受检源文件前后指纹一致；这只验证现有回归范围，不证明生成体验与竞品相同。

本机证据：`test-results/frontier-alignment-baseline-2026-10-15.log`、`test-results/frontier-alignment-source-snapshot-2026-10-15.json`、`test-results/interactive-live-2026-10-15T03-51-43.458Z/manifest.json`。这些文件在 Git 忽略目录中。

## 3 方案选择

| 方案 | 收益 | 代价与结论 |
| --- | --- | --- |
| 重建智能交互核心，分阶段迁移阅读工作区 | 同时解决语义、作品生命周期、运行能力和质量评估；继续使用已有模型连接和小说账本 | 推荐。需要引入构建与类型系统，但每阶段可验证、可回退 |
| 全站切换 Next.js、云数据库和云沙箱 | 适合明确需要账号、多租户、云协作与部署的产品 | 这些需求尚未建立；一次改动首页、数据、部署与模型接入，难以分辨质量收益来源 |
| 继续增加正则与现有 HTML 渲染分支 | 短期改动小 | 无法补齐稳定作品身份、版本编辑和生成验证，不满足此次综合升级目标 |

“彻底优化”落实为替换智能交互的关键协议和生命周期；迁移采用可验证步骤，不让全站重写成为使用新能力的前提。

## 4 技术栈与职责

| 层 | 目标选择 | 解决的问题 |
| --- | --- | --- |
| 阅读与交互工作区 | React、TypeScript、Vite；复用现有字体、颜色和阅读设置 | 用稳定组件身份、明确状态归属和错误边界管理复杂界面 |
| 协议 | Zod 与 TypeScript 判别联合；版本化 wire schema | 请求、生成结果、补丁、事件及存档共用验证；减少字符串 JSON 的歧义 |
| 模型接入 | `ModelGateway`；保留 Codex 适配器，API 路径采用 AI SDK Core | 统一取消、能力声明、流事件、usage 和错误；不强迫用户重新购买或配置模型 |
| 工作流 | 显式 Job 状态机和类型化 SSE 事件；兼容现有 NDJSON 剧情接口 | 生成、构建、检查、修复、取消及最终提交可追踪 |
| 作品存储 | `ArtifactStore`，不可变修订与原子 head 更新；先使用现有本地持久化基础 | 版本历史、续改、撤销、状态迁移；不为 UI 改造立即迁移正式账本数据库 |
| 生成界面 | 标准组件、旧 HTML 沙箱、受控 React/TSX 三种 renderer | 简单任务快速显示；复杂交互可以使用稳定的组件与依赖 |
| 构建 | esbuild 的虚拟文件构建和依赖白名单 | 编译 TSX、精确诊断、禁止读取任意宿主路径和任意联网安装 |
| 运行检查 | Playwright 的独立检查进程，运行时错误遥测 | 检查真正渲染与控件反馈；独立进程超时结束卡死候选 |
| 回归与评估 | 继续使用 Node 测试；增加类型检查、工作区组件测试和浏览器任务集 | 验证协议、故事不变、局部状态、移动端与任务成功率 |

React 官方支持在现有项目中逐步引入组件，并提供 Vite 接入路径：[官方说明](https://react.dev/learn/add-react-to-an-existing-project)。流协议参考 [AI SDK UIMessage Stream](https://ai-sdk.dev/docs/ai-sdk-ui/stream-protocol)；构建能力参考 [esbuild API](https://esbuild.github.io/api/)。依赖在实施时按兼容矩阵选定并锁定确切版本，不用运行时 CDN 或每次生成时安装依赖。

不需要为了对齐增加 Next.js、Redis、向量数据库或微服务。当前瓶颈证据指向生成与界面生命周期，尚未指向 HTTP 路由吞吐或关系数据库性能。

## 5 核心模块

### InteractionCoordinator

外部接口是 `run(request, signal): AsyncIterable<InteractionEvent>`，请求携带 owner/session/branch、当前 storyVersion、requestId、用户输入和可选 artifactId/revision。内部选择查看、创建、修改、继续故事或需要澄清的路径。

保留确定性本地查询作为快速路径；其余自然措辞交给带 schema 的语义决策。模型只返回意图、目标 artifact 和请求参数，正式动作仍由现有行动处理器验证。纯界面修改不进入剧情；混合“修改图，再出发”分别保存界面请求与行动申请，不能把展示需求丢弃或把尚未提交的操作执行。

对明确的创建/修改请求，将意图与第一份方案合并在一次模型调用中；自动场景判断尽量复用已有叙事记录阶段的展示建议。避免给每次操作固定增加独立分类调用。无法确定指代时定位当前活动作品，确实有多个同等候选时才要求用户选择。

### ModelGateway

统一 `run({task, messages, schema, signal, onEvent})`，提供 `capabilities`，如 contentDelta、structuredOutput、usage、resume。Codex 保留当前登录与隔离调用，能实际提供什么事件就展示什么事件；不能把进程开始或最终文本拆字伪装成 token 流。API 适配器支持真实增量时再输出 delta。

区分模型生成耗时、前置排队和本地检查耗时。模型名称不在此次设计中擅自更换；对比模型配置必须作为独立实验变量记录。

### ArtifactStore

作品身份使用稳定 `artifactId`，与内容 digest 分离。修订包含 revisionId、parentRevisionId、内容 hash、sourceFiles 或标准组件定义、依赖版本、公开数据引用、stateSchemaVersion、状态迁移描述、来源故事版本、检查结果和更新时间。

局部输入状态另存，由 stateRevision 进行并发校验。状态恢复优先级是同修订已保存状态、通过 schema 的迁移结果、新修订初值。迁移只允许声明的键映射、保留和默认值，不执行任意模型提供的迁移代码。`0`、false、null 和空数组不当成缺失值。

采用 `get / listRevisions / commitCandidate(expectedHead, expectedStateRevision) / restore / saveState(expectedStateRevision)` 接口。修订先写不可变内容，校验完成后将 head、迁移后状态、分支作品指针和该请求的最终结果索引放入同一个原子更新的 manifest；无效候选不成为当前版本。若生成期间玩家继续改参数，状态版本冲突时重新迁移最新参数或拒绝提交，不能覆盖。展示回滚不回放故事 operation，不回滚世界状态。

作品可以跨剧情回合保留，但其公开数据绑定有版本；旧数据明确标识并重新取数。只有使用当前 storyVersion 的行动契约可以提交。切换小说分支产生独立作品指针和状态副本，旧分支消息不能影响当前分支。

本地 UI 缓存继续保留未同步编辑；共享的已确认 UI 状态由服务端持久化以便同一故事恢复。UI 状态始终不写入正式事实、库存或行动授权。存储位置与小说账本分开，使用相同 owner/session/branch 隔离。导出增加可选的作品修订与局部状态字段，导入时按 schema 验证并创建新的作品命名空间；旧格式继续可读，不能依赖未包含在导出中的独立 localStorage 键。

### ArtifactEditor

生成支持三类结果：沿用/不展示、完整新修订、基于 `baseRevision` 和内容 hash 的补丁。模型只能修改虚拟文件或可寻址组件节点。补丁前置条件失败时返回冲突，不猜测套用位置。

首先将筛选、排序、字体、主题等操作表达为现有组件属性或状态变化，减少代码重生成。需要改变逻辑时提交可审阅候选，保留未触及的参数与内容。一次修改失败后旧版仍可用，可选择重试或回到历史版本。

### ArtifactRenderer 与 RuntimeBridge

标准组件直接用 React 渲染；旧 HTML/CSS/JS 通过兼容渲染器保留；复杂新交互支持受控 TSX。生成器获得一致的排版、颜色、布局、图表、滑块、表单与空状态组件，不必每次从零写整套样式。

可运行代码留在 opaque iframe 与 CSP 限制内，不在宿主 React 树执行。依赖只能由构建器解析到随应用发布的白名单包，禁止任意路径、动态导入和联网安装。消息核对实例、来源、修订与 scope。

桥接仅提供公开数据快照、局部状态、草稿、调整显示尺寸和用户请求重新编辑等能力；正式执行仍经宿主行动入口。生成中的代码不执行；完整候选构建并通过检查后替换 iframe。父级 React 更新不改变未变化作品的 iframe 身份。

### ArtifactVerifier

检查分层：schema 与数据引用校验；构建/语法；候选运行；业务结算。标准组件走确定性验证，不为每张表启动浏览器。

生成代码候选在独立浏览器进程中快速启动并检查可见内容、错误、布局和代表性控件。全面多视口、键盘和连续修改验证放在回归任务集，避免把全部 QA 时间加入每次生成。卡死候选由进程级超时终止，不能只依靠同线程 JavaScript 定时器。

检查器接收宿主提供的验收任务，例如修改数量后剩余值同步、草稿按钮不改变回合；不直接执行模型任意编写的宿主测试代码。失败报告包含 revision、阶段、错误位置与可公开展示的诊断，最多进行一次自动修复，然后显示手动恢复入口。

正式 rule 继续沿用最新代码的契约审核缓存与服务器重放；纯展示不重新增加整份模型审核。对只读数据的可靠性使用绑定到公开来源的数值/标签、公式核对与任务评估；任意自由文本仍需标明来源或未知，不能因省去 judge 而宣称语义完全验证。

## 6 用户体验与事件

桌面阅读区保持正文为主。简单图表在相关正文附近呈现；复杂工具可以展开到侧边工作区，顶部显示具体任务、版本、返回阅读和恢复入口。手机上使用同一作品的全宽展开视图，保留返回位置和草稿。无需先让玩家选择图表类型。

任务状态为 queued、understanding、generating、building、checking、repairing、ready、failed、cancelled。界面只显示真实发生的阶段，不显示虚构百分比。轻量字段调整立即反馈；请求新修订时旧作品保持可见，明确正在更新。

事件 envelope 含 protocolVersion、jobId、requestId、sequence、artifactId、revisionId 和 timestamp，数据类型包含 status、textDelta、artifactCandidate、validationResult、artifactCommitted、error。所有与权威状态相关的最终结果只能来自 committed。

恢复连接通过 jobId 与最后 sequence 补取已持久化事件；已提交请求重复读取同一结果。请求索引保存 requestId、规范化请求指纹、最终 revision 和事件终止序号；同 ID 不同输入拒绝。最终 committed 事件由原子 manifest 中的结果与序号重建，即使进程在 head 更新后、事件发送前退出，也能恢复同一结果而不重复生成。

同 owner/session/branch/artifact 的新编辑作业主动 abort 旧作业，限制在途数量；不能仅等模型返回后发现结果过期。取消在原子提交点之前生效，此后返回已提交结果并允许用户恢复旧版。切换分支停止订阅并拒绝旧 scope 事件。原有 NDJSON 剧情接口通过适配器兼容，不一次改变全部调用方。

## 7 迁移阶段与完成条件

1. 固定基线、共享协议与 ArtifactStore：保存当前源码指纹和任务集；建立作品 ID、修订与状态隔离；旧存档按需映射为第一个只读或可续改版本，不批量改写用户文件。
2. ModelGateway 与任务流：现有 Codex 和兼容 API 均能使用；加入 prepare 真实阶段、取消、恢复和时序指标；对不支持内容增量的适配器明确能力限制。
3. 语义路由和修订：通过自然措辞、对白与混合输入用例；完成局部修改、三轮参数保持、撤销与分支隔离。
4. React/TypeScript 工作区与 renderer：从独立挂载的交互区开始替换 DOM 拼接；支持受控 TSX 构建和隔离开发预览，同时保持旧组件、阅读设置和存档可用。完成下一阶段之前，TSX 候选不能成为玩家的已提交成品。
5. 候选运行检查与修复：接入真实浏览器检查、错误归因和旧版回退后开放 TSX 成品提交；完成手机、键盘和故障注入回归。
6. 同题对比与默认切换：运行新旧系统同配置任务集；取得账号可用的 ChatGPT/Claude 同题成品后再进行产品级盲评。达到门槛才切换默认路径并移除被替代实现。

上述是架构迁移顺序，不是已完成的实现清单。每阶段产出可运行切片，新增路径用一个明确配置开关控制；不能同时维护两套互相写入的正式故事状态。

| 目标 | 测量方式与门槛 |

| 正确路由 | 固定自动测试中的展示/对白/否定/剧情样例全部符合预期；额外至少 100 条未参与调试的自然措辞集，展示精确率与召回率均 ≥95%；测试集误推进剧情为 0 |
| 生成任务完成 | 20 类基础任务重复至少 5 次，报告首次成功与一次修复后成功；目标首次 ≥90%、修复后 ≥95%，逐类列失败 |
| 续改保留 | 至少 10 组、每组 3 次连续修改；明确未要求改变的参数、单位和选项全部保留，失败不能静默重置 |
| 速度 | 本地任务接受反馈 p95 <300ms；本地控件响应 p95 <100ms；简单续改最终就绪时间相对同模型新基线 p50 至少降低 30%，p95 不回退；新作品 p50/p95 不回退，任务成功率不能因提速下降 |
| 可见进度 | 真实阶段开始后及时发送事件；没有内容流的适配器不产生伪造 token；所有耗时阶段可归因 |
| 可靠性 | 超时、网络中断、刷新、重复请求和切分支回归无跨作品覆盖、无重复结算、无草稿丢失 |
| 视觉与易用性 | 390、768、1280px 无页面水平溢出或关键控件遮挡；键盘能完成主要任务；至少两位评审按固定 1–5 分标准盲评任务清晰度、层级、反馈与准确性，各项平均 ≥4，且无任务阻断缺陷 |
| 小说约束 | 查看、筛选、试算、修改、撤销不会改变故事回合/库存；正式行动仍由当前 scope 契约提交 |

阶段 1 在改造前冻结样本、阈值和计时规则；如新基线说明某项门槛不可实现，应在实施前修订并记录理由，不在得知结果后放宽。跨产品展示题与游戏专属题分别统计，20 类中不能适用某产品的题不算该产品失败。

比较 ChatGPT、Claude 时记录产品、模型显示名、日期、计划、实际工具模式、网络、输入和生成成品。API 测试不冒充网页产品测试。模型错误、构建错误、任务理解错误和运行时错误分别统计。所有计划运行均进入结果清单；失败与超时计入成功率分母，可用耗时分布标明只统计成功样本并同时公布超时/失败率；主动取消独列，不将其伪装成更快完成。完整计时与样例由验收集固定。

## 9 审阅重点

建议采用“重建智能交互核心，逐步迁移阅读工作区”：引入 React、TypeScript、Vite、共享 schema、模型适配与事件流、作品版本管理和候选运行验证；保留现有模型登录方式及正式小说账本。源代码、包版本与迁移任务将在书面方案确认后细化为实现计划。

这一选择将改变智能交互的协议、数据模型、构建方式和主要前端生命周期。批准该架构后，可以在同一工作区按迁移阶段实现；现有未提交改动须先核对归属，任何全量替换都不得丢弃它们。
