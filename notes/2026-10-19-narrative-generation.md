# 叙事生成改造与验证记录（2026-10-19）

已按用户提供的《ElseLife 叙事生成改造方案》完成本轮源码改造。沿用 Flutter → Go → Rust → 模型 → Go 的正式链路，未新增第二套世界状态、数据库表、共享协议版本或客户端 Agent。改动位于本地分支 `codex/narrative-generation-2026-10-19`，尚未提交或推送；首次交付时未重启正在运行的 Go/Rust 服务。

后续用户提出亲自测试：确认没有 pending/generating 故事后，重新构建并仅对已核验的 Go/Rust 进程发送正常终止信号，再用现有启动器启动新版。18080 页面、18081 Go、18083 Rust 均通过身份/当前二进制检查，现可在 `http://127.0.0.1:18080/` 本机自测。未清空、导入或重建故事库；这次本机切换不代表公网发布。

本轮实现补强了记忆记录、人物与剧情生成约束、资料恢复及阅读准备调度。**真实样本显示结构化记忆留存增加，同时整页生成等待变长；不能宣称质量与速度均已获得验收。**

## 生成链路的具体变化

- 原本完整 `NARRATIVE_PROMPT` 未进入当前模型调用；现在改动的是实际使用的 `RESPONSE_PROMPT`，版本为 `elselife.narrative.v3`。
- 模型输入新增 `authoring.narrative_brief`，它是最多 8 KiB 的当前证据 ID 导航，包含来源版本、客观记录/人物说法的区分、未解决线索、知情关系与偏好来源。它从当前分支冻结视图派生，不储存第二份事实；历史回取仍保留原坐标。ask 先进行读者权限投影。
- 紧凑输出 schema 开放已有的 `ReadRequest`，复用来源句柄、完整原文回取与有限调用预算；没有重新接入旧 task/workflow。
- 可选资料失败不再一律清空其他资料。最多检查三类新增字段的七种组合，保留完整验证通过的独立字段；真实依赖必须一起通过。公开、线索解决、人物知情和玩法更新分别进行累计验证。不会删除字段内的某个坏记录来猜修对象，也不会篡改 ID 或来源。
- Go 对字段形状恢复与完整权威语义验证分工明确；缺失/非字符串故事时间保留旧时刻；受信的本地 `NarrativeOnly` 标记不会误执行绑定玩法。
- 复审发现旧 8192 字节容量预留不足，现按 Rust 内容开销上限 32768、schema 上限 9000、动态 protobuf 封装及作者附件保守计入。Go 与 Rust 上限有直接一致性测试，且以真实 Rust 请求验证近满窗口。代价是可装入的正文更少；旧整页可裁剪，必要状态或最新整页放不下时明确失败，不偷偷截断或虚构。

## 真实连续阅读对比

完整正文见 [连续阅读样本](2026-10-19-narrative-reading-samples.md)。输入场景见 [continuous-reading.json](../backend/internal/experience/testdata/narrative/continuous-reading.json)。该场景为人工编写的虚构测试输入，不是用户经历；样本文字由真实模型生成。

测试使用本机已配置的 `gpt-6.1-sol`、现有 Codex CLI 适配器和临时隔离 PostgreSQL。两组开局、行动序列相同，每组连续五轮，每轮一次模型调用，没有失败后反复生成到满意。baseline 冻结 Git `f0f1648b78eda01a92d902f531a305f3251076b7` 的旧提示词、旧紧凑 schema，并移除新导航；两组共用本轮后端与验证器，**这不是完整旧二进制与新二进制的对照**。

| 指标 | 旧提示词对照 | 初版 v3 |
| --- | ---: | ---: |
| 正式提交轮数 | 5 | 5 |
| 总模型调用 | 5 | 5 |
| 平均完整可读页等待 | 15.758 秒 | 21.121 秒 |
| 中位完整可读页等待 | 15.646 秒 | 20.489 秒 |
| 最后一页累计事实 | 0 | 13 |
| 最后一页累计实体 / 线索 | 0 / 0 | 7 / 2 |

这里的等待是 `GenerateAccepted` 到正式页读取返回，包含模型、校验及持久化；不是首 token、首段或单独的数据库提交耗时。一次样本中平均等待增加约 **34%**。模型上游波动、生成长度和同机工程检查都可能影响时间，不能当作受控性能基准。

两组短篇正文都保持了戒指归属和同伴独立性，不能声称这些能力在旧版完全缺失。新版额外把交付、拒绝、角色说法和来源持续留在状态中，可供后续上下文选取与回取。旧事实保留为历史，新转移追加在后；并非删除旧的“玩家持有账册”记录。

初版新版第五轮较保守，重复守卫拒绝与等待。最后增加的通用提示要求 read 在不替玩家决定的前提下，让环境、NPC 目标或已有后果继续发展。用最终运行时、相同第 4 页状态及空 read 输入额外生成一次候选后，守卫允许玩家在其在场时询问工人，同时保留不能查簿、不能碰货的限制。该候选约 20.901 秒，无数据库提交；原失败倾向样本保留，没有替换到五轮指标中。它仍偏保守，不等于伏笔回收或高潮节奏获得验收。

另从已保存的两组第五页进行 ask：询问未揭示的账册姓名及守卫知情。最终探针各调用一次，模型/验证返回后状态与时刻完全相同；两组都拒绝凭空列出未公开名单。该探针是只读候选，不生成正式页，耗时与上表测量边界不同。

首次 ask 探针的报告字段曾漏填状态（实际不变式断言通过）；修正报告写入后重新执行，两次文本都保留在本机 `.validation/narrative-evaluation/`。样本文件明确区分这两个记录，不以重测文本冒充唯一输出。

## 复跑

先使用后端 README 中的本机模型配置，并构建当前 Rust runtime。需要显式设置 `ELSELIFE_TEST_RUST_RUNTIME` 和 `ELSELIFE_NARRATIVE_EVAL_DIR`（独立的本机输出目录），以及已有的 `ELSELIFE_DEV_CODEX_CLI_PATH`、`ELSELIFE_DEV_CODEX_AUTH_HOME`、`ELSELIFE_DEV_CODEX_MODEL`、`ELSELIFE_DEV_CODEX_TEMP_DIR`，代理按本机需要设置。不得把认证内容填进命令或源码。以下命令会实际调用模型并消耗当前授权额度。

在 `backend` 目录执行：

```sh
go test -count=1 -timeout=20m -tags=integration,codexlive -run '^TestNarrativeQualityComparisonLive$' -v ./internal/experience
go test -count=1 -timeout=10m -tags=integration,codexlive -run '^TestNarrative(UnknownQuestion|RefinedContinuation)Live$' -v ./internal/experience
```

没有显式配置时这些测试跳过；普通测试不会发真实模型请求。后续探针读取同目录已保存的合成对比，不需要重新生成前五轮。再次运行主对比会在指定目录写新的报告，应为每次评价使用新目录，以保留不理想样本。

后续仍需目标读者对连续章节进行盲评、更长分支中的秘密传播与真实选择代价测试、真实首段/阅读中断指标及并发负载测量。当前没有证据支持专项训练、后台摘要或流式正式发布已完成；速度目标仍未达到。
