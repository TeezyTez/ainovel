# NAR-009 第七步容量失败：重现与修复

原始证据：`.validation/deep-benchmark/20261019T092722Z/NAR-009/events.jsonl`。S01–S06 共提交六个真实模型生成段落；S07 在模型调用前报 `context_capacity`，没有生成或提交新正文。这个记录不能算完整 NAR-009 通过。

## 根因

64 KiB 模型窗口减去 8 KiB 输出、36 KiB 各流水线阶段附加内容上界、4 KiB schema 和真实 transport 开销后，本次只剩 15,522 字节可用于冻结 Context。revision 7 的权威 State 已达 14,609 字节，包含 35 条事实和 5,008 字节笔记；再放入最新完整正文、输入及范围信息就超限。

原先 `RecentRevisions=16` 把最近十六版的所有变化当作不可省略根节点。短故事只过六轮就包含全部历史事实，删除旧正文无法释放这部分空间。错误发生在 Go 生成视图编译阶段，不是模型输出过长，也不是前端等待超时。

## 改动

`Service.buildGeneration` 先保留原来的首选最近窗口；超限时，使用真实不可变快照逐版收窄窗口，选择能够放入容量的最早完整版本边界。规则、secret 类型事实、未结束线索、输入明确引用的对象及其依赖、最新版本事实、完整笔记和最新完整页仍然必须保留。单条事实和正文不截断，模型窗口和预算不调大。

每次生成的 `recent_from_revision`、精确 omitted counts 和 scoped source handle 一并冻结。延后加载的事实仍存在 Go 完整提交权威中，可以使用原有同操作/同分支/同版本 read capability 按原字回取。正式页、快照、事实 ID 与 `known_by` 不改写。

## 已验证范围

新增的 `TestRecordedSixTurnNarrativeFitsAndRetainsPinnedAuthority` 使用仅含合成世界的真实运行记录建立独立 PostgreSQL 回放。测试先确认旧固定窗口仍然重现错误，再检验新编译：14,709 / 15,522 字节、最近边界为 revision 3、保留 27 / 35 条事实、完整 5,008 字节笔记和最新一页。

回归同时检查：延后事实可以按原字及原 `known_by` 回取；省略 ID 不能被新事实冒充；七个正式快照均未变化。真实 Rust transport 配合明确标为固定结构模型的六阶段执行也通过；该测试证明请求可通过实际容量门禁和完整 Apply，不评价生成文学质量。

该修复不承诺无限容量。必须保留的规则/依赖/笔记/最新页本身超限时仍明确失败。较早普通事实可能延后加载，模型是否正确请求所需旧证据、最终故事是否违背早期事实，仍须真实长程轨迹评审。原始失败证据保留，后续真实模型重跑必须另建记录目录。
