# 来源受限的知识传播：最小机制原型设计

2026-10-20。仅阅读产品代码和既有封存证据；本文没有实现协议、运行模型或修改正式状态。目标是检验一个有限改变是否减少部分告知带来的越界知情，同时保留正常交流和人物利用信息的能力。不能据此宣称自然语言蕴含已被解决。

## 1. 起点与关键限制

NAR-017 S04 的已知缺陷是：于砚听到 14:30 约谈，却获得包含封箱、挪箱的整条 `lu-appointment-r4`；听到《潮汐表》放回店里，却获得旧记录的 09:40 时间。原 candidate 已有准确的窄 `jy-report-r5` statement，两个旧 fact grant 并非保存交流所必需。原事件根、精确记录和先前知情见 [封存审读](../.validation/v47-reading-review/NAR-017-S04-knowledge-overgrant.json)。本文不修改该正式前缀，也不把后续成功当作抹去旧错误。

当前代码提供的能力：

| 代码 | 实际能力及限制 |
|---|---|
| [Fact / KnowledgeChange](../backend/internal/experience/types.go) | `Kind` 可为 fact/rule/secret/statement/belief；没有 observation 类型。`KnowledgeChange` 只有主体与目标 fact ID；给整条记录加 `known_by`，不表示子内容。 |
| [Apply](../backend/internal/experience/types.go#L354) | 新 fact 记录 `next_revision`；旧事实内容不变，知情边可追加。不能表达撤回已获得的信息；也不应把改信理解为失忆。 |
| [审稿支持校验](../backend/internal/experience/narrative_pipeline.go#L74) | 绑定同一 candidate，检查所有边都有唯一支持项、quote 原字存在。没有验证引文蕴含目标全部内容。 |
| [actorProjection](../backend/internal/experience/narrative_pipeline.go#L291) | 从完整 authority 确认 `known_by`，只返回已经 materialized 的事实。返回的是所有满足这两项的事实，不只是 trigger 的 fact IDs；保留 kind、subject_id、source_revision，移除其他人的知情名单和 Reader 数据。 |
| [人物笔记校验](../backend/internal/experience/narrative_state.go#L135) | `belief_fact_ids` 只接受本人的 statement/belief。听者不应把说话者的 statement 塞进自己的这个槽位，也不需要这样才能使用它。 |
| [生成视图](../backend/internal/experience/generation_view.go#L96) | 新近记录、变化记录等进入工作集；旧材料可能省略。显式提到听者，不会自动装入他曾听过的全部 statement——这样做本来也会造成历史膨胀。 |

因此第一步不需要新数据库或把全部旧事实拆开。可以继续用窄 statement 表示实际言语，用 fact 表示确实发生的观察事件，例如“乙打开了信，并读到了其中……”。但后者仍是自然语言记录，**不是程序签发的观察回执**。

现有 `source_revision` 是记录创建版本，不是获知版本、有效时间或信任评级。来源版本、人物已知集合和正文原字可以由程序取出；何人听清、说法真假、是否相信、是否完整覆盖仍可能需要语义判断。

## 2. 需要收紧的语义

### 2.1 接触、相信、事实为真是不同结果

同一场对话可以产生：

1. **交流记录成立**：甲确实向乙说了 P，乙实际接触到该说法。新增 statement 的 `subject_id=甲`，`known_by` 只含有来源的参与者。
2. **人物接受或怀疑**：乙如何理解 P。只有正文确有相应心理或行为依据时，才记录乙自己的 belief/statement；不为每条听闻自动制造一个 belief。
3. **世界 P 成立**：依权威世界与本段真实事件判断。不能仅因甲说了 P 就新增 `kind=fact` 的 P。

“完整告知”也需要区分：乙完整获得一段说法，可以合法扩充**该 statement** 的获知范围；这不自动把其内容转成客观事实或乙的信念。对旧世界 fact 授予 whole-record 知情，完整内容覆盖是必要条件，还需有支持人物实际获得这些信息的来源与语境；不能只因为作者知道该 fact 为真，就把听者的认识升级。可信报告也可以提供这种依据，不能把“独立核验过”设成统一必要条件。

这不要求普通对话都增加“核验—复述—确认”仪式。人物可以依关系、报告来源和当时处境，合理地相信完整报告、形成认识并采取普通行动，也可以询问或怀疑；不要求正文额外写一遍“我相信”，更不要求每次亲自检查。是否授予对应世界 fact ID 仍须与实际内容和人物认识相符。完整覆盖是内容范围约束，不是让所有听闻停下来核验的门槛；正常信息利用也不应被绑定为“先升级成真相才能继续”。

### 2.2 旧 fact grant 不能用窄陈述替换审查目标

对每个 `knowledge_changes(subject, fact_id)`，必须查看目标 **完整原 text**，而不是只读支持 quote。审查范围为：原目标、该主体此前实际可用的证据、本段新增接触，以及遗漏部分。

如果正文只支持某些内容，优先生成已有协议能承载的窄 statement/观察记录；不修改旧 text，不添加 whole-record grant。若目标内容全部获得，可保留合法 grant。原 `known_by` 已包含主体时不重复追加，不把再次提起误写为再次获知。

“部分”和“全部”不能按分号、关键词或句数硬拆。否定、时间、条件、归属、转述层级可能跨句；正文与先前证据也可能共同支持完整内容。程序没有一般能力证明这种蕴含。

## 3. 最小数据流与内部接口

先做不写世界的研究原型，再决定是否纳入正式阶段。保留当前 Candidate 和正式 Fact 合同；第一轮不增加 observation 枚举、不批量迁移旧 fact、不额外调用一个语义模型。

### 3.1 Go 构造被审查的边及原始证据

在 extract 之后、当前 review 之前，由 Go 为候选新增的所有获知边建立待审条目，包含：

- `knowledge_changes` 的旧事实边；
- `new_facts[*].known_by` 的全部新事实边，避免只检查旧 fact，却通过新 fact 文本复制隐藏内容绕过；
- 读者 reveal 仍走原有公开边界，不能与角色知情混用。

内部函数草图，不是已存在的 API：

```go
func BuildKnowledgeAudit(
    pin OperationPin,         // 分支、base revision、正式 source handle
    authority State,         // Go 持有，禁止整体转发给 actor
    candidate Candidate,     // 同一冻结正文与候选
) (KnowledgeAuditInput, error)

type KnowledgeAuditInput struct {
    CandidateSHA256 string
    Targets []KnowledgeAuditTarget
}

type KnowledgeAuditTarget struct {
    SubjectID string
    FactID string
    Target Fact              // 原目标完整值，不能由模型改写
    IsNewRecord bool
    WasKnownBefore bool
    PriorEvidence []Fact     // 仅该主体此前有权知道、且已具体选中的原记录
    CoverageComplete bool    // 仅描述此证据查询是否完整，不声称认知完整
}
```

`OperationPin` 表示复用现有操作绑定能力，不要求引入第二套业务身份。`CandidateSHA256` 由程序计算。目标从完整 authority 或本 candidate 原样取得；未知 ID、重复边、跨分支/未来引用、替换目标正文直接拒绝。

不能把全部旧知情历史塞进 `PriorEvidence`。原型复用该次 generation context/recalls 中实际 materialized、且由 authority 确认对该主体可见的原记录，不按评估标注挑出“正确答案证据”。已经在 context 中的原值可通过 ID 引用，避免再复制一遍；完整目标缺失时由同一 pin 原样补入并计费。产品化时必须复用有预算、同操作绑定的回取，缺证据应标未完成，而不是标“人物之前不知道”。该检索策略本身是待测问题。

这份审核输入只给世界审核阶段；actor 仍用现有受限投影。其大小要计入实际阶段容量，不能以“只是 audit”绕过上限。

### 3.2 在现有 review 中显式报告判断，而非另开一轮审稿

现有支持项只有 subject/fact/quote。研究原型可用一个内部、版本化结果扩展：

```text
KnowledgeAuditDecision {
  subject_id, fact_id,
  source_mode: observed | heard_statement | read_record | inferred | undetermined,
  evidence_spans: [{start_utf8, end_utf8}],  // 指向本次冻结 passage
  prior_evidence_ids: [...],                // 仅引用所提供原记录
  target_scope: full | partial | unsupported | undetermined,
  uncovered_content: "...",                 // 审查意见，不写入世界
  reason: "..."
}
```

`target_scope` 判断的是对目标记录内容的新增获知是否成立，不是声明自然语言证明已经完成。`source_mode`、人物是否听见、理解和接受也属于模型提议；程序不因枚举合法就相信它们。

不引入 `accepted_belief=true` 自动生成信念。若本段确有信念变化，应在正常 Candidate 中明确表达并独立受检；拒绝/怀疑本身不改变另一个 statement 发生过的历史。

程序可确认：条目覆盖与目标一一对应；引用 ID 在所给主体证据内；UTF-8 范围合法且原字匹配；候选、pin、目标值未变化；输出预算和共享修复次数未超限。**这些检查不能确认 `full` 判断正确。**

为避免无意改变协议，第一轮可把这份结果只存为研究 sidecar。若后来进入生产，需要同步 Go/Rust 的 review schema、状态机和容量测试；不能让某端把它当装饰日志、另一端当审批依据。

### 3.3 不在审批后偷偷删 grant 或修成“通过”

影子原型只记录 `would_reject/would_allow/undetermined`。它不改候选，不签发正式页。

产品实验臂中，extract 应直接输出范围正确的 Candidate；review 若发现 partial/unsupported 的整条 grant，应拒绝原候选，沿现有共享一次修复规则处理或停止。不得批准后程序悄悄删边，也不得通过 normalize、补造 statement 或新增重试使结果变绿。修复候选必须重新经过完整同候选审批。

最终 Go 提交仍将正文、实际世界变化和本段关键获知同步写入一个正式版本。不能把获知写入后台摘要后再迟迟影响下一场人物。

## 4. 这是否只是把问题搬到另一次 LLM？

如果实施仅仅是增加一个“是否完全蕴含”的 LLM 调用，答案是**是**：同模型可能重复原误判，还增加等待。上述接口的价值只能来自可验证的职责变化：

1. Go 原样提供被授予的完整内容和先前权限，不让模型自己回忆、概括或换掉审查目标。
2. 候选默认使用已有的窄交流记录；需要传播的对象更接近实际接触范围，减少不必要的 whole-record grant。
3. 审查意见暴露“哪些内容没有来源”，使独立复核能定位误判；程序对错 ID、错 pin、假 quote、跨主体证据给出确定性阻断。
4. 使用原来的 review 调用比较效果，明确测量仍会发生的 `full` 误判和合法传播漏记。

第 1、3 项有确定性部分；第 2、4 项涉及模型行为，未获实验支持。明确记录来源可以缩小错误面，**不能把自然语言蕴含升级为程序定理**。

暂不建议让模型把所有旧事实自动拆成命题，再给每个命题打已知标签。那会新增语义抽取、指代、否定和联合推理错误；也可能把“甲或乙拿了钥匙”拆成两个假事实。原型应先证明同一窄任务中 structured audit 比简单原流程有用。

## 5. 六类最小反例与正控制

以下是研究夹具的语义规格，不是生产词表或每题固定结局。具体名字、对象、时间、否定和表达方式应轮换；不得要求人物必须采取指定行动来得分。

| 类别 | 最小设定与实际正文 | 可以成立的更新 | 必须拒绝或保留未知的更新 | 下一场要观察什么 |
|---|---|---|---|---|
| 合法完整告知 | 旧 statement 是“甲称自己封箱并挪到门内”；乙原未听过，本段明确听完整段。正控制分别包含：乙按既有可信关系接受报告；乙亲自完整查看对应记录/现场 | 乙获得完整 statement；若来源、语境与实际认识支持，可合法形成认识并授予相应旧 fact whole grant，不要求可信报告再经独立核验 | 仅因听见就自动新增“乙相信”、或把此前未定的世界事实写真；反过来因未亲自检查就一律拒绝 | 乙可根据可信报告或实际观察自然继续；不能以“仍需核验”为由永远禁止普通后续 |
| 部分告知 | 旧 fact 同时含封箱、挪箱、14:30 约谈；本段只告知约谈 | 新窄 statement，或既有同一窄 statement 的合法新增听者 | 把封箱、挪箱或旧精确时间送入乙的 actor 输入；改旧 fact 为窄 text | 乙能围绕约谈回应，同时不会无来源谈到箱子 |
| 撒谎 | 世界钥匙在蓝盒；甲对乙说在红盒；乙听见，未交代是否相信 | 保存甲的陈述与乙的接触；允许后续怀疑、相信或调查，但须由实际场景承接 | 把世界钥匙改到红盒；因为作者知道蓝盒就把蓝盒秘密送给乙；自动添加乙相信/不信 | 乙的反应能基于所听说法及自身旧证据，而非作者真相 |
| 亲眼看见 | 乙看到甲把箱子放进门内，但没有看到封箱；另设乙连续看到全部动作的正例 | 窄观察事实；完整正例允许覆盖全部实际观察到的内容 | 因为在场就获知封箱前发生的事、精确旧时间或甲的动机 | 乙可用眼前位置行动；不会把此前不在场的细节当回忆 |
| 否认/修正 | 甲先说 P，后说“刚才看错，是 Q”；乙听到两次。世界是否 Q 单独给定 | 保存两次言语及修正归属；若乙实际改变看法，可新增其相应认知记录 | 删除先前陈述发生过的历史；直接用最新说法覆盖世界；强迫乙无条件接受 | 乙能区分旧说法与新说法、指出冲突或按其理由改信；不重复把过期信念当当前确定态度 |
| 时间与旧知情 | r2 记录“09:40 前已归书”；乙 r5 听到“书已放回店里”。另设乙早先确知 09:40 的分支；再设书后来被重新借出 | 新报告记录标 r5；旧有确切时间保持其来源；旧信息与新观察可共同支持完整目标 | 用 `SourceRevision=2` 推断乙 r2 已获知；用 r5 记录版本冒充归书时间；将历史“已放回”当现在仍在店 | 相同新句子在不同既有证据下应允许不同理解；乙不会跨分支继承另一个版本的知情 |

完整告知正控制不能仅靠“候选拒绝次数下降”通过：应检查信息是否真的在下一场可用。部分告知负控制也不能仅看 grant 数量：复制一个泄密的新 statement 同样算失败。

## 6. 防止三种退化

### 全部拒绝

每个负例配合法正例，分别统计整条误授予、合法交流漏记、合法 world fact 获知漏记、以及不必要停滞。新 statement 可以支持正常推理，不能把“尚未确认真值”当作人物不能行动的统一理由。

`undetermined` 必须保留为未能判断，不能计作正确拒绝；也不能当 `full`。第一轮固定候选审查可以暴露这种比例，尚不能据此确定产品如何继续。若保守策略显著阻断普通交流或只让故事反复核验，应否决该策略。

### 制造重复 statement

不要每提到一个 fact 都新增“某人知道”的认知事实。statement 表示实际言语事件；belief 只记录有依据且有持续作用的认知变化。一次说话向多个听者传播同一内容，可用一个窄记录和各自有依据的 `known_by`，不按听者复制全文。

同一次事件的精确重复候选可以检测；跨场重复同一句话却可能是真正的新事件，不能按文本相等自动删除。语义近义去重仍不可靠，第一轮只报告重复及成本，不做 embedding 自动合并或改写正式原文。

若需要去重 sidecar，可用分支、正文版本、原字范围和说话主体标识**同一次来源事件**；它不证明两个不同范围的内容语义等价。一个来源可以支持多条不同内容，不能因 source 相同就一律合并。

### 知识进了数据库，却不进入人物推理

现有 actorProjection 已能发送别人的 statement，不需要扩大 `belief_fact_ids` 或转发全知 notebook。应使用真实投影检查下一场：`jy-report-r5` 保留 statement/subject=jy，两个未获知的旧 fact 不在 xiu 的输入；当前已知的其他合法证据不丢失。

近期新记录通常会被 generation view 装入；长史下可能被省略。必须分别检验：记录存在、权限正确、检索 materialize 成功、actor 实际收到、人物反应是否合理。`used_fact_ids` 只是模型自报，不是推理已经有效的证明。

长期最小后续方向是按固定操作 pin 查询某人物已获得的相关记录，先验权限过滤再返回原文；不能把“显式提到人物”改为强制装入其全部历史。旧证据未取回时不得以新 belief 或全知 notebook 补洞。取得历史记录后的新反应仍需语义审读。

## 7. 公平对照与停止条件

分开三个问题，不在同一试验里同时更换正文生成、五字段装配、笔记结构和知识策略：

1. **冻结候选审查三臂对照**：首批必须同时纳入 A 当前 review、B 仅加入同等传播语义的简单提示、C 加入结构化来源表与显式 scope 判断。三臂使用同一冻结候选、相同可用世界依据、同一模型和一次调用预算；B/C 的规则含义相同，不给 C 独占额外事实或评估标签。候选既包含错 grant，也包含合法完整告知。比较误放行、误拒绝、未决和成本，分别判断语义指令与结构化接口是否有额外价值。三臂都只诊断、不修正候选；本试验不证明新故事能写对。
2. **冻结正文抽取对照**：A 保留原抽取惯例，B 使用窄传播惯例；都输出同一版 Candidate，保持固定正文和笔记策略，review 路径固定。观察 B 是否自然避免多余 whole grant、是否复制泄密内容到新 statement，以及是否遗漏真正发生的知情。所有原始输出保留；不择优、不重试至成功。
3. **下一场连续性对照**：仅在候选通过相同提交边界后继续；使用真实 generation view/actorProjection，检查合法交流是否影响人物反应及后续选择。未通过者计为该场失败，不能删除后再只比较成功分支。人物允许合理不同反应，不指定其必须同意玩家。

上述简单语义提示臂是首批必要比较，不能等结构化方案表现较好后才追加。若 C 相对 B 没有可复核的收益，就没有证据支持新增 sidecar 的复杂性。不要把更多输入和更长输出的成本藏掉；也不要声称调用数相同就计算预算完全相同。

先用已读真实失败定位，再固定六类开发场景的词汇/角色/时态变体，按故事而非单条边报告结果；新场景、正负例数量及预算在调用前锁定。模型审读与人工评审分开。结构测试可证明权限和引用校验，不能证明人物心理或文学效果。

否决条件包括：错 grant 没有降低，只换成泄密 statement；合法信息利用明显减少；依靠新增无限重试；把未知强填为相信/不信；因同义重复造成历史快速膨胀；actor 收不到刚刚合法获得的内容。不能用总分抵消严重的跨人物秘密泄露。

## 8. 实施前仍需决定的问题

- `known_by` 对世界 fact 在产品中究竟表示“接触到该内容”还是“已建立该事实的认识”？当前字段没有保存这一区分。最小原型用 statement 承载未经确认的说法，避免悄悄扩大现有字段含义；不宣称所有旧边已符合这一新惯例。
- 哪些普通交流足以支持旧 fact grant、哪些只保留说法，仍含来源可信度和语境判断。不能用“说了/看到/相信”等词表决定，也不能统一要求独立核验后才允许相信、形成认识或行动。
- 多个旧证据与本段部分告知联合支持完整目标时，如何在有限容量内找到它们？完整 authority 不等于审核 prompt 已含全部证据，缺检索不可误判为没有来源。
- 旧错误知情如何纠正？不就地删除已封存边，也不把所有旧边追认为正确；修复历史或开启纠正分支应走明确产品流程，与本次新传播机制分开。
- 否认和改信的当前状态仍主要通过带版本的文本表达。若六类反例显示后续模型持续把旧态度当当前态度，才有理由增加显式 supersedes/有效时间等合同；本原型不能假称这已解决。

建议下一步先完成冻结候选的来源表与六类正负控制，再决定是否实现 review 内部扩展。现有窄 statement 是可用起点；严格来源绑定是可机械保障的部分；自然语言完整覆盖与人物理解仍是本次实验需要测量的未知量。
