# Demo 互动规则的增量协议

本地融合沿用导出源码的 Go 唯一正式写入方、Rust 候选验证和 Flutter 客户端分工。原版 demo 的资源、空间、旅程与时间规则模块保留为固定、无 HTTP 或数据库访问的校验 worker；用户点击已有作品动作后，Go 校验来源、分支、版本、规则摘要与授权，保存操作，并在提交事务中重放确定结果。客户端预览不直接写入世界状态。

协议仅增加三个可省略、可为 null 的字段：`state.gameplay`、`candidate.gameplay_update`、`context.gameplay_action`，及七个对应的闭合定义。去除这些新增项后，JSON 结构与原合同完全相同，既有字段、必填集合和约束不变。旧数据不需要批量改写；询问操作仍不得改变世界。没有互动状态、更新或动作时，旧提交流程走原有路径。

`gameplay_action` 由 Go 从已保存作品和规则中生成；模型不能提交此字段。模型只提议当前正文原句支持的公开变化，实际数值、持有权、路线费用与时间由后端重新验证。Go-only 的 worker、运行上下文和重放材料不进入 JSON 模型上下文。正式回执使用现有请求 ID、operation 恢复和提交机制。
