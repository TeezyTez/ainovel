# 世界权威、人物认知与长期记忆：面向交互叙事的架构研究

日期：2026-10-20。范围：主要原始文献阅读、当前代码与已封存合成场景证据审查；采用 `research` 技能。本文没有运行新模型、构建或修改产品协议。案例判断是独立模型审读，不是真人文学验收。下面的设计是待证伪的工程提议，不是文献已经证明适用于 ElseLife 的方案。

建议保留 Go 的正式历史、事务和分支权威，首先改变**信息传递与记忆更新的语义**，而不是增加 Agent 数量。短期用现有窄 `statement` 表示交流内容，禁止把部分告知自然扩展为整条旧事实的知情；中期把世界事件、观察/转述、人物信念和可丢弃的叙事索引分开，并逐步采用带来源的增量更新。没有证据支持“换成知识图谱”或“增加独立 review”就能自动解决这些问题。

### 1.2 严格验证挡住错误，但完整笔记重写制造了额外出错面

v4.7 后续来源 `.validation/deep-benchmark/20261020T044736Z-v47-reading-resume/NAR-017` 的 S05，seq 26 candidate 把 `jy-stay-r6` 加入季砚的 `belief_fact_ids`；该记录实际上是 `kind=fact`，描述季砚作出留下过冬的决定。Rust [narrative_state.rs:154–165](../algorithms/src/narrative_state.rs#L154) 要求这个槽位引用本人的 `statement/belief`，因此以 `invalid_character_belief` 拒绝，未正式提交。这是有效阻断，不能靠改类型、删除引用或放宽 validator 将候选“修过”。

但当前 [extract 指令](../algorithms/src/narrative_pipeline.rs#L930) 要求模型每次输出整份替换笔记，并保留旧条目。模型因此同时承担：抽取新事件、区分世界事实与心理内容、复制旧知识引用、改写长期人物笔记。即使正文合理，任何一个旧条目的抄写或类型错误都能阻断整次生成。这里的替代方向是**由程序保留未变内容，模型只提议明确的局部变化**；不是让所有事实都能放进 belief 列表。记住自己的已发生决定，也未必需要再造一个 belief 条目，普通事件记忆即可表达。

### 1.4 人物声音不能仅靠可反复改写的形容词维持

[既有章节审读](2026-10-20-v46-nar014-017-model-review.md) 记录了 NAR-014 多章反复“核清—不保证—不算完成”，以及 NAR-017 前几章近似的核对、翻页、时间和下一本书节奏。现有 voice 笔记容易落到“话少而具体”“短句配合动作”之类通用描述。它们难以区分人物，也可能使模型把审核措辞写进每个人的台词。

这项判断仍是有限样本的模型审读；不能从中推断所有故事都已声音漂移。可检验的替代是：从合法视角的既有正文保留少量风格例证，把稳定声音、当下情绪、人物信念分别检索。风格例证仍须过滤未来情节和秘密，不能为模仿口吻把作者全知段落送给 actor。

## 3. 三种机制选项

| 选项 | 能解决的主要问题 | 代价与尚未解决的问题 | 选择 |
|---|---|---|---|
| 完整可能世界/动态认知逻辑模型 | 在预先形式化的小领域里，精确计算私下消息、怀疑及高阶知识变化 | 自然语言到命题/事件模型仍需判断；角色、命题和嵌套认知增长后维护困难；容易强加不符合人物的理想理性 | 用作小型反例与测试 oracle；暂不作为全产品核心 |
| Go 权威事件与快照 + 明确观察/说法/信念 + 可追溯增量记忆 | 保留现有事务/分支；从授予整条记录转向有来源的交流与认知变化；减少整本笔记重写 | 需要逐步明确数据语义；自由文本蕴含仍有灰区，不能声称全部可机械证明 | **推荐，分阶段实施** |
| LLM 自动知识图谱/RAG + 滚动笔记作为主要状态 | 语义检索、长期主题回忆、压缩输入较易接入 | 错抽取、别名合并、最新消息覆盖、可见性传播都可能成为世界错误；没有自动得到事务/秘密/分支保证 | 适合派生检索索引，不替代权威状态 |

推荐路线的重点是**确定谁可以把什么变成正式历史**。图存储、向量库或传统 SQL 都不是这一问题的答案。现有 Go CAS、fence、正式快照和原文回取值得保留；新增表示应尽量成为其上的小型、可审计变化。

## 4. 推荐机制的具体语义

### 4.1 先充分使用现有类型，再引入确有必要的新关系

对 NAR-017 这种部分告知，最小可行表达已经存在：

1. 保留两个旧 fact 及原 `known_by`，不重写它们。
2. 新增窄 statement，记录谁对谁说了什么；本例已有 `jy-report-r5`。
3. actor 可以知道“季砚这样说过”，但系统不自动推出他说的内容全部真实、于砚全部相信、或于砚知道说话中未包含的细节。
4. 若之后确实查看了原借阅记录或完整听取另一段说明，再根据新观察建立适当知情关系。

这个惯例可以先在现有协议内验证。单靠一句 prompt 仍不是底层保证：候选中的旧 fact grant 必须在审查时与**整个目标 record、此前已知内容、实际传播渠道**一起比较。若要在程序上强制，需要一个显式的获知依据，而不是假装字符串子串检查已经完成语义判定。

随后可在影子投影中试验以下关系，只有实验证明必要才改变共享合同：

```text
FormalEvent
  id, branch, revision, story_time_or_interval, page_span
  kind = action | utterance | observation | world_change

Claim
  id, content, modality, subject_refs, qualifiers
  asserted_by?, source_event_ids[]
  # “A 说 p”与 p 是不同对象；候选 claim 尚不是世界真相

Acquisition
  observer, claim_or_event_ref, channel, source_event, learned_revision
  # 获得了何种信息，不隐含赞同，不依组织关系自动扩散

BeliefRevision
  actor, claim_ref, stance, evidence_refs[], supersedes?
  # stance 可表达接受/怀疑/拒绝；保留当时的误信与后续改信

DerivedMemory
  key, kind, content, source_refs[], source_head, subject_scope
  # 剧情索引/声音例证/未兑现承诺；可重建，不能单独提交世界变化
```

这不是要求立刻增加五张业务表。可先由现有 fact/statement/belief、page/source revision 构造影子视图，统计哪些关系现有字段不足以无歧义表达。旧数据没有可信获知时间时应标未知，不能把 `SourceRevision` 自动当成谁何时获知。

### 4.2 “拆原子事实”的适用粒度与剩余缺口

需要的最小单位是**能被独立传播、否认、失效或约束行动的内容**，不是按句号、三元组或固定字数切分。例如“归书发生”“09:40 前已归还”“季砚说自己归过书”可能必须分开；“A 或 B 拿了钥匙”却不能拆成 A 拿了钥匙与 B 拿了钥匙两个真事实。

每个单位仍须保留否定、条件、主体、时间范围、引述归属和不确定性。“陆棠相信 P”不能变成 P；“答应见面”不能变成“已见面”；“没有看到钥匙”不能变成“钥匙不存在”。别名合并也可能把两个人的认知混在一起。

即使粒度合适，语义蕴含仍有缺口：两个各自允许的小信息合起来可能泄露秘密；共同知识和“甲以为乙知道”不是简单的观众 ID 列表；自由文本不能由纯结构检查穷尽。因此不建议宣称原子化完成后即可取消独立语义审查。应对关键关系采用少量明确规则，对开放叙事保留不确定性与原文证据，并测量误放行和过度阻断。

### 4.3 区分世界变化、纠错与改信

“钥匙被移走”是世界变化；“先前记录拿错钥匙的人”是记录纠错；“角色发现自己被骗”是人物信念改变。三者不能都用“新记录覆盖旧记录”处理。

本项目需要至少区分：

- **故事有效时间**：事情何时发生，或在什么区间成立；允许未知、相对时间和区间，不凭空补精确日期。
- **正式记录版本**：系统何时接受这条记录。
- **人物获知时间/版本**：哪个角色通过哪个事件获得了什么。

当前状态可由类型明确的关系推导，例如“某物在某处”的有效区间；历史原文仍保持不变。自由文本里的“现在九点”不应无限充当所有后续场景的当前时钟。对还没有明确单值语义的自由文本，不应靠最新一条 LLM 抽取自动裁决冲突。

人物可以相信假话，也可以同时保留矛盾、偏见或不确定意见。新消息只有在角色实际接触并作出相应判断时才修订其信念；“最新”不等于“可信”。为了防止谎话污染世界，保存说话事件本身为真，并把其内容的真假和听众的态度分开。

### 4.4 观察范围、主体层级与分支

作者/世界验证器、读者、当前 actor 是不同主体。作者秘密可以供受控的世界一致性判断使用；actor 的输入和回取必须先按角色、分支、版本过滤，再做检索排序。不得先把完整秘密送给模型，再要求它“假装不知道”。人物自己的意图和私密信念也不应自动公开给玩家。

在场名单只提供观察候选，不能直接生成获知边。渠道还可能受距离、语言、遮挡、注意和是否打开文件影响。已经授权的角色自主行动可以产生真实观察；玩家的计划、他人的建议和作者希望发生的情节不能替代实际行动。

可先只显式保存“甲知道某件事”和少数必要的“甲认为乙知道某件事”，不强行构造无限嵌套认知。公开事件应记录实际受众与公开条件；两个各自听到的人不自动获得“对方也知道”的认知。完整共同知识求解留给确有需要的小场景。

分支共享不可变前缀，之后各自追加事件；认知和当前状态都按分支头计算。索引可以复用前缀内容，但每次返回证据必须验证属于当前祖先链、未越过时间上限且对主体可见。异步缓存带 `source_head`，过期结果不能在另一个分支或更新版本直接生效。哈希相等证明来源字节未变，不证明原先的语义正确。

### 4.5 长期记忆是可回取索引，不能成为第二套权威

建议拆开三种记忆职责：

- **已发生经历**：保留原页/事件；摘要只是带来源的入口，不能覆盖原始事实。
- **未完成承诺、问题、计划**：稳定 key 与明确状态；只有有来源的完成/放弃才能改变状态。未来计划和发生事实分开。
- **人物连续性**：稳定身份、少量声音例证、当下目标与情绪分开；未变化部分由程序保留，模型只提议局部更新。

初步不需要自动对每条事实调用模型做图谱整理。先减少每回合完整 notebook 改写，再测哪一类查询确实需要额外检索。重要的是回取能找回早期细节，同时维持权限和来源；仅提高相似度召回没有解决人物知识问题。

容量目标应是：完整历史线性增长在存储中，每阶段工作集根据当前行动选择；旧证据可按需取回。不能保证固定窗口容纳任意大的必要闭包；若一项行动确实需要超出预算的证据，应明确失败或分解该行动的取证过程，不能悄悄删掉不可缺少的约束。输入压缩、额外查询延迟、遗漏率需要一起测量。

## 5. 最小实施顺序与可证伪验证

这不是将八篇论文的组件全装进产品。建议从一个小而完整的变化开始，并保留现在已经有效的失败阻断。

**第一步：现协议内验证传播语义。** 用封存 S04 固定正文、旧快照和 candidate，比较原行为与“窄 statement 足够则不额外授予旧复合 fact”的候选策略。必须同时包含完整告知、读到完整原记录的正例，避免一律禁用知识变化。这一步证明的只是特定信息流边界，不能假称一般自然语言蕴含已解决。

**第二步：影子实现来源与认知投影。** 只新增派生结果，不改原页和旧 snapshot；比较窄 statement、观察事实和 belief 在后续 actor 输入中有何差异。量测现有字段无法无歧义表达的比例，再决定最小共享协议增量。禁止无来源回填旧人物的获知时间。

**第三步：增量笔记与受权限约束的回取。** 模型只输出对稳定 key 的小变化，Go 按 base revision 确认未变化项；缓存需可从正式记录重建。对无关旧条目拷贝错误、错用 belief 引用、voice 泛化分别测试。不要为了使类型通过而自动把事实改成信念。

**第四步：真实长程对照。** 预先固定场景组、停止条件、预算和评审方法；记录全部尝试，不选最好的一次。至少包括以下可推翻方案的反例：

| 检验 | 反例构造与失败条件 |
|---|---|
| 部分传播 | 同一复合内容只告知一个分量；若另一个分量出现在 actor 输入或正式获知边，失败。完整告知后仍永久拒绝也算失败。 |
| 说法/误信/欺骗 | 甲说假话、乙听见但怀疑、丙没听见；若世界被改真、乙被强迫相信或丙获得信息，失败。随后可信反证应允许改信且保留历史。 |
| 观察与共同知识 | 睡着、隔墙、组织成员未收信；私下分别收到与公开共同听到使用相同内容。若系统一律传播或自动合并高阶认知，失败。 |
| 时间与分支 | 迟报旧事、真实新变化、记录纠错；同前缀两个分支做相反决定。若旧时间变当前时间，或查询/缓存串支，失败。 |
| 长史与容量 | 在 20/50/100 段历史中埋入低频约束、被否定误信及未兑现承诺；同时记录必要证据遗漏、容量阻断、回取成本。不能只问“还能背出什么”。 |
| 角色声音 | 在未用于设计的完整场景里盲读角色台词与行动；比较角色可辨性、自然反应与重复密度。仅关键词命中或模型打分上涨不足以验收。 |

工程断言与内容评估应分开报告：类型、CAS、权限 scope 和分支隔离可做确定性回归；开放语义需要独立评审及人工抽检。至少同时报告错误知情授予、合法告知漏记、未经授权世界变化、人物声音/阅读质量、耗时和模型调用数。只报告 QA recall 或失败减少，会掩盖“什么都不让发生”的退化。

## 6. 哪些修复已经有价值，哪些结论仍不成立

CLI 单 user 原字传递、抽取对象代替嵌套 JSON 字符串、实际传输容量计量、冻结正文与精确 quote 检查、完整支持 ID 覆盖、共享唯一修复预算，以及正式历史/分支/取消/恢复的证据约束，都解决了可复现的工程缺陷。它们应保留，并作为之后语义实验的稳定基础。

尚不能成立的结论包括：“多阶段所以人物有独立心智”“review 通过所以知识变化正确”“全部结构回归通过所以故事可信”“34 KiB 预留通过两例所以长期容量解决”“论文长篇/问答分数高所以能安全接管世界状态”。这些论断都跨过了实际证据。

当前最有希望的底层改变，不是另添一层提示词，而是让每种数据只承担它能证明的职责：**正式事件说明发生了什么，交流记录说明谁说/看到了什么，人物信念说明他接受了什么，长期索引帮助找回这些证据。** 先用现有窄 statement 完成第一步，再根据反例推动有限的数据语义升级；这样既避免逐题修补，也避免没有证据支持的大规模重构。
