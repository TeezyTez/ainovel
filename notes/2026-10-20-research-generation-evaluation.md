# ElseLife：生成架构、校验边界、延迟与可信评价研究

日期：2026-10-20。作者：benchmark_harness agent，按 research skill 执行的后台研究。本文只提出可检验的假设与研究协议，没有修改产品/基准、运行付费模型、实施新实验或获得真人评价。外部资料以原论文和作者仓库为准；本地事实来自冻结运行记录与只读源码。本文中的样本量、实验流程和预算是**拟议方案，不是已取得结果**。

当前最值得验证的方向是：减少同一信息在串行模型间反复生成，保留真实提交权威；将审稿作为有误判成本的概率性检查，而不是事实证明；用完整从头轨迹和盲读决定是否改善体验。没有研究足以证明“多 agent 越多越可靠”，也没有研究足以证明“全部改成一次生成一定更好”。应先做小型对照，不先建设通用 agent 框架。

## 1. 已读取的原始研究及可用边界

下列八项是主要研究来源。摘要中的效果值不作为 ElseLife 的预期收益；没有引用二手博客作为结论依据。

| 来源 | 本文实际采用的发现 | 不能外推的部分 |
|---|---|---|
| Huang 等，ICLR 2024，[Large Language Models Cannot Self-Correct Reasoning Yet](https://arxiv.org/pdf/2310.01798)，尤其第 3–7 节 | 在所测推理任务中，没有外部正确性反馈的自纠错可能失败或退化；比较需控制推理成本，并给初次生成完整任务要求。 | 论文明确不否定其他领域的自修订。它不是中文长篇叙事、当前模型或 ElseLife 审稿的直接实验。 |
| Madaan 等，[Self-Refine](https://arxiv.org/html/2303.17651v2)，第 3 节、第 6 节及人工评价说明 | 同模型反馈/修订在所测七类任务中有收益，部分任务用了盲评；反馈应具体指向可改之处。 | 实验是英语任务，允许多次迭代；不证明“同模型批准”有事实权威，也不是固定相同预算下对所有强基线的胜出保证。 |
| Zheng 等，NeurIPS 2023，[Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena](https://arxiv.org/html/2306.05685v4)，第 3.3–3.4 节、附录 D | 模型裁判会受答案顺序、冗长及推理能力限制影响；交换位置、参考明确标准是可检验的缓解方法。 | 论文对“偏爱自己”的证据保留因果不确定性；不能将其约八成的人类一致性概括成所有中文小说评价的准确率。 |
| Liu 等，TACL，[Lost in the Middle](https://arxiv.org/html/2307.03172v3)，第 2–3 节 | 多文档问答、键值回取中，材料位置会显著影响使用效果；装得下不等于能可靠利用。 | 旧模型、检索任务不等于当前长篇小说。该文没有证明任意摘要、任意排序或删材料能修复 ElseLife。 |
| Kim 等，[Towards a Science of Scaling Agent Systems，固定 v2](https://arxiv.org/html/2512.08296v2)，实验与限制节 | 架构收益随任务可分解性、协调成本和模型能力变化，需在工具与预算受控下比较。 | 不把文中的阈值和放大倍数当普遍规律。作者后续版本及分析已变化，见下面的版本说明；长时人物互动不在该版实验直接覆盖范围。 |
| Kim 等，ICML 2024，[An LLM Compiler for Parallel Function Calling](https://arxiv.org/html/2312.04511v3)，第 3–5 节 | 根据真实依赖图并行独立工具任务，可缩短串行等待；依赖前序结果的任务必须等结果。 | 其工具调用任务与 ReAct 对照的加速比不能直接套到小说写作。本文不据此并行“尚未产生的正文”的提取或审核。 |
| Brown 等，[Large Language Monkeys](https://arxiv.org/html/2407.21787v2)，第 4 节 | 更多采样中的“至少一个正确”与实际选中正确样本不同；选择器可能先饱和，测试也可能有误判。 | 不将 pass@k 上界当玩家实际拿到合格内容的概率；本文不建议无限重采样或用知道答案的 oracle 选故事。 |
| Oren 等，ICLR 2024，[Proving Test Set Contamination in Black Box Language Models](https://proceedings.iclr.cc/paper_files/paper/2024/file/46e624c244cff669223d488defd4e835-Paper-Conference.pdf)，第 2–4 节 | 黑盒污染检测也依赖明确假设和可用的 log probability 查询；不能仅凭熟悉题目就证明预训练污染。 | ElseLife 连续步骤并非可随意交换的独立样本，当前也未运行此检测。因此只能确认开发团队已见题/反复适配，不能声称模型预训练已污染。 |

架构论文的版本需要特别谨慎：读取时，[作者仓库](https://github.com/ybkim95/agent-scaling)将后续成果列为 *Capable language models can outgrow the benefits of collaboration*；[作者 CHANGELOG](https://github.com/ybkim95/agent-scaling/blob/main/CHANGELOG.md)说明 v2.2.0 修正分析集默认包含样本的错误，从 270 配置改为论文中的 260 配置，并提供新的复现脚本。上表固定 v2 的 180 配置不是后续同一套实验。本文仅采用“需受控比较架构”的研究动机，不混合版本，不搬用流传的 45% 阈值、17.2 倍错误放大或架构选择准确率作产品决策。

这些研究并不互相抵消：风格修订可能有效，事实/授权推断仍可能失败；更多候选可能增加覆盖，选择器仍可能选错；并行可能更快，但只有在真实依赖允许时成立。下面是结合本地证据提出的工程推论，不是论文已验证 ElseLife。长上下文论文中的 token 长度、材料位置效应，与本地 JSON payload 的 UTF-8 字节预算是不同量；通过容量检查只说明请求能发送，不能据此推断模型有效记忆长度，更不能把 KiB 当作千 token。

## 2. 本地问题应如何重新表述

当前普通推进状态机包含 memory、可选 actor、plan、evaluate、write、extract、review，另有共享一次的修复/修订。多阶段不是逻辑上独立的见证者：后段往往接收前段输出，同类模型可能继承同一个错误。**“相关误差是否严重”仍需测量；不能只因角色名称不同就假定独立。** Go 的 actor 视图确实有知识过滤，这是有价值的权限边界，缩短流程也不能扩大它。

只读位置：`algorithms/src/narrative_pipeline.rs` 的 Stage 与 advance 分支；`backend/internal/experience/narrative_pipeline.go` 的阶段检查和 actorProjection。源码正在迭代，以下具体运行数字以对应冻结记录为准。

已有三个足够具体的问题：

- **串行成本真实存在。** NAR009 从头 v4.3 的八个正式页用了 54 次调用、1,031,648 ms；各页为 6–7 次调用。这不是首字延迟，也不包括冷构建。v4.6 NAR014 S05 与 NAR017 S04 分别用了 9/8 次调用，约 250/239 秒。来源：[NAR009 完整审读](2026-10-20-nar009-fresh-v43-model-review.md)、[v4.6 两例审读](2026-10-20-v46-nar014-017-model-review.md)。
- **冻结正文仍被重复输出。** write 产出 Draft 后，extract 生成完整 candidate，随后代码要求 Draft 与 candidate 对应字段一致。v4.6 已去掉嵌套 JSON 字符串，但 extractor 仍承担复述原文任务。重复生成耗时，也增加转义/改字机会；这不等于其语义提取价值为零。来源：上述 Rust `Stage::Extract` 的 `self.draft...matches(&candidate)` 与 [v4.6 进展](2026-10-20-deep-benchmark-progress.md)。
- **review 的净收益并非单向。** FUN001/07 原首稿有真实主管知情缺口，但首审也错误要求执行 actor 开筒提议；revise 随之越权，后审挡下并使操作失败。固定候选 old→new 的一次配对保留了真实拒绝而去掉错误要求，是修复迹象，但只有一次随机输出。来源：[失败分析](2026-10-20-fun001-v44-actor-authorization-review.md)、[配对审读](2026-10-20-fun007-v45-paired-review.md)。

root 随后对原记录做了零模型调用的[机制探针](../.validation/research-mechanisms-20261020/results.json)，本研究已读取其协议与结果：NAR014 S05 模型阶段合计 249,610 ms，其中 extract 64,768 ms（25.95%）；NAR017 S04 为 238,950 ms，其中 extract 61,895 ms（25.9%）。这与操作 elapsed_ms 是不同口径。两个 actor 在同一快照下并行的理想算术节省前者仅 13,086 ms，后者只有一个 actor，节省为零，尚未计并发争用。17 组已配对产物去掉五个冻结 Draft 字段后，程序重组与原 candidate 对象完全相等；规范化对象总字节从 135,935 降到 103,866，减少 23.59%，另一个无合法配对的 NAR017 S04 产物明确排除。这是事后表示实验：保留原语义错误、未测试新模型抽取、未含 schema/信封、未证明实际提速，更不能把 extract 的全部四分之一耗时视为可删除。它支持优先做下面的对照一，不替代该对照。

因此目标不是“减少失败提示”，而是**更快得到能提交、能尊重玩家和人物、值得继续读的正文**。必须同时减少漏检坏稿、误拒好稿和无理由拖延普通成功。v4.7 去掉 review 的创作提议、保留原 context/candidate，已经是一个有依据的方向；但它是否影响文学连贯性或漏检新的错误，仍需对照，不能由容量绿测回答。[本地容量说明](2026-10-20-review-context-capacity.md)。

## 3. 三层责任，不能互相代替

| 层 | 负责什么 | 可验证证据 | 不应宣称什么 |
|---|---|---|---|
| 确定性代码与权威提交 | strict schema、ID/引用、状态版本、actor 输入权限、ask 不写世界、旧页不可改、数值已明确规则下的计算、租约/fence/取消/幂等、原文与候选原字一致 | 实际解析、SQL 读回、负控制、精确引用位置、提交事务 | quote 是子串不等于 quote 支持该事实；known_by 输入过滤不等于输出绝不暗示秘密 |
| 概率性语义判断 | 行动是否越过本次授权、人物何时如何获知、表达是否真同意、候选新增事实是否被正文支持、是否遗漏发生的知识传播 | reviewer 给当前 input/旧事实/正文的具体证据；用独立标注测误判 | approved 不是真值；两个同类模型同意不是两份独立事实；不能把计划当义务 |
| 读者体验 | 声音、节奏、可信反应、重复感、选择是否有意义、想不想继续、等候是否破坏投入 | 完整篇章盲读、实际交互任务、延后记忆、弃读/等待记录 | JSON 合法、无越权、模型分数高，不等于作品好读 |

新增事实支持和知识边是“代码能验证结构、模型需判断含义”的交界。现有精确 quote 应继续保留；若要减少复制负担，可试验返回原文的段落/起止位置，由代码取得原句。位置存在仍不能证明语义蕴含，且字符/字节单位必须明确。本文不建议为了减少拒绝而容忍非原文引文。

误判要分开记：非法候选被放行、合法候选被拒绝、正确拒绝、正确放行，以及无法判定。语义未知不能偷偷并入正确拒绝；合法完成低难度目标后又加阻碍，也不能因“没有越权”而获奖。默认不给一个能用更多拒绝抵消漏检的总分。

## 4. 两个对照与一个校准研究，先小后大

### 对照一：只移除冻结正文的重复生成

**问题：** extractor 的语义增量是否值得当前传输与重复生成开销？

选择四份已有封存 Draft/Context，覆盖普通小动作、公开/私有知识传播、长章节、多项新事实。它们是开发材料，不是 holdout。每份使用相同 model、输入上下文、采样配置，随机交错执行两个提取接口，各三次：

- A：当前完整 candidate 对象输出。
- B：仅输出允许的状态/叙事增量与引用；代码将**原冻结 Draft 的全部对应字段**装配进完整 candidate，绝不让模型再次生成正文，也不接受 delta 覆盖正文/标题/outcome 等冻结字段。

两臂装配后运行同一套 Candidate.validate、Apply、review 和一次共享修复限制；此次只在隔离评估路径，不提交用户历史。出现结构错、遗漏事实、错误 known_by、错误 reveal 都保留。若 B 改变内部接口，需要显式版本与 Go/Rust 同步测试，但无需先更换正式世界模型。

该小试验是 24 次初始提取请求；后续 review/修复另计真实调用，不把它们隐藏在“24”里。统计首轮结构成功、语义遗漏/增造、正文一致性、生成字节/用量、首提取及最终可用候选耗时。A/B 的同候选语义评审盲化，不能因知道 B 是新方案宽容。**只有减少复制错误且未增加语义遗漏，才进入完整流水线实验。**

### 对照二：三阶段短流程是否优于现有多阶段

**问题：** 普通交互是否需要每次都支付 memory→actor→plan→evaluate 的前置链？

用两个完整流程比较，不先引入路由器、调度框架或新模型训练：

- A：冻结当前完整流水线。
- B：沿用同一个权威上下文编译器、同样原文回取能力与字段边界，由一个 writer 直接产出 Draft；随后使用通过对照一的 delta extractor，再独立 review。普通无回取路径为三次模型调用。按原上限处理需要回取/修复的情况，不假称永远三次。

B 的 writer 是作者/导演视图；不能把全知材料作为某个 actor 的输入。它能否仅凭合法作者上下文维持 NPC 自主性与知识界限，是此实验必须测的风险，不是预设成功。所有臂初次 writer 都要获得完整相同任务要求，不能把 A 的重要限制藏到后段再称 B 更好。上下文不够则明确失败，不能用人工挑选“关键答案事实”替 B 减负。

第一阶段用六个固定权威检查点，每臂两次，共 24 个操作样本，覆盖：容易合法完成、拒绝仍有后续生活、秘密只由一人知道、玩家许可但未选择执行、较长章节、真实资源冲突。样本量只用于发现大缺陷和测方差，不能证明跨题稳定率。每个检查点原字相同、账户/分支隔离；调用顺序分块随机并交错，不能总 old→new。

只有候选 B 在此阶段没有新的严重权限缺陷，才用两个新作者场景，从同一开局分别执行两种有实质差异的玩家选择，每臂各两次、每条三轮：共 48 个操作上限。每条都独立从头运行该版本；后续人物反应必须承接自己实际产生的历史。分支效果看人物知识、机会/成本、关系反应和可行后续是否有根据地分化，不能只按文本相似度或“差异越大越好”判定。

这两阶段避免把“处理同一旧前缀”偷换为“新版从头体验更好”。若 B 普通步骤更好但复杂知识场景更差，再考虑条件升级：先用既有明确 mode/委托/状态依赖作保守范围，不新增一次模型路由调用；路由规则需在开发样本冻结并单独测漏分。不能把 benchmark ID、期望结果或人工正确答案作为运行路由条件。

### 研究三：先校准 review；有真实处理差异时再做对照

**问题：** 当前 reviewer 的漏检、误拒和随机不稳定是多少？只有另一个明确不同的审核条件可用时，才进一步问它是否改善。

建立一个固定候选面板：来自开发真实轨迹的合法候选与已证实问题各六份，成对保留最小语义差别；再加入独立作者封存的新场景候选，不提前给开发者内容。初始 12 份只是校准面板，合法/非法标签需独立审读、存在分歧就记 ambiguous，不能由待测 reviewer 自己生成金标准。

**默认是单条件校准。** 对每个同一 candidate/context，运行冻结 v4.7 的当前 reviewer 两次，固定预算，候选顺序随机；不因第一次拒绝就重抽到批准，不自动 revise。v4.7 本来就只读取原 context 与完整 candidate、不读取 writer 理由、actor/plan 提议或旧 review 分数，因此“只看 context+candidate”不能再算第二个处理条件。12 份候选的两次请求是 24 次审核调用，不是 A/B，也没有检验异构模型。

**可选的真正 A/B 必须另行登记唯一差异。** 若能使用另一个模型家族，A 为当前 reviewer，B 仅更换 reviewer 的模型/必要 provider 适配；业务 system/user/schema 原字、候选、信息可见范围及总预算保持一致，实际传输差异全部记录。若 provider 无法维持同等约束，则不能称纯模型对照。每个条件各两次，顺序随机交错；模型家族不同仍不证明误差独立，要实际统计两者共同漏检、共同误拒及独立标签上的差异。若没有异构模型，也没有预先写明且真正不同的 review 协议，就只做上述单条件校准，不能用“提示隔离”命名制造实验条件。

同一冻结 v4.6 候选上比较旧输入含提议与 v4.7 输入不含提议，可以另做历史机制诊断，但需要固定同一模型、其余提示/字段/预算并明确唯一改动；它不能冒充当前两个新流程，也不能证明新版从头更好。

单条件及可选 A/B 都记录上述混淆矩阵，并把结果对事实、知识、授权、纯风格问题分层。对已批准但实际错误、已拒绝但实际合法的例子分别复审。可记录自报置信度，但未经独立标签校准，不将它作为升级或放行阈值。

文风意见原则上与事实阻断分列：应试验“没有证据的风格建议不触发重新生成”，但不能未经实验把所有语义疑点都降级成建议。该面板证明的是检查器边界，不能单独给完整故事 PASS；最终仍需对照二的端到端漏检、误拒、用时与盲读结果。

## 5. 低延迟：先缩关键路径，再单独检验缓存与投机

把可见等待拆成队列/上下文准备、模型请求与输出、校验/提交、网络/渲染。正式首内容时间应从用户动作开始到**经审核并正式提交的第一段可读正文**，另外报告内部 TTFT。显示“正在写作”不能当内容首字，冷编译不能混入操作延迟，预生成耗费也不能从成本中消失。

依赖上只有真正独立的工作可并行。例如多个已经确定 ID/版本/权限的原文只读回取；不同 actor 在各自封闭视图上形成提案，也可能并行，但之后的决策必须等待所需输出。提取需要冻结 Draft，完整事实审核需要提取后的候选，因此不能为降低数字把这两步无条件并行。LLMCompiler 提供的是依赖调度启发，不是这里加速的证据。

当前 `backend/internal/experience/narrative_preparation.go` 已有 preparation pin、BaseRevision/BaseFence、引擎版本和 ready lease 检查；claimablePreparation 只消费空 input、空 reading_request 的 read。consumePreparation 再核对当前 branch revision/fence、偏好/世界 pin、approval 与 Apply。这些正确限制应保留；“缓存命中”不能绕过当前授权。

拟议缓存必须声明所缓存对象及失效集合：

| 对象 | 允许的复用与必须绑定 | 不允许 |
|---|---|---|
| schema /固定提示前缀 | 精确 model/provider、prompt/schema/engine 版本与原字；供应商是否真正缓存需实际用量/日志 | 从本地字符串相同推断服务端已缓存或质量不变 |
| 权威上下文与回取片段 | account/workspace 隔离键、experience/branch、revision、权限投影、事实/原页摘要、偏好与编译配置版本 | 跨分支/跨角色复用隐藏知识视图；旧快照在新 revision 当真 |
| 已审核候选 | 完整 candidate hash、对应 input/mode/reading_request、状态 pin、review 配置及批准、最新 lease/fence；提交时再 CAS | 改字后复用旧 approval；用户输入不同却命中“相似请求”；取消后迟到候选仍提交 |

这些是语义缓存边界，不涉及改变模型的底层 KV 实现。不能仅凭一篇论文许诺某供应商缓存节省百分比。

预计算仅作为第二个独立实验因子，在流程质量冻结后再测开/关；先只用现有默认 read 范围。最多准备下一候选，不把若干未来分支都生成出来赌用户选择。遇到 act、明确新 reading_request、偏好修改、分支切换、权限变化或新 revision，就按实际依赖取消/失效。

未审核、未提交的正文、对白、新人物、资料字段、图像提示等不能进入浏览器可见响应，也不能先写进公共缓存/日志/搜索索引再靠前端隐藏。阶段状态可以公开，候选内容不可以。审稿后的投机结果也不能未经用户下一次实际请求便成为正式世界。

对每次预计算记录：触发原因、来源 pin、资源用量、完成/取消时间、是否被合法消费、丢弃原因。报告命中率、浪费字节/计费 token、抢占真实请求的排队时间、P50/P95 的用户等待与所有后台成本。可按实际记录计算“总生成资源 / 实际交付合格页”，并同时公布交付失败数；不能只对命中样本报速度。取消供应商请求不保证已发生计算免费或立刻停止，计入实际已发生费用。

## 6. 预注册：让失败能推翻设计

下列数值均为拟议 pilot 的设计选择，不声称经过功效计算或用户已经认可实验费用；本研究未执行任何付费请求。

**分析单位与重复。** 固定前缀实验单位是“原权威状态 + 当前输入”，完整体验单位是整条轨迹。模型调用、句子、facts、重试不是独立样本。上述两至三次重复只探索随机不稳定与大缺陷；正式比较样本量应根据 pilot 的方差、最小有意义质量差异和可负担成本重新预注册，不能边跑边在显著处停止。

**冻结与随机化。** 预先保存运行代码/模型标识、完整 prompt/schema、上下文编译规则、fixture 作者选择、序列、评价准则和预算摘要。按场景类别分块，将臂顺序随机交错；固定 seed 仅在 provider 真正支持且记录时使用，不声称 seed 能跨不同 prompt 保证同一随机样本。模型/供应商版本变化另开实验。读取结果后修改 prompt 的下一轮是新开发实验，原失败保留。

**预算。** 首个流程对照采用相同已冻结单请求窗口/输入容量/输出上限，每操作最多 12 次请求、共享最多一次修复，操作墙钟上限拟定 360 秒；这些是上限，不要求短流程把剩余请求花完。回取、拒绝、修复均消耗原上限。公布每次实际输入/输出字节、可得的计费 token、调用数、阶段时间和总成本；若没有可信 token 用量，不称严格等 token 实验。

为单独回答“同预算下哪条流程更好”，开发 pilot 另预注册两个累计**实际请求/输出 UTF-8 字节**档位：每操作 256 KiB / 512 KiB，各臂使用相同档位、相同最终请求计量、相同输出预留，schema/信封按实际发送计入；无法保守预留下一请求就记预算耗尽。它是可复验的传输/生成量预算，不等价于 token/FLOP。若能获得可靠 provider 用量，再另预登记 32k / 64k 总输入加输出 token 档位，按同档位比较，不以字节换算伪造真实 token；计量能力不足则不开展该 token 结论。只有同一预算内的最终可交付结果算成功，不用免费的人类答案在多个候选间择优。预算边界敏感性只在开发 pilot 做，holdout 用冻结配置。这样将“实际部署更便宜/更快”与“同预算能力更好”分成两个可反驳命题。

**失败与分母。** 超时、provider 故障、取消、容量、解析、错误拒绝、不可恢复断点都进入启动样本分母。工程故障与内容问题分栏，并同时给端到端完成率；不能删 provider 失败后只对成功故事作主结果。原题依法不成立的条件步骤单列不可触达，不将 NPC 合法拒绝计作内容失败，也不自动发该子检查 PASS。失败候选不进入用户正式史，但保留供审计。

**主要指标。** 第一组：越权/私密知识泄漏/旧史改写与无依据状态变化。第二组：合法普通成功、合法拒绝后的可继续性、完整轨迹完成与错误阻断。第三组：盲读选择、重复感/声音/选择后果与用户等待。同时报告率的分子分母、区间和按场景的结果；不以仅减少平均调用数、review 批准率或单个合成总分选择架构。严重权威破坏是停止发布的条件，未观测到破坏不是已证明风险为零。

**统计。** 对同一场景的臂差使用配对分析；按场景/整条轨迹聚类，读者分析同时考虑读者差异。小 pilot 只报样本级差值与宽区间，不把几十个同源回合当几十个独立场景。主比较预先指定一个，其他风格轴/子组探索性标注。不同分支允许产生不同合法结局，裁判依据事先定义的因果/权限条件，不要求复现某条标准故事。

**盲评。** 拟议 pilot 邀请 12 名符合目标语言/题材的成年读者，按不完全区组平衡分配：同一读者对同一场景只读一个版本，避免从第二遍记住情节；不同场景中各版本暴露均衡。去掉引擎名、版本、调用次数、修复说明和自动 review 结果。完整读后再问是否愿意继续、人物行为理由、重复/说教感、玩家选择是否有可辨影响；需要时 24–72 小时后做预先固定的记忆任务。纯文本盲评与实际带等待的交互体验分开：前者控制文字质量，后者测真实可用性。12 人是可行性 pilot，不是正式显著性保证。

**模型评审校准。** 如使用自动辅助裁判，对成对文本做 A/B 与 B/A 两种顺序，保留矛盾/平局，不挑有利顺序；人类分歧也保留。裁判不看版本、先前分数或“本次修好了什么”。异构裁判只有在独立人审校准后才可支持推广；换模型名不能证明独立。

**开发集与真正保留场景。** 已读题目及其已公开变体都属于开发集。独立作者可以按预先约定的能力分层创作新场景，提前封存原世界、合法输入策略、必要作者补充、反事实条件及评分指南；开发团队只知道类别与资源约束，看不到具体题目和答案。运行冻结后才开放执行；失败后可进入开发集，但下一轮需要新的未见材料。原始连续步骤不能用 Oren 等的交换顺序检验直接证明无污染；缺乏预训练数据访问时，预训练污染保持未知，团队对公开题的适配则是已知事实。

## 7. 推荐的下一步与明确止损

先实现对照一的最小实验适配，保留当前完整流程作基线；它针对“已冻结内容仍由模型复述”的具体工程冗余，较容易隔离收益。随后只做对照二的一轮小 pilot，并用研究三的单条件方案校准 reviewer；有实际异构条件才追加 A/B。所有结果无论好坏都登记，不因短流程失败就补越来越多角色直到无法归因，也不因短流程快就取消语义检查。所有新采样、异构调用和读者招募仍是未执行计划，费用亦未发生；本文没有授权、预订或启动这些付费活动。

只有冻结从头轨迹和盲读同时支持，才把较短路径用于产品；高风险类别保留已验证路径。预计算的开/关最后单独比较。若 reader 仍觉得重复、人物声音趋同、选择无后果，即使结构全绿，也应转向创作上下文与人物行为机制，而不是继续给 evaluator 增加通过项。

目前能诚实主张的是：已有工程修复解决了真实权限、传输和取证缺陷；已有少数故事样本显示普通成功与收束改善。但多阶段架构的净效益、当前 reviewer 的错误拒绝率、跨新场景泛化、读者偏好和可接受延迟尚未得到可信比较。本文提供下一轮可被反驳的实验设计，不预写结果。
