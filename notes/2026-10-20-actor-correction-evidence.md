# 角色更正证据：存储、取回与采信需要分别验证

2026-10-20。本记录针对 v4.9 整合审查中新发现的候选问题，不把旧信念仍在历史中视为错误，也不把记忆索引更新视为人物已经改信。

## 本地证据与问题边界

最新 NAR010 的正式正文包含秦姨对茶壶口味的完整说明，阿穆在后续两页按口味服务。但之后两次成功 actor 调用的主体均为秦姨；何叔的 actor 调用因 provider 退出失败。该轨迹没有阿穆获得更正后再次独立决策的输出，不能用它证明角色认知更新成功或失败。

v4.9 为作者增加有出处的局部文学记忆，角色仍只获得其有权知道的正式事实。这个隔离应保留。作者把某条解释标成 `revised`，并不意味着所有角色都听过新消息，更不意味着他们相信它。

当前取材把角色自身 `subject_id` 事实排在其他已知材料之前。在预算压力下，自己早期的信念和大量个人日常记录，可能挤掉其他人对其说过的更正。是否构成程序缺陷，必须检查更正是否具有当前接口可识别的关联：显式 `fact_ids`、人物关系、实体引用或其他已知依据。不能要求程序凭字符串 ID 知道两段自然语言互相否定。

另一个表示层限制是：`Fact.source_revision` 表示记录建立的版本，`known_by` 是当前知情集合；这两者都不直接表示某个人第一次获知旧事实的版本。因此仅按 `source_revision` 排新旧，不能保证优先取到“刚刚才告诉这个人的旧消息”。是否需要新增持久字段，先用权威历史能否可靠重建来判断，不先建立第二套世界库。

## 调研对设计的约束

LongMemEval 将索引、检索、阅读分别评估，知识更新与时间推理也是不同能力；其分析还显示，把互动进一步压成孤立事实会丢失信息。这里借鉴的是分阶段诊断，不能把对话问答成绩视为小说人物质量证据。[LongMemEval，ICLR 2025](https://arxiv.org/html/2410.10813v2)

Zep 区分系统记录时间和内容的有效时间，并保留失效关系的历史。这有助于识别本项目“事实发生、记录建立、角色获知”混为一个版本的风险。但其新信息优先的失效策略不能直接用于戏剧中的谎言、误解和立场冲突。[Zep §2.1、§2.2.3](https://arxiv.org/html/2501.13956v1)

CogMem 保留带来源与对象的主张，并以附加记录保存同一来源的时间性修订。论文自己限定了英文对话、模型评审及合成探针的适用范围；它不是多角色小说的有效性证明。本项目可以借鉴来源区分，不必为此迁移图数据库。[CogMem §3.1、§6、附录D](https://arxiv.org/html/2610.11314)

## 当前决策

先验证“证据是否进入人物实际输入”，再评估人物如何理解。不得用作者的完整真相直接替人物改信，也不得把所有他人 statement 永久升到最高优先级。

| 控制 | 需要观察的行为 |
| --- | --- |
| 有明确关联、角色已获知的更正 | 在足够容纳相关材料的预算内能取回；不是强制接受 |
| 同一更正，角色未获知 | 不进入输入，排序和计数也不泄漏它 |
| 无字面重合，但有可靠实体或引用关联 | 能通过结构依据查找，不依靠固定词表 |
| 无结构关联、只有自然语言矛盾 | 单列为语义检索限制，不靠改测试伪造可计算信息 |
| 旧事实最近才告知某人 | 区分建立版本与获知版本；不删除旧来源 |
| 新消息可信性不足、多人互相否认 | 保留来源与冲突，允许怀疑和拒绝改信 |
| 从更正之前分支 | 不带入未来信息或另一分支的修订 |
| 刻意省略无关旧事 | 不为提高召回把所有材料塞回提示词 |

## 两组独立程序观察

第一组在 `.validation/actor-belief-selection-20261020/` 单次运行：1800B 材料预算足以同时容纳旧信念与已知更正（952–997B），加入 50 条个人日常记录后更正被省略，返回的是旧信念与三条日常记录。未听闻信息和作者摘要没有进入输入。六个子例中三个原预期失败，包括把更正改成人物本人新信念的控制；原日志均保留。

这组更正关联来自作者 `LiteraryMemory.FactIDs`，不是人物已经获得的关系，所以其失败不能当作现有协议违约。既有个人事实与更正同属一个版本时，“最早/最新交替”也不能自动识别语义更正。它证明了材料遗漏风险，尚未证明真实角色因此作错决定。

第二组 `.validation/actor-belief-controls-20261020/` 不修改首组，另行执行五个控制，全部通过。显式要求两条事实、正式实体同时关联两条事实，均在同一预算内取齐；未听闻的实体关联不授予知情；明确请求未授权与不存在事实返回同类错误。三种作者私有索引变化相对于无索引基线，完整材料包和实际 actor 输入字节都相同。

两组均绑定运行前后整个 Go experience 包哈希，零模型、零正式状态修改。第二组表明已有明确选择接口有效，也支持继续保留作者索引与角色认知的隔离；不能为了让第一组变绿而打破这个边界。

表示层另有确定限制：正常 `Candidate → Apply` 能追加新实体、揭示旧实体，不能为旧实体追加 `RelatedIDs`；初始实体也不能预先引用尚不存在的事实。后续新关联仍可由每轮 `trigger.fact_ids` 明确选取，但上游识别哪些证据互相关联依赖语义处理。这是需要后续独立实验的设计范围，不在本轮匆忙扩大共享协议。

当前不调整“全部 statement 优先级”，不删除旧信念，不把私有摘要提供给角色。下一步观察整合版原题的实际取材、角色输出和后续行为，再决定是否需要可追溯且按角色授权的关系索引；召回通过仍不等于理解、采信或文学验收通过。
