# 正式智能交互联调（2026-10-19）

## 来源与边界

最早的智能交互实现在旧 Node/Web Demo 中。旧提交 `a3023dd` 的 README 和模型网关包含 React/TypeScript 工作区及 AI SDK/SSE 链路。随后正式工程接入了作品生成、语义输入分类、版本与状态保存、隔离的 Web/React 渲染，以及 Go 权威执行。`07a4c84` 已将当前仓库主工程整体替换为融合后的 Flutter/Dart、Go、Rust 源码。

这不等于所有 Demo 能力已逐项等价迁移。当前正式作品准备仍等待完整模型结果，再校验、编译和提交；真正的增量节点流式渲染尚未实现。Web 智能交互仍复用 React/JS 沙箱，非 Web 平台使用备用展示。详见 `notes/2026-10-16-generative-ui-architecture.md` 第 7 节。

## 实际运行

通过 `tools/start-local.ps1 -Build` 启动当前仓库的正式工程，入口为 `http://127.0.0.1:18080/`，Go API 为 18081，Rust 运行时为 18083。启动器校验运行二进制、协议及 Web 根目录。Go 健康检查、模型配置检查均通过。

本次仅新增独立的合成验收故事，没有修改已有用户故事。使用本机已授权 Codex 模型实际生成开场，经 Go 提交到 PostgreSQL；随后实际生成含排序控件的 React 比较表，并完成校验、编译、保存。相同准备请求编号回取同一作品修订。原始模型输出、验收故事标识及本机日志仅保留在忽略的 `.validation/`，不加入版本控制。

## 联调发现及修复

浏览器修改排序后，空闲 3 秒内作品状态修订从 264 增至 278。原因是 PostgreSQL JSONB 回传对象键顺序与本地不同，而工作台使用 `jsonEncode` 字符串比较判断是否需要继续保存。同值被误判为变化，导致持续写入及 iframe 反复打开。

`reader_prepared_workbench.dart` 改为递归比较 JSON 值：对象键顺序不影响相等，数组顺序仍影响相等。没有修改服务端权限、协议、故事提交或状态 CAS 规则。

回归测试通过真实 surface 消息、工作台、repository 和 HTTP mock 的调用链模拟每层对象键重排。修复前预期一次保存、实际重复保存；测试主动截断第二次写入以避免挂死。修复后还验证相同状态回传不追加写入，数组顺序改变仍保存。这是状态传输测试，不代表叙事质量验收。
