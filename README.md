# 方糖 · 纯文字互动小说游戏

一个以可参与处境为入口、支持一句话创建、自由行动、假设问答、纠错、润色与分支恢复的本地 Web 原型。没有账号、付费入口或外部图片资源。

## 启动

需要 Node.js 22 或更高版本（开发验证环境：Node 24.20）。没有生产依赖，不需要 `npm install`。

```powershell
git clone https://github.com/TeezyTez/ainovel.git
cd ainovel
npm start
```

打开 **http://127.0.0.1:4173**。停止服务按 Ctrl+C。也可以执行 `node server.mjs`。请固定使用同一地址：`localhost` 与 `127.0.0.1` 的浏览器本地存储彼此独立。

## 试玩

1. 选择「雾港来信」「山门之外」或「星期四书店」，直接开始，或调整角色身份。
2. 演示中点击一条建议，它只会填入输入框；可以审阅后点击「写下行动」，或按 Ctrl / Command + Enter。
3. 每个世界有八轮、两处分歧和延后的关系后果。完整建议文本精确匹配；任意其他输入会保留为草稿，并解释自由生成需要模型。
4. 「人物与见闻」展示公开资料和已确认事实。「故事之外」提供设定查询、叙述调整、改写、重生成、分支和导出。
5. 「保存此刻」创建命名存档。「我的故事」可恢复、重命名、归档、取消归档与确认删除。
6. 历史节点可以新建分支。重生成会回到被替换回合之前建立新分支，不叠加旧后果。

「读下一段」无需编写行动，人物会按自身目标行动，事件继续发展到值得回应的位置；输入框里未发送的草稿保留。写下行动可以介入并改变走向。普通行动之后也会接续事件，不需要逐步下指令；重大立场、承诺和不可逆选择仍由玩家决定。每次点击生成一段，不在离线或后台自动运行。演示的 1.2 秒呈现等待支持取消，不是模型流式生成。

## 重构后的体验

首页优先展示上次经历，再提供具体可参与的处境。新增「真话城的第一壶茶」真实模型开局，旧三个八轮演示保留。详情明确角色前提、可参与方向和自然收束方式。

阅读区可选择实际行动、先问问、帮我措辞，并切换亲自行动、多读一段、有限目标委托或略过已决定的过程。自动意图识别只是保守提示，可显式覆盖。

「故事之外」将三种重来拆开：指出错误→审阅→新修复分支；内容不变换写法→审阅→替换末轮表达并保留修订；另试历史→从旧节点分支。辅助问答和表达草稿不增加回合、不执行事件。

「回到这一刻」展示已发生的公开内容与未发送方向，不以现实离线时长推进故事。「今天先到这里」可暂存或满意归档，仍能恢复与导出。

完整范围和验收见 [重构设计](docs/REFACTOR-DESIGN.md)、[重构验证记录](docs/REFACTOR-VERIFICATION.md)。

## 剧情生成架构（2026-10-10）

真实故事默认先构思、再写作：从当前事实、人物动机和待兑现期待中提出两个短场景，核验依据后选一个，再生成正文与事件。7 张原创创作方法卡覆盖能力兑现、行动后果、人物主动选择、证据重释、关系变化、有限期待与安静余韵。方法近期使用会降权，长时间未兑现的问题优先处理。

每个分支额外保存最多 8 条读者期待、6 条近期剧情变化和 3 条未采用机会。候选构想不是事实，公开事件及期待更新需要正文原句佐证；正文、事件和叙事记录一并提交。旧存档无需迁移，下一轮自动开始记录。完整方案见 [生成架构](docs/NARRATIVE-ARCHITECTURE.md)。

这增加为每轮两次模型调用，共享一次超时与取消。失败不写入，不静默退回旧流程。开发对照可设 `MODEL_NARRATIVE_ENGINE=direct` 并重启；默认 `planned`。`node scripts/verify-narrative.mjs` 只校验评估方案；明确加 `--live` 才会使用已配置模型，连续生成隔离的测试故事并保存完整证据到 `test-results/`。结构和原句校验不等于文学质量或语义一致性的保证。详见[实测记录与耗时](docs/NARRATIVE-VERIFICATION.md)和[完整正文样本](docs/NARRATIVE-SAMPLES.md)。

## 自建世界与版本

「创建世界」支持由一句自然语言设想，通过真实模型生成世界、人物、身份前提和当前可玩的开场。先展示草案，采用后可逐项编辑，再保存并进入；生成不会自动覆盖原草稿。无模型时仍可手动填写。支持草稿自动保存、开场预览、私有保存和复制。

人物公开介绍与幕后秘密分开。新版本不改变旧存档；已有故事应用新版本时建立分支，并保留历史开场。若新版删去历史中已有的人物，会阻止直接应用并建议保留人物或从新版独立开局。

自建或编辑后的世界可阅读自己的开场；后续生成需要真实模型。修改了规则的世界不会继续套用原来的预设脚本。

## 真实模型配置

支持直接复用本机 Codex 的 ChatGPT 登录，无需 API Key。先复制 `.env.example` 为 `.env`，按自己的设备填写 CLI 路径、授权目录及可用模型；需要代理时再填写代理地址。仓库不包含本机授权、`.env`、玩家存档或测试输出。启动服务后，新故事默认选择真实模型。旧演示存档仍保留演示模式。

本机 Codex 配置示例（不含任何登录令牌）：

```dotenv
MODEL_PROVIDER=codex
CODEX_CLI_PATH=Codex CLI 可执行文件的绝对路径
CODEX_AUTH_HOME=本机已登录的 .codex 目录
CODEX_PROXY=http://127.0.0.1:10808
MODEL_NAME=gpt-6-astra
MODEL_TIMEOUT_MS=180000
```

使用 `codex login status` 检查登录。授权过期时通过官方 Codex 重新登录；程序不读取、复制或返回授权令牌。代理仅传给 CLI 子进程，不改变系统代理。模型使用现有账号额度；本机网络不需要代理时可留空 `CODEX_PROXY`。CLI 升级后如路径变化，更新 `CODEX_CLI_PATH`。

每次生成使用临时独立目录、只读沙箱、结构化输出和关闭的 Shell / 浏览器 / 插件工具；通过标准输入传递小说资料。CLI 不加载用户配置或宿主技能，避免把小说当作代码任务。配置接口对 Codex 检查真实登录状态，登录检查不等于网络或额度始终可用。

官方依据：[Codex 非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)支持复用 CLI 登录和 JSON Schema 输出。显式运行 `node scripts/verify-codex.mjs` 可进行消耗模型额度的连接实测。

如果改用兼容 API，复制 `.env.example` 为 `.env`，仅在本机服务端填写：

```dotenv
MODEL_API_KEY=在这里填写你的供应商密钥
MODEL_BASE_URL=https://你的兼容接口地址/v1
MODEL_NAME=供应商提供的模型标识
MODEL_PROVIDER=OpenAI-compatible
MODEL_CONTEXT_BUDGET=24000
MODEL_OUTPUT_BUDGET=2400
MODEL_TIMEOUT_MS=60000
PORT=4173
```

重新启动服务，设置页点击「重新检查连接配置」，再从世界详情新建一个「真实模型」故事。配置指示只表示服务端字段完整，不代表供应商连接或模型语义已验证。需要支持 Chat Completions 和 JSON object 输出格式的兼容接口；不保证任意供应商兼容。

- 浏览器不接收、不存储 API 密钥。`.env` 被 Git 忽略且不能通过静态服务下载。
- `MODEL_CONTEXT_BUDGET` 是保守的**字符预算**，不是精确 token 计数；`MODEL_OUTPUT_BUDGET` 传给供应商作为输出 token 上限。
- 请求区分系统叙事规则、固定世界、当前状态、玩家、偏好、带来源记忆、近期原文与当前行动。预算不足时先丢弃旧原文和旧记忆，不截断权威状态和本轮输入；仍超出则拒绝。
- 当前采用完整 JSON 回应，**不支持流式输出**。UI 会诚实等待；超时、取消、配置缺失、无效生成都有独立反馈。
- 取消后结果不能提交；重复请求有有限缓存去重；切换分支或离开页面会取消请求。失败不会静默切换演示。
- 模型没有工具调用能力。世界文本不能更换服务端地址、密钥或执行外部动作。

## 存储与导出

技术栈为原生 JavaScript ES modules、CSS、Node HTTP 服务。空仓库没有 Telos 代码，因此这不是 Flutter / Go / Rust / PostgreSQL 的正式技术栈实现。

权威原型状态在浏览器内，以 `localStorage` 键 `cijian:archive:v1` 单次原子写入。**没有服务端存档、云同步或账号恢复**。世界、故事、分支、草稿、阅读设置、最多500条匿名交互事件都仅在当前浏览器。清理浏览器数据会丢失资料；建议定期导出 JSON。

数据结构分离世界版本、游玩会话、分支、已完成回合、状态快照、带来源事件、分支记忆和命名存档。只有完整且通过校验的回应才能同时提交正文和状态；保存失败显示失败且保留页面中的内容。

- **Markdown**：仅当前分支的开场、行动、正文，不含旁支、隐藏事实与人物秘密。
- **JSON**：有 `schemaVersion: 1`，包括幕后资料。导入前校验结构、版本、日期、标识、世界引用、回合链、事件来源以及重放状态一致性。导入新建独立故事，不覆盖已有故事；完整备份内的阅读偏好和草稿一并恢复。
- 导出弹窗提供「下载文件」和完整内容复制。开发时 Codex 内置浏览器的下载完成事件未返回，因此额外验证了导出内容与文件选择导入的闭环；若内置浏览器不处理下载，可复制内容保存为显示的 `.json` / `.md` 文件，或使用普通浏览器。
- 两份存档中同 ID 同版本的世界定义不同，会解释性拒绝导入，不猜测哪份正确。

## 能力边界

- 已实现确定性的结构、状态版本、实体引用、事件类型、可见性、分支来源、JSON 防注入及回放一致性校验。
- 演示人物边界与延迟后果由预写情境保证。真实模型的动机、知识边界与硬设定遵守依赖提示规则和模型判断；没有独立语义判定器或自动修复链。
- 记忆从本分支回合重建，保留最近6轮原文，并按词语相关性选择最多6条较早记录，加上近期记录组成最多12条记忆。文本仍为短摘录，重要事件单独携带；不是无限上下文或长期一致性的证明。
- 原型面向本机单人、单个活动标签页。没有跨标签页并发写入协调、生产级数据库、加密存档或用户隔离系统。
- 三档浏览器宽度已实测；实体手机软键盘、系统中文输入法和屏幕阅读器未进行设备级测试。组合输入不发送的键盘规则有单元测试。
- 已实际验证本机 Codex 授权、真实剧情结构化生成和浏览器提交存档。长期叙事一致性仍需持续游玩评估，不能由短程测试保证。
