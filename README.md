# 人生复本 · 智能互动小说游戏

一个以可参与处境为入口、支持一句话创建、自由行动、假设问答、纠错、润色与分支恢复的本地 Web 原型。没有账号、付费入口或外部图片资源。

## 启动

需要 Node.js 22 或更高版本（开发验证环境：Node 24.20）。首页动态虫洞使用固定版本 Three.js，首次运行先安装依赖。

```powershell
git clone https://github.com/TeezyTez/ainovel.git
cd ainovel
npm ci
npm start
```

打开 **http://127.0.0.1:4173**。`npm start` 会先构建交互工作区。停止服务按 Ctrl+C。直接执行 `node server.mjs` 前须先运行一次 `npm run build`。请固定使用同一地址：`localhost` 与 `127.0.0.1` 的浏览器本地存储彼此独立。

## 生成式交互工作区（2026-10-15）

新工作区由 `.env` 中的 `GENERATIVE_UI_ENABLED=true` 启用，修改后重启服务。仓库示例默认关闭，保留原路径供回退；本次已在当前本机配置开启试用。完整产品对比门槛尚未完成，不把这次工程验收当作面向所有环境的默认发布。

智能交互已接入 React / TypeScript / Vite 工作区、Zod 协议、版本存储和模型网关。既有结构化视图继续可用，复杂工具可使用受控 TSX；只允许本地 React 与 `@story/ui`，编译后在隔离 iframe 运行。候选可运行界面在独立浏览器进程完成运行和窄屏检查后才替换旧版本；标准表格、卡片等无需启动浏览器。运行验证自动发现本机 Edge/Chrome，其他环境需安装 Playwright Chromium（`npx playwright install chromium`）。

自然输入先结合公开场景与当前作品判断“生成/修改界面”或“故事行动”；模型在同一次调用内给出界面意图和候选。修改支持精确版本/内容哈希的局部补丁，已保存参数优先于初始默认值。任务进度通过 SSE 实时发送，可重连重放；Codex 只报告真实阶段，兼容 API 经 AI SDK 消费实际内容流，界面不会伪造模型逐字输出。自由故事输入的语义判别会增加一次模型调用，等待时间仍受所连接模型影响。

## 试玩

1. 选择「雾港来信」「山门之外」或「星期四书店」，直接开始，或调整角色身份。
2. 演示中点击一条建议，它只会填入输入框；可以审阅后点击「写下行动」，或按 Ctrl / Command + Enter。
3. 每个世界有八轮、两处分歧和延后的关系后果。完整建议文本精确匹配；任意其他输入会保留为草稿，并解释自由生成需要模型。
4. 「人物与见闻」展示公开资料和已确认事实。「故事之外」提供设定查询、叙述调整、改写、重生成、分支和导出。
5. 「保存此刻」创建命名存档。「我的故事」可恢复、重命名、归档、取消归档与确认删除。
6. 历史节点可以新建分支。重生成会回到被替换回合之前建立新分支，不叠加旧后果。

「读下一段」无需编写行动，人物会按自身目标行动，事件继续发展到值得回应的位置；输入框里未发送的草稿保留。写下行动可以介入并改变走向。普通行动之后也会接续事件，不需要逐步下指令；重大立场、承诺和不可逆选择仍由玩家决定。每次点击生成一段，不在离线或后台自动运行。演示的 1.2 秒呈现等待支持取消，不是模型流式生成。

## 重构后的体验

阅读页以正文和输入框为中心，辅助功能统一收在输入框旁的「+」。周围、物品、人物、时间与手记等资料按需展开；也可以直接输入「我在哪」「身上有什么」「现在几点了」。查询不会推进故事，从菜单查看资料或继续阅读会保留未发送的草稿。地图保留路线查看与出发操作，存档、导出、阅读设置和更多故事选项位于「+」菜单的「存档与设置」中。

首页优先展示上次经历，再提供具体可参与的处境。新增「真话城的第一壶茶」真实模型开局，旧三个八轮演示保留。详情明确角色前提、可参与方向和自然收束方式。

阅读区可选择实际行动、先问问、帮我措辞，并切换亲自行动、多读一段、有限目标委托或略过已决定的过程。自动意图识别只是保守提示，可显式覆盖。

「故事之外」将三种重来拆开：指出错误→审阅→新修复分支；内容不变换写法→审阅→替换末轮表达并保留修订；另试历史→从旧节点分支。辅助问答和表达草稿不增加回合、不执行事件。

「回到这一刻」展示已发生的公开内容与未发送方向，不以现实离线时长推进故事。「今天先到这里」可暂存或满意归档，仍能恢复与导出。

完整范围和验收见 [重构设计](docs/REFACTOR-DESIGN.md)、[重构验证记录](docs/REFACTOR-VERIFICATION.md)。

## 对话中的智能交互（2026-10-13）

真实模型故事会在进入当前场景和每轮剧情更新后，根据已发送的对话与公开剧情判断是否需要辅助呈现。需要时自行选择比较表、SVG 关系／流程图、数值图、卡片、时间线或 SVG 概念插画，也可与已有的多选、条件输入、计算预览和多步骤准备组合。普通阅读保持纯文字，不固定展示面板。

无需开启功能或选择展示形式：表格和图示会在有助于理解或行动时随内容自动出现。没有手动唤出菜单和格式切换器。出现后的表格支持筛选和排序；图卡上的「写入草稿」追加到原有文字，修改后再发送。角色的实际行动仍由玩家决定。

整理、筛选和生成图示不推进故事，也不花费角色资源。只读展示与尝试草稿不再串行调用另一个模型审核内容；可运行界面增加上述编译和浏览器检查。生成只接收公开上下文；图中的文字和计算质量仍需模型及实际任务验收。概念插画使用受控 SVG 图元，可运行交互图使用隔离沙箱，不能直接执行剧情动作。取消保留草稿，生成失败时保留仍然有效的旧界面。模型连接与现有登录保持一致；流式能力见上面的工作区说明。

运行 `node scripts/verify-rich-interactions.mjs --live` 可在隔离账本验证真实生成；运行 `node scripts/preview-rich-interactions.mjs` 可打开独立端口的固定数据浏览器验收场景。验收证据与边界见 [智能交互验证记录](docs/GENERATIVE-INTERACTION-VERIFICATION.md)。

## 动态交互（2026-10-12）

2026-10-15 补充：有当前界面时支持筛选、排序、字号和列说明等自然追问；交互图修改可显式恢复局部参数，填写无关字段不再重载正在使用的图。优化范围、真实模型等待时间、浏览器验证和前沿产品对比见 [智能交互优化与差距评估](docs/AI-INTERACTION-GAP-2026-10-15.md)。

同日提速调整：界面生成不再强制使用 medium 推理，缺省使用 low 并保留显式配置。只有新的正式 `rule` 契约需要模型检查成本、公式与授权；同场景、事实依据未变且输入字段、步骤和正式规则完全相同的界面改版复用已有验证。已结算行动的后续描写只生成一次，不再追加正文审查。数值结算、版本冲突、证据引用、脚本编译与沙箱限制继续由本地代码执行。

真实故事会按当前公开事实与玩家意图生成可执行交互。输入、条件、多步准备、比较与效果使用受限的 JSON 规则组合；没有商店、战斗等场景分派。辅助界面按需要自动出现。选择、预览和准备步骤只改草稿；提交后的正式回执先保存，后续正文单独生成和重试。自由输入可执行已审核规则、申请新契约，或进入人物判断与叙事流程。

协议、验收证据和边界见 [动态交互交付记录](docs/DYNAMIC-INTERACTION-DELIVERY.md)。模型输出可能被拒绝；失败会保留原状态与输入。无效结构不是有效的“无需界面”决策，验证记录区分两者。

```powershell
node scripts/verify-dynamic-interactions.mjs
node scripts/verify-dynamic-interactions.mjs --live
```

第一条只检查测试方案；第二条使用已配置真实模型执行商人、10个其他情境及3个无需界面的情境，写入隔离临时账本与 test-results，不使用演示替代模型。

## 剧情生成架构（2026-10-12）

真实故事默认先写正文，再由独立记录调用提取状态。叙述模型负责故事连续性、人物行动和玩家意图的理解，不接收方法卡、候选评分或状态登记 schema；读者已经经历的内容与幕后参考分开传入。2026-10-15 起，记录阶段只返回包含非空记录对象的 `{record}`，不再判断正文是否“相容”，也不通过 `compatible` 或 `reason` 拒绝正文。记录器不能改写正文；本地结构、原句证据和状态校验通过后，正文与事件一起提交。底层提示、实现与历史实测见 [正文优先重构](docs/STORY-FIRST-REFACTOR.md)。

每个分支额外保存最多 8 条读者期待、6 条近期剧情变化和 3 条未采用机会。候选构想不是事实，公开事件及期待更新需要正文原句佐证；正文、事件和叙事记录一并提交。旧存档无需迁移，下一轮自动开始记录。完整方案见 [生成架构](docs/NARRATIVE-ARCHITECTURE.md)。

通常每轮两次模型调用，共享一次超时与取消；记录格式、证据或状态校验失败时，最多修复一次记录，仍不改写正文。技术失败不写入，不静默退回旧流程。默认 `MODEL_NARRATIVE_ENGINE=story`；`planned` 和 `direct` 仅作显式开发对照。`node scripts/verify-story-first.mjs --live` 使用已配置模型验证独立虚构故事，证据保存到 `test-results/`。结构与原句校验不等于文学质量或全部语义一致性的保证。

## 自建世界与版本

「创建世界」支持由一句自然语言设想，通过真实模型生成世界、人物、身份前提和当前可玩的开场。先展示草案，采用后可逐项编辑，再保存并进入；生成不会自动覆盖原草稿。无模型时仍可手动填写。支持草稿自动保存、开场预览、私有保存和复制。

人物公开介绍与幕后秘密分开。新版本不改变旧存档；已有故事应用新版本时建立分支，并保留历史开场。若新版删去历史中已有的人物，会阻止直接应用并建议保留人物或从新版独立开局。

自建或编辑后的世界可阅读自己的开场；后续生成需要真实模型。修改了规则的世界不会继续套用原来的预设脚本。

## 真实模型配置

支持直接复用本机 Codex 的 ChatGPT 登录，无需 API Key。先复制 `.env.example` 为 `.env`，按自己的设备填写 CLI 路径、授权目录及可用模型；需要代理时再填写代理地址。仓库不包含本机授权、`.env`、玩家存档或测试输出。启动服务后，新故事默认选择真实模型。旧演示存档仍保留演示模式。

本机 Codex 配置示例（不含任何登录令牌）：

```dotenv
MODEL_PROVIDER=codex
CODEX_CLI_PATH=Codex CLI 可执行文件的绝对路径
CODEX_AUTH_HOME=本机已登录的 .codex 目录
CODEX_PROXY=http://127.0.0.1:10808
MODEL_NAME=gpt-6-astra
MODEL_TIMEOUT_MS=180000
```

使用 `codex login status` 检查登录。授权过期时通过官方 Codex 重新登录；程序不读取、复制或返回授权令牌。代理仅传给 CLI 子进程，不改变系统代理。模型使用现有账号额度；本机网络不需要代理时可留空 `CODEX_PROXY`。CLI 升级后如路径变化，更新 `CODEX_CLI_PATH`。

服务应从已登录 Codex 的正常用户终端运行 `npm start`。不要让网页服务长期运行在 `CodexSandboxOffline` 等受限工具账号下：登录检查可能成功，但实际生成仍会因运行目录权限不足而立即失败。出现 `CODEX_PERMISSION_DENIED` 时，在正常用户环境重启服务即可；无需复制授权文件或修改存档。`CODEX_UNAVAILABLE` 表示 CLI 路径失效，`CODEX_EXECUTION_FAILED` 表示进程执行失败，与模型输出校验错误分开反馈。

可在正常用户终端执行 `node scripts/verify-dialogue-live.mjs --live`，用独立临时账本验证真实对话、提交、收据恢复和重复请求不重复执行；加 `--browser` 可打开独立测试故事进行页面验收。这会使用模型额度。前端核对进度最多等待 15 秒，支持停止与切换故事；过期请求保留原输入并允许按新进度重新发送。

每次生成使用临时独立目录、只读沙箱、结构化输出和关闭的 Shell / 浏览器 / 插件工具；通过标准输入传递小说资料。CLI 不加载用户配置或宿主技能，避免把小说当作代码任务。配置接口对 Codex 检查真实登录状态，登录检查不等于网络或额度始终可用。

官方依据：[Codex 非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)支持复用 CLI 登录和 JSON Schema 输出。显式运行 `node scripts/verify-codex.mjs` 可进行消耗模型额度的连接实测。

如果改用兼容 API，复制 `.env.example` 为 `.env`，仅在本机服务端填写：

```dotenv
MODEL_API_KEY=在这里填写你的供应商密钥
MODEL_BASE_URL=https://你的兼容接口地址/v1
MODEL_NAME=供应商提供的模型标识
MODEL_PROVIDER=OpenAI-compatible
MODEL_CONTEXT_BUDGET=24000
MODEL_OUTPUT_BUDGET=2400
MODEL_TIMEOUT_MS=60000
PORT=4173
```

重新启动服务，设置页点击「重新检查连接配置」，再从世界详情新建一个「真实模型」故事。配置指示只表示服务端字段完整，不代表供应商连接或模型语义已验证。需要支持 Chat Completions 和 JSON object 输出格式的兼容接口；不保证任意供应商兼容。

- 浏览器不接收、不存储 API 密钥。`.env` 被 Git 忽略且不能通过静态服务下载。
- `MODEL_CONTEXT_BUDGET` 是保守的**字符预算**，不是精确 token 计数；`MODEL_OUTPUT_BUDGET` 传给供应商作为输出 token 上限。
- 请求区分系统叙事规则、固定世界、当前状态、玩家、偏好、带来源记忆、近期原文与当前行动。预算不足时先丢弃旧原文和旧记忆，不截断权威状态和本轮输入；仍超出则拒绝。
- 剧情接口仍采用完整 JSON 回应。智能交互通过 SSE 提供真实阶段进度；API 适配器消费供应商实际文本流，Codex CLI 仅上报已发生的阶段。完整候选验证后才激活，未完成的 JSON 不执行。超时、取消、配置缺失、无效生成都有独立反馈。
- 取消后结果不能提交；重复请求有有限缓存去重；切换分支或离开页面会取消请求。失败不会静默切换演示。
- 模型没有工具调用能力。世界文本不能更换服务端地址、密钥或执行外部动作。

## 存储与导出

阅读器与小说账本沿用 JavaScript ES modules、CSS 和 Node HTTP；智能交互工作区采用 React、TypeScript、Vite，服务端以 Zod 校验协议、esbuild 编译受控 TSX、Playwright 独立进程验证候选。作品版本与参数保存到服务端独立的原子文件清单。

真实故事使用本机服务端 `.data/branches` 账本作为已提交进展的权威来源，浏览器以 `localStorage` 键 `cijian:archive:v1` 保存阅读副本、草稿和设置。演示故事仍只在浏览器中。服务端通过浏览器持久随机所有者标识隔离账本；这不是云账号。请同时备份浏览器资料与服务端账本，受保护故事的公开 JSON 不包含幕后事实，不能单独替代完整账本。

数据结构分离世界版本、游玩会话、分支、已完成回合、状态快照、带来源事件、分支记忆和命名存档。普通叙事先生成正文，再提取结构化记忆和状态；第二次调用承担记录工作。动态确定规则先原子提交行动、状态与回执，再附上一次生成的正文，不追加模型审查。正文失败不回滚或重做行动，恢复后可单独续写。

- **Markdown**：仅当前分支的开场、行动、正文，不含旁支、隐藏事实与人物秘密。
- **JSON**：有 `schemaVersion: 1`，旧作者档案可包括幕后资料，受保护故事只导出公开投影。新动态交互以可选的分支契约、操作回执和叙事状态扩展现有格式，保留旧档与历史ID。导入前校验结构、版本、日期、标识、世界引用、回合链、事件来源以及重放状态一致性。导入新建独立故事，不覆盖已有故事；完整备份内的阅读偏好和草稿一并恢复。
- 导出弹窗提供「下载文件」和完整内容复制。开发时 Codex 内置浏览器的下载完成事件未返回，因此额外验证了导出内容与文件选择导入的闭环；若内置浏览器不处理下载，可复制内容保存为显示的 `.json` / `.md` 文件，或使用普通浏览器。
- 两份存档中同 ID 同版本的世界定义不同，会解释性拒绝导入，不猜测哪份正确。

## 能力边界

- 已实现确定性的结构、状态版本、实体引用、事件类型、可见性、分支来源、JSON 防注入及回放一致性校验。
- 演示人物边界与延迟后果由预写情境保证。真实故事的动机、知识边界、硬设定和玩家意图由叙述模型理解；正文没有独立语义审核或自动重写。记录提取仍有本地结构、证据与状态校验，以及最多一次记录修复。
- 记忆从本分支回合重建，保留最近6轮原文，并按词语相关性选择最多6条较早记录，加上近期记录组成最多12条记忆。文本仍为短摘录，重要事件单独携带；不是无限上下文或长期一致性的证明。
- 原型面向本机单人、单服务进程。真实行动支持同一账本的多页面版本检查与请求幂等，浏览器草稿冲突仍需保留副本后合并。不支持多个服务进程同时写同一所有者账本，也没有生产数据库、云同步或加密存档。
- 三档浏览器宽度已实测；实体手机软键盘、系统中文输入法和屏幕阅读器未进行设备级测试。组合输入不发送的键盘规则有单元测试。
- 已实际验证本机 Codex 授权、真实剧情结构化生成和浏览器提交存档。长期叙事一致性仍需持续游玩评估，不能由短程测试保证。
